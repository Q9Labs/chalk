Option 2 is not the automatic next step after an embedded failure. It is the next step only after Chalk accepts a new format.

D1 · Device thresholds

Premise: “Feels native” cannot decide a release.

A · Absolute + native reference: one clear support bar; may exclude older devices.

B · Premium + floor: broader support; two experience and evidence levels.

C · Relative only: adapts per device; may permit poor absolute behavior.

Recommend/default: A, frozen after Phase 0 variance is known.

D2 · Native pen capture

Premise: pen can fail while the rest of the editor passes.

A · Allow one neutral-stroke overlay proof: better pen ceiling; adds camera and preview handoff tests.

B · Pure embedded only: simpler architecture; any pen miss fails the whole option.

Recommend/default: A. Excalidraw still creates the canonical element.

D5 · First release consumers

Premise: Chalk has a React Native package, not standalone SwiftPM, CocoaPods, or Maven whiteboard products.

A · React Native

First-party app plus public React Native component. Native hosts stay internal. Lowest release and support cost.

B · Thin native SDK hosts

Add public embedded views, native sample apps, ABI policy, install proof, and independent releases.

C · Pure-native editors: makes Option 3 or a lower-level Option 2 core part of launch.

Recommend/default: A. Reopen standalone native distribution later.

D3 · Format policy

Premise: full Excalidraw behavior turns a focused engine into a port.

A · Dual format: chalk/1 for new work; permanent legacy policy.

B · Full compatibility: one format; highest engine scope.

Recommend/default: A. If B stays mandatory, skip Option 2.

D6 · Existing mobile boards

Premise: the new engine cannot edit the Excalidraw board that triggered it.

A · Read-only + Chalk copy: best mobile continuity; keeps a legacy viewer.

B · Web-only: simplest; mobile users cannot open old boards.

C · Full native edit: activates Option 3 as well.

Recommend/default: A, with honest web-only fallback.

D4 · Option 2 shared core

Premise: the fallback must remove the measured cause of failure.

A · TypeScript

Web Canvas plus React Native Skia fits current apps and ships faster. Reject it after a JavaScript scheduling or React Native contention failure.

B · Rust or C++

Wider native reach and different runtime behavior. Adds bindings, memory ownership, build, debugging, and release cost.

Recommend/default: A only after a WebView, Excalidraw, or browser-UI failure. Otherwise the failure report chooses B or stops the branch.

 The browser whiteboard-v1 end-to-end gate is required before mobile integration can pass. Local bundle and native-host feasibility may run beside it. Only one Phase 2 branch may activate. A failed branch returns to product scope; it does not silently start the other editor.
