## Effect Schema → Go contract generation (spike, 2026-05-13)

Explored whether TypeScript Effect Schema definitions can be the source of truth
for Go websocket/API contract types. Built a throwaway prototype that walked the
Effect Schema AST and rendered Go payload previews, then deleted it.

**Decision: viable, but only as a narrow policy-driven Chalk contract generator —
not a generic TypeScript-to-Go converter.**

Maps cleanly: `Schema.Struct` → Go struct, primitives, literal unions → enum-like
types, arrays, records, optional/nullable fields.

Cannot be inferred and needs explicit overrides or annotations:

- Casing per contract group (Go websocket payloads are mostly snake_case; some
  outbound TS payloads are intentionally camelCase).
- `uuid.UUID`, `time.Time`, `int64`, `json.RawMessage`.
- Opaque `Schema.declare(...)` shapes — override or fall back to `json.RawMessage`.
- Discriminated unions — either generated variant structs plus custom unmarshal,
  or a deliberate `json.RawMessage` fallback.

Any real implementation must emit to a temp package and run `gofmt` + targeted Go
tests as a compile gate, backed by golden fixtures. Unsupported constructs should
surface as warnings rather than silent fallbacks.
