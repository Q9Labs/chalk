# 2026-W33 (2026-08-10 – 2026-08-16)

Condensed from 16 session logs. Originals removed on
`chore/docs-scratch-cleanup`; full text remains in git history.

Post-rename reality check: the dashboard and diagnostics were **shipped but not
usable end to end**, and each fix exposed the next contract mismatch. Alongside
that, CI/CD Phase 1 went live and a production database cutover took six document
revisions to land.

## The dashboard was disconnected from the product

A read-only investigation named the gap plainly: Dashboard Space rows exposed
Edit/Archive but **no Open or Join**, Episode rows exposed details/End but no
Join, Home Space cards routed generically to `/spaces`, and `/new` rendered no
product UI. The standalone `/space` flow was backed by an
**infrastructure-configured Space, not the selected Dashboard Space** — and
because the Dashboard contained duplicate Space names with distinct slugs while
Episode rows showed only the shared name, a person could not reliably match
history to the Space they had used.

Two root causes, both structural:

1. **The deployed `/space` parent rendered the generic public `SpacePage` without
   a router `Outlet`.** Because `/space/$slug` is its child, the named Dashboard
   route never mounted — and the **service worker returned the cached app shell
   for the route's 404**, hiding the mismatch and making the generic entrance
   look usable. Fixed by turning `/space` into a layout route with an `Outlet`
   and moving the public Space to the `/space/` index.
2. **The server SDK discarded the optional diagnostics credential** while
   rebuilding an `AccessGrant`, so browser diagnostics never started.

Media access then failed with `media.unavailable` before any provider request:
the affected Tenant had no media-plane provider configuration, and **the
Dashboard had created the Space on RealtimeKit even though the web Space client
consumes Cloudflare SFU grants**. Production was repaired by enabling
Chalk-managed media without pinning the Tenant to one provider and switching only
the affected Space; Dashboard Space creation now has one SFU default in the API
client.

## The diagnostics contract chain

Five successive strict-contract failures, each found only by a signed-in
production browser test and each fixed at its real boundary:

1. **The generated TypeScript schema rejected a backend-valid PostgreSQL UUID
   shape** before any Episode request was sent. Fixed in the Effect schema
   generator with a runtime contract regression across all generated UUID-backed
   IDs.
2. The Pages account gateway still returned 404 because **its shared path
   validator kept the older RFC-only UUID rule** — aligned with the API parser.
3. Episode decoding failed because **two migrated rows expose an empty
   `started_at`**, outside the public ISO timestamp contract. An API
   response-boundary fallback exposes the persisted `created_at` only when legacy
   `started_at` is blank.
4. The gateway returned 200 with a valid raw `DiagnosticSnapshot/v1` while **the
   web client incorrectly required a resolver envelope**.
5. **The API snapshot encoded ten required empty arrays as `null`** and omitted
   the empty Flame projection version.

Later, the API emitted **Participant values outside the public diagnostics
contract**; it now maps stable anonymous labels and allowlisted identity, state,
and visibility values, with snapshot validation covering Participant projections
**so future server drift fails before a bad response ships**.

Cloudflare Pages deep links returned the SPA shell with HTTP 404 because the
build emitted a top-level `404.html`; the build now relies on Pages' automatic
SPA fallback, and deployment verification probes a dynamic Episode Diagnostics
URL for HTML with 200.

Diagnostics discoverability was also closed: an account-scoped `chalk.episode`
alternate reference, a direct Episode detail launch link, a Developer launcher,
and a **bounded idempotent reconciler backfill** so diagnostics created before the
safe reference become openable without an operator database update. Review caught
two P2s — a selected Episode could briefly expose a debugger link before its
reference existed, and **the completed reference backfill would still scan once
per second**.

## Browser Sync recovery loop

A production failure reproduced from a recording: **the Sync WebSocket completed
its handshake and recovery, then the client closed the healthy socket and
retried.** Traced to stale queued Sync snapshots in the Connection lifecycle;
fixed with recovery coalescing.

Two layout problems surfaced alongside it — the production Space route disabled
the Entrance and **gave `<Chalk />` no definite viewport-height parent**. A live
retest then exposed an older synthetic Episode left active when its creator page
unloaded, so **unload-safe, back-forward-cache-aware creator cleanup** was added
so leaving the page cannot strand an Episode. A wide-screen screenshot exposed
remaining SDK caps and a single-Participant aspect constraint; the SDK Space
chrome and stage now use the full host viewport.

## The missing Episode

Reported symptom: a joined Space had no Episode in the Dashboard. The code-path
diagnosis found a chain of quiet failures:

- Dashboard auto-start leaves `episodes.started_at` **null**.
- That path **bypasses the Episode commit observer**, and the periodic
  diagnostics backfill **filters out null `started_at` rows** — so no diagnostics
  root is created.
- If an enabled `episode.started` webhook target exists, **webhook encoding
  rejects the null start time and rolls back the whole join transaction**.

Production correlation then found the actual user-visible cause: browser history
showed the affected named route carried a **broker invite capability**, and the
production database showed a two-Participant Episode in the broker's fixed Space
one second later while the named Dashboard Space had no lifecycle rows. **The UI
had silently joined a different Space.**

The repair removes broker invite capabilities from marked Dashboard links before
entry (public invite links still work), defaults Episode starts to the database
transaction time, observes Dashboard-created Episodes after commit, and backfills
both authoritative and diagnostic start timestamps.

Recorded honestly as an observability gap: **production diagnostics cannot
discover an Episode by Space and time** — it needs an Episode, journey, request,
command, or trace identifier first. Root creation, reconcile health, queue drops,
projector lag, and dead letters lack durable health signals, which makes exactly
this class of failure quiet.

## API CI/CD Phase 1

CI now builds, signs, and publishes the arm64 API and Sync images plus the release
manifest on every green master push; deploys stay manual. First fully CI-published
release: `managed-episode-20260814T100054Z-e984122b-40e5ec42`, with managed
signing independently verified `COMPLETE` for both images.

Three defects found on the way:

1. OSV flagged Go 1.25.12 stdlib (GO-2026-6090/6091/6218) → bumped to 1.25.13
   across Dockerfiles, `go.mod`, `db-migrate.sh`, README.
2. Images pushed but signing failed with `ACCESS_DENIED` — **ECR managed signing
   executes as the pushing principal**, and the CI role lacked
   `signer:SignPayload`.
3. A rerun reported failure despite signing actually completing: the poll used
   `--query status` while the response shape is `signingStatuses[0].status`, so it
   **always read `None`** — it could never see COMPLETE or FAILED, and it had also
   masked the earlier `ACCESS_DENIED`.

## The a4d1227a production cutover

Six document revisions (v21–v26) plus a fenced recovery, each fail-closed with
zero database harm.

**The real root cause was the credential layer, not the tooling.** After v21
failed at `goose up-to` with a generic error, the diagnosis stopped iterating in
production and audited the migration helper: **its cleanup trap deleted
`helper_error`, destroying goose's stderr on failure** — which is why every
attempt reported only "Goose up-to migration failed." A complete local rehearsal
with the exact helper image and all 35 migrations passed, proving the tooling
correct. A read-only privilege query then found it: `participants` is owned by one
PlanetScale role while the sync and api environments connect as two different
roles with `pg_has_role` = false. **Reads work; `ALTER TABLE` cannot — every
cutover attempt was doomed regardless of tooling.**

Fix: an owner-role migrator credential staged as an SSM SecureString
(`sslmode=verify-full`), verified on-host to yield `current_user=owner`,
`is_member=t`.

The remaining five failures were each a distinct, instructive mechanism:

| Doc | Failure                                                                                                                                                                                                                                                                                                |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| v22 | The bundle tarball carried **macOS xattr headers** (`com.apple.provenance`); host extraction rejected it                                                                                                                                                                                               |
| v23 | The preserved migration-stage root still held the **old helper** while the document pinned the new sha; prepare died on a silent bare-`[[` assert (rc=1, no output)                                                                                                                                    |
| v24 | Stage-refresh implemented as `if verify_stage_root` — **bash suppresses `set -e` inside functions called in condition contexts**, so the failed assert didn't abort and refresh never fired                                                                                                            |
| v25 | Ownership query returned `true` but the gate accepted only `t` — fixed with a SQL-side `::int` cast                                                                                                                                                                                                    |
| v26 | Gates green, migration **applied and head advanced** — then the helper's post-migration check **grepped goose status from stdout while goose prints to stderr**, aborted before writing evidence, and the controller correctly refused to start. The fence held: no old restart on a migrated database |

Landed live at 14:33:40Z after out-of-band completion of the aborted
verification. Outage ~33 minutes, fenced throughout, database migrated once, zero
data harm.

**Pipeline lessons recorded:** never destroy failure stderr; all goose output
parsing must use combined streams; prove DDL capability pre-stop; the migrator
credential is a stable per-environment SSM parameter structurally separate from
runtime roles; no verification functions in bash condition contexts; rehearse the
migration chain in CI against scratch Postgres.

## Deployment fast-path

The API performance harness was measured at 177.62 s cold / 57.46 s warm and
**reported throughput without enforcing any performance contract** — so the
unfinished harness was removed rather than left standing as a release gate.

Replaced with: one deterministic local API gate with isolated migrated Postgres
(PostgreSQL preparation moved to a background lane so static checks start at
once), component-aware API/Sync build and restart planning so unchanged images
can be carried from the stable release, and a local-first exact-SHA web release
with staging default and explicit emergency bypass. Real Postgres was
**deliberately kept** for migration, constraint, transaction, and lifecycle
coverage — warm startup costs ~4 s plus ~2 s of migrations, so a mock would save
little while removing the checks most likely to catch database release failures.

The canonical gate also exposed an existing **Bash 3 runtime failure** in OSV
lockfile discovery, replaced with a line-delimited tracked-lockfile scan that runs
under both system and Homebrew bash.

## Web release runner, exercised for real

Preflight caught that the local repository was not shippable: local `master` was
ahead 9 and **behind 1**, and the missing commit was a live diagnostics fix — so
deploying local HEAD would have **regressed production**.

The first CI run failed in 13 seconds with `Command "wrangler" not found`.
`runWebRelease` called `checkPinnedTools` **before** the workspace install, and
Wrangler is a workspace dependency — a warm local checkout has `node_modules`
already, so the preflight passed locally and failed on **every fresh CI
checkout**. The dry run couldn't catch it either, since it returns before the
preflight. Fixed by splitting the preflight, with a regression test that records
call order and asserts `["install", "wrangler"]`.

## Dashboard sidebar and theming

The hand-rolled `.dashboard-sidebar` was replaced with a shadcn-style sidebar
rebuilt on Base UI 1.3.0 in `packages/ui`: `Drawer` for mobile, `useRender` in
place of Radix `Slot`, Chalk's own `Tooltip` for the collapsed rail, state
persisted to a `chalk_sidebar_state` cookie for 7 days, ⌘B/Ctrl+B toggle. About
300 lines of dead CSS removed.

**A breakpoint gap was closed:** the old CSS hid the sidebar below 760px while
the primitive swaps to a drawer below 768px — **leaving 760–767px with no
navigation at all.** The mobile header is now driven by `useSidebar().isMobile`
so both agree on one breakpoint.

Three follow-up bugs, each with an interesting cause:

- **Invisible nav labels.** Tailwind v4 puts utilities in a layer, and the chalk
  scoped reset sat _unlayered_ — **unlayered CSS beats every layer regardless of
  specificity**, so it painted over `text-sidebar-foreground`. Moving the reset
  into `@layer base` restores ordering, and a test asserts the nesting because
  nothing else would catch a regression here.
- **Base UI error 31.** `Menu.GroupLabel` throws without a `Menu.Group` ancestor.
- **Theme desync.** Chalk portals called `resolvePortalThemeFromDocument()` once
  during render, so a popup kept whatever palette it saw at mount and fell
  through to `prefers-color-scheme` while the page stayed light. `usePortalTheme`
  now subscribes via `useSyncExternalStore` to a `MutationObserver` plus the
  media query.

Theming is route-scoped with `<html>` as the single source of truth;
`THEME_BOOTSTRAP_SCRIPT` runs inline in `<head>` and reads the `chalk_theme`
cookie **before hydration** — a server read cannot help, since the shell is
prerendered static on Pages.

Because the dashboard needs auth and the local stack is shared, the visual check
ran off a **static harness**: a jsdom test dumped real component markup and
Playwright screenshotted it against the built stylesheet in both modes. It caught
two spots the token sweep missed, both drawing `#fff` on `var(--ink)` — white on
white in dark mode.

## Kaadr vertical slice — Chalk as the provider

A separate product selected **Chalk over Daily** for its video-call slice, with
Kaadr staying authoritative for context, permission, identity, call state, and
audit while Chalk grants are short-lived provider capabilities. The integration
audit found two real SDK gaps:

1. **No Space lookup/archive in the server SDK** — `ChalkServerClient.spaces` was
   `{ create }` only while the Go API mounts `getSpace`, `listSpaces`,
   `archiveSpace`, `restoreSpace`. Fixed by adding `spaces.get/list/archive/restore`
   with `retry: "always"` (archive/restore are idempotent upserts).
2. **No public `AccessGrant` parser** — and this turned out to be **a ratified
   decision, not a bug**: a contract test asserts the parsers are _not_ on the
   root surface, from the 2026-08-04 ruling that "AccessGrant is opaque; customers
   never construct or inspect it."

The resolution avoided both a cast and an export: `GetAccess` now resolves with
`AccessGrantSource = AccessGrant | Response | object`, the core validates via the
still-private parser, and join fails with `Access was rejected` on non-OK or
malformed input. **The brand on the return type had been ceremony** — the core
already treated the result as `unknown` and validated it.

Also recorded: Chalk React has **no RTL support** (physical `left-/right-`
classes), so consumers must isolate the call surface with `dir="ltr"`; and the
required CSP hosts are `https://api.chalkmeet.com`, `wss://sync.chalkmeet.com`,
plus the SFU hosts carried in the grant.

## Shared-worktree discipline

This week made the pattern explicit, because the shared checkout was almost
always dirty with other agents' work:

- Commits were assembled in throwaway `.worktrees/<name>` checkouts so the gate
  ran against **only** the intended paths — "when the pre-commit ratchet reads
  other agents' dirty files, a `.worktrees/<name>` checkout is the way to run the
  gate honestly instead of `--no-verify`."
- One commit was written with a temporary `GIT_INDEX_FILE` seeded from
  `origin/master` because the shared index already held another agent's staged
  work.
- Type errors and ratchet deltas traceable to other agents' staged files were
  identified and **left untouched**.
- The main repo's `.git/config` flipped to `core.bare = true` twice, unprompted,
  in windows when other codex worktrees appeared; restored each time.

A delegation lesson: a Luna root thread using `fork_turns: "all"` **cannot pass
`agent_type`**, so six `spawn_agent` calls silently failed and the root sat in
`wait_agent` for ~50 minutes with no worker ever existing. **A `wait_agent` on
zero agents should be treated as a stall signal.**
