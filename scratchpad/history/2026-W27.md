## Asset CDN on Cloudflare R2

Created R2 bucket `chalk-assets` and attached custom domain
`assets.chalkmeet.com` (ownership and SSL both active after propagation).
Uploaded optimized backgrounds and sounds under `ui/backgrounds/` and
`ui/sounds/` plus `ui/manifest.json` with short revalidation cache headers.
Configured R2 CORS for public browser reads (`GET`, `HEAD`, any origin) and
verified all 29 manifest URLs returned 200 with the expected content type, cache
policy, and CORS header. `@q9labs/chalk-ui/assets` now exports CDN metadata
instead of packaging background and sound binaries.

**Known gap:** deleted legacy background keys return 404, but exact old immutable
URLs may linger in edge cache. The local Wrangler OAuth token got 401 from the
cache-purge API, so no edge purge was performed — a cache-purge-capable token is
needed.

## ElevenLabs sound generation

Generated all 10 sound sets × 24 events = 240 one-shot assets from
`docs/redesign/sound-design.md` via the authenticated
`api.us.elevenlabs.io/sound-generation` endpoint. Request shape:
`{ text, prompt_influence, duration_seconds, loop, output_format }` with
`prompt_influence: 0.7`, `loop: false`, `output_format: opus_48000_128`.

Output: 240 canonical Ogg Opus files (stereo, 48 kHz) in
`elevenlabs-sounds-2026-07-05/sounds/`, four raw takes each in `raw/`, and a
`manifest.json` recording every take's `historyId` and the `canonicalTake` index.
24 MB total. _(The 960 raw takes were deleted in this same cleanup; the canonical
240 and the manifest provenance remain.)_

## Camera backgrounds under a direct Cloudflare SFU

Question: can Chalk do blur/virtual backgrounds when talking to Cloudflare SFU
directly instead of using RealtimeKit's SDK feature?

**Yes.** RealtimeKit implements backgrounds as local video middleware
(`@cloudflare/realtimekit-virtual-background`); Cloudflare SFU is an
unopinionated WebRTC forwarding layer that forwards whatever track the client
publishes. So Chalk owns a client-side video transform pipeline, outputs a
transformed `MediaStreamTrack`, and publishes/replaces that track on the direct
SFU path. Captured in `docs/camera-backgrounds.md` and
`docs/prompts/camera-backgrounds-implementation.md`.

## The SDK reset

`packages/sdk-core` (150 tracked files) was replaced with a single
`README.md` — a plain-English product spec with no technical detail. Downstream
imports from web, mobile, React, React Native, UI, and TS path aliases were
knowingly left broken until the new direction gets wired back in.

`packages/sdk-react` was reduced to presentational-only: test suite, runtime and
session hooks, context, and logic utilities removed or replaced with inert
placeholders; `src/components`, `src/assets`, `src/styles` preserved as the
visual layer; `@q9labs/chalk-core` dependency dropped.

Web app logic that was really SDK logic — room creation, token exchange,
join-context storage, room entry availability, meeting runtime provider wiring,
mobile join redirects, SDK debug export plumbing, scheduled room SDK calls, SDK
avatar helpers, diagnostics/media simulation — was removed while keeping routes
and visible UI shells. The small app API URL helper used by public status/share
pages was separated from the removed conferencing session helper.

**Surface boundaries settled in the same pass:**

- Media ownership moved into `packages/ui/src/assets`; reaction emoji constants
  into `packages/ui/src/reactions.ts`. Unused shared primitives pruned; narrow
  subpath exports added for `@q9labs/chalk-ui/button` and `/utils` so consumers
  stop importing the root barrel.
- `@q9labs/facehash` root is core-only; React and React Native components sit
  behind `/react` and `/react-native`.
- React Native SDK platform entries split so Android, iPhone, iPad, iOS
  aggregate, and macOS each emit a separate surface.
- Excalidraw references removed from web/root; it stays owned by
  `packages/chalk-whiteboard`.
- `apps/mobile` lost its last `@q9labs/chalk-core` import by moving the helpers
  it needed into mobile-local files.

## Tooling and infrastructure

- Package manager cleanup: legacy runtime command examples replaced with pnpm
  throughout; web public-asset sync switched to `pnpm exec tsx`; the OpenTUI
  incident terminal UI entrypoint, its dependencies, and lockfile records removed.
- `infrastructure/uptime-worker` audit follow-ups: critical ingest alerting, R2
  fallback isolation, manual run auth, generated artifact cleanup, workspace
  rename. Regression coverage added for critical ingest outages with healthy
  checks, R2 replay/buffer/state failures, and token-gated manual runs.
  - **Gate bug found:** `.d.ts` files were not actually ignored, because
    `path.parse("cloudflare.d.ts").ext` is `.ts`, not `.d.ts`. The gate now skips
    paths ending in `.d.ts`.
  - Remote worker delete/recreate was skipped: the authenticated Cloudflare
    account had neither the old nor new worker name, and deploy-time secrets
    weren't available locally.
