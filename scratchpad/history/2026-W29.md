# 2026-W29 (2026-07-13 – 2026-07-19)

Condensed from 66 session logs. Originals removed on
`chore/docs-scratch-cleanup`; full text remains in git history.

The week the pieces met reality: **Sync v3 landed** across a dozen parallel
lanes, **recording was deliberately sidelined**, and the first genuine
**two-tab video call** ran end to end on Cloudflare SFU.

## The first real call (2026-07-14)

Two browser tabs, admitted through the Go API, each created a real Cloudflare
peer session, published camera and microphone tracks, and rendered the other's
remote video — both reporting `Live — API + Sync + Cloudflare SFU` with
`2 tab(s) in Sync · 1 remote feed(s)`. Mute and camera-off were exercised and
restored without error.

Getting there surfaced four real defects:

1. **Browser reconnect storm** traced to client-originated WebSocket close codes
   1012, 1002, and 1001. Browsers permit clients to send only 1000 or application
   codes 3000–4999. Every restart path now uses application code **4000**.
2. **The browser lifecycle adapter disconnected hidden tabs**, making
   simultaneous two-tab Sync presence impossible while Cloudflare media stayed
   live. Browser Sync now gates on network availability only; document
   visibility is no longer treated as application suspension. React Native keeps
   explicit AppState behavior.
3. Sync had to run on its **in-memory adapter** — the Postgres adapter rejected
   the API-created folded snapshot with a digest-contract `invalid_state`
   mismatch.
4. A Vite hot reload during a package build left both media peer connections
   alive but dropped the seeded in-memory Sync coordinator, silently reducing
   presence.

The audit that preceded it was blunt: `RealtimeKit` was dropped for **Cloudflare
Realtime SFU (`cf_sfu`)**, and while Chalk had a Go SFU bootstrap adapter and
provider-neutral Sync contracts, it had **no browser `RTCPeerConnection`
adapter, no track signaling, and no mounted provider-operation executor**. Repo
history contained no earlier browser SFU runtime to restore.

**Credential incident, handled correctly.** An isolated Cloudflare Serverless SFU
app `chalk-local-dev-20260714` was created and its one-time secret stored in the
`dev` 1Password vault. The secret was then reclassified as **compromised**
because Cloudflare exposed it as unredacted accessibility text in a Computer Use
transcript. Rotation was interrupted mid-flight; Hasan explicitly accepted using
the exposed development-only credential for the local test and deferred rotation.
Scope stayed restricted to that one app.

## Declarative Sync v3 — the big landing

Implemented across roughly a dozen concurrently owned lanes (codegen, durable
reducer, Postgres operations, transport, live coordination, SDK, breaker,
retention, admission lifecycle, API integration, v2 removal, real-browser proof)
in one shared dirty worktree, with strict file ownership.

**Contract corrections found during implementation, not design:**

- The frozen migration's receipt foreign key required receipt `command_id` to
  match an event `command_id` — **impossible for external-origin events** whose
  only origin is `external_operation_id`. Replaced with a deferred origin-neutral
  event FK plus a deferred integrity trigger validating command,
  external-operation, or narrowly linked admission lifecycle origin.
- The one-event-per-external-operation partial index **contradicted keyed
  Recording transitions** — one operation may publish ordered acceptance _and_
  terminal facts. Removed; the applied-event pointer identifies the terminal fact.
- Lifecycle origins tightened: only `participant_joined` and
  `admission_requested` use lifecycle intents. Leave and Session end require
  external-operation origin.
- `admission_request_expired` and an exact `admission_expired` control fact were
  added so **pending admission state can no longer disappear through
  nondeterministic wall-clock filtering**.
- Tenant deadline changes use a generation-fenced `tenant_set_deadline` intent
  with external-origin `deadline_changed { deadlineAtMs, deadlineGeneration }`.

Contract grew 17 → **18 events**.

**Authority and race work.** Admission decisions reserve
`decision_external_operation_id` inside the acceptance transaction while holding
the admission row lock, so competing decisions are rejected rather than both
accepted. Maximum-duration acceptance persists and validates the
scheduler-supplied `deadlineGeneration`, rejecting stale first arrivals.
Participant authority is read from the **writable primary** under a share lock,
deriving capabilities from the current role rather than caller claims — token
capability claims are never consulted for live authorization.

**A real production defect the breaker caught:** provider observations had no
monotonic version, so an older snapshot could overwrite newer media truth and
release leases incorrectly. Added a provider-neutral `{incarnation, sequence}`
observation cursor; inconsistent cursor reuse is rejected and stale observations
are ignored before projection or lease reconciliation.

**Another the audit caught:** live reconciliation was emitting fresh
sequence-zero replacement snapshots, contrary to the frozen exact-next live
projection contract — a reordered replacement can leave the TypeScript replica
stale because unrelated projection IDs aren't freshness-comparable. Ordinary
media/presence changes are now exact-next projection events with explicit
disabled/disconnected tombstones; snapshots are limited to recovery and bounded
rotation.

**Long-session correctness gaps** returned to the transport lane rather than
accepted: screen leases were acquired but never renewed, provider-driven media
loss had no periodic refresh, provider calls could block coordinator tasks, and
ambiguous grant completion could strand a reservation. Fixed with bounded
`async_nolink` MediaPlane calls, a single coalesced `Task.Supervisor`
reconciliation task with stale-result discard, and lease renewal/rotation with
recovery after local Coordinator state loss.

**End acceptance ordering** was corrected twice. Final shape: tenant end and
maximum-duration expiry lock the Session and Participants, install end fences,
and mark ending **immediately** without waiting for pending or ambiguous
publication grants; Sync's operation claim is the only wait point. Session-end
acceptance also locks any active `starting|recording|stopping` Recording and
retains its ID, so end can't confirm media cleanup while a Recording is live.

**Provider executor.** Replaced the local false-success consumer with bounded
all-operation dispatch: confirmation-only success, terminal failure
finalization, retained ambiguity/retryability, and terminal retry exhaustion at
a durable 100-attempt claim ceiling. Every provider adapter call is wrapped in a
hard timeout so a hung provider can't block the single bounded consumer.
End-session aggregates MediaPlane and RecordingPlane concurrently under one
deadline with a stable operation ID, finalizing only after both confirm.

**Retention was reopened after acceptance.** A read-only spec-to-code audit found
the seven-day cleanup pruned events, receipts, and lifecycle intents but retained
terminal external operations, AdmissionRequests, Recordings, leases, fences, and
grant reservations **with no later age bound**, and eligibility didn't exclude
pending external reconciliation. Rewritten with explicit FK-ordered deletion in
one locked transaction after an independent event fold, durable row/byte
checkpoint counters across 18 deletion counters, and negative pending-work
eligibility proofs.

**v2 removal.** `/v3/sync` owns `SocketV3`; version 2 generation is rejected; v2
server/client/storage/breaker artifacts deleted. Disabled v1 remains an isolated
RoomServer compatibility surface. This left **no v3 deterministic campaign or
replay oracle** — the surviving generic breaker is protocol-v1/action-shaped —
so a v3 breaker was rebuilt.

**The v3 breaker took three attempts and one plan change.** The first pass
represented required faults as _schedule labels_ instead of executing production
seams, and was rejected rather than accepted. The replacement still lacked
ordering, crash-window, race, stale-generation, and reconciliation schedules, and
its "independent" oracle called the production reducer. Rather than relaunch the
same brief a third time, the plan changed: shared deterministic seams were fixed
first (`DeliveryGate.emit/4` intercepts command results before the socket mailbox
and Coordinator notifications at their actual sends, with the production adapter
immediate; an external-executor crash checkpoint sits after provider confirmation
and before durable finalization), then four collision-free phases ran in
parallel — durable/lifecycle, external/media, delivery/recovery, wire/SDK.

A recorded limit worth keeping: **deterministic ACK/event ordering and
dropped-head-hint replay cannot be controlled by a test-only breaker.**
Stateholder exposes transaction hooks including `after_commit_before_reply`, but
`notify_head/3` has none and Coordinator sends outbound messages immediately.
Completing the approved matrix needs a production coordination fault boundary or
an injected scheduler/notification port.

The wire/SDK phase's first invalid-wire proof was found **tautological** (it used
`type=operation` and server-only encoding checks) and replaced with five concrete
legacy `type=command` aliases plus a remote-force-on shape, proved rejected on
both the Elixir decode side and the production-source SDK encode side.

**Codegen defect found only by real browser proof:** generated `delivery_ack`
validation retained the wire `stream` key but **discarded it from the decoded
value**, so the live socket returned `error:protocol_error` after revision 2.

**SDK.** Self-media waits for server authorization _and_ same-ID local adapter
confirmation; adapter observations are bounded and read-only; **no remote
force-on port exists**. External-operation liveness polls the unchanged command
frame every second after `external_operation_pending`, independent of the
three-attempt transient retry budget, with command-keyed timers cleared on ACK,
disconnect, stop, reconnect, removal, or the configurable
`maxOperationPendingAgeMs` ceiling (24-hour default).

Review found and fixed a family of SDK persistence races: failed startup latched
`#started`, a stopped startup resumed after `load()`, failed durable cleanup
threw before settling the command promise, and a stale ambiguous attempt could
re-reserve an ID after startup proved its row absent.

Several client test failures turned out to be **test races, not product bugs** —
`TestSocket.receive` only enqueues onto the private inbound promise, so a fixed
event-loop delay was unrelated to asynchronous digest completion. Replaced with
exact snapshot-subscription predicates; the conflicting-evidence scenario then
passed 200 independent repetitions.

## The v3 migration bug — caught, then caught again

The v3 migration was first verified clean and marked **done**. Post-commit review
invalidated that verdict twice:

1. The backdated version `20260712233000` **could be skipped** by databases
   already at head `20260713090000`, and the new v3 lifecycle/receipt checks
   **rejected valid v2 writes during a rolling upgrade**.
2. A later rename from `20260712233000` to `20260713130000` was itself flagged as
   release-blocking: Goose tracks applied versions, so databases that applied the
   old version would see the renamed file as pending and **rerun its
   non-idempotent DDL**.

Final repair: migration at `20260713130000`, each existing Session's deadline
backfilled from its own `created_at`, legacy v2 rows preserved via `NOT VALID`
checks that are then validated on clean histories, new v2 writes rejected, and
the v2 lifecycle index preserved. Verified by seeding PostgreSQL 18.3 at
`20260712223000` with an old Session, lifecycle history, and committed/rejected
v2 receipts, then migrating and confirming all three intents, both receipts, both
legacy NULL field sets, and the per-row deadline survive.

## Recorder — built, spec'd, then sidelined

**Foundation implemented:** one Go control plane with PostgreSQL authority plus
isolated capture and render binaries, worker mTLS identity, exact-size conditional
R2 upload primitives, public-safe fail-closed health endpoints, recorder metrics,
and reservation/pipeline HTTP routes.

Two review rounds found **thirteen defects** and judged the first foundation
incorrect: admission ignored pool health, expiry could race an active lease,
render packing ignored individual deadlines, release left claimable work, two
domain errors mapped to 500, critical monitors had no health writer, no-show
expiry didn't restrict to never-claimed capture jobs, future-dated health was
accepted, terminal reporting wasn't retryable, stale audio levels never expired,
and render assignments weren't evaluated in EDF order.

**Four dedicated seam specs** were then written (control plane, native capture
worker, GPU render/finalization worker, staging qualification) after an audit
found the ratified recorder document was an _umbrella_ spec with no
implementation-ready seam contracts. Official Cloudflare docs settled **direct
Cloudflare Realtime SFU as the native capture transport**, with Pion as the
worker WebRTC client and workers never receiving the SFU application secret.

**Then the destination changed.** RealtimeKit's 2026 managed composite and
participant-track recording replaced the unimplemented custom Pion/GPU launch
path — and shortly after, Hasan decided deferred recording must not remain
partially exposed or incur avoidable cost. The exposure map found the custom
runtime inert by default but public and Sync surfaces could still promise
recording or create partial durable state, with **no global kill switch**.

Final boundary: retain SDK methods, React/React Native utilities, REST routes,
OpenAPI, generated clients, and Sync schemas; remove recording only from
Chalk-owned UI and active execution. REST mutations and SDK calls return
`recording_disabled`, historical REST reads remain, Sync capability/dispatch
detaches at one compile-tested seam, and runtime/infrastructure stay detached
rather than becoming commented-out code.

## Transcription

An API-owned fenced artifact subsystem, private R2 transcript documents, and a
separately packaged Lambda dispatcher.

**Provider contracts are weaker than they look.** DeepInfra and Cloudflare timing,
version identity, file bounds, and billed duration are **not fully guaranteed by
published contracts** — DeepInfra's OpenAI-route payload/time limits and
successful-response schema are undocumented, and Cloudflare exposes no
enforceable model-version or per-attempt billing identity. Adapters therefore
validate timings, distinguish measured from observed duration, and fail closed
when execution identity or corpus gates are unavailable.

Integration review **rejected** static worker bearer auth, caller-supplied
manifest/chunk keys, configured-as-observed DeepInfra identity, unverified
conditional-upload collisions, and plaintext Lambda secret environment variables.
The fixed boundary uses replay-bound workload signing, recorder-owned committed
source metadata, job-scoped manifest/chunk/result URLs, SSM cold-start reads, and
API-side object verification before fenced commit.

Multi-chunk completion closed with a durable fenced finalizer job that verifies
and merges ordered chunk documents, retains and marks cross-track overlap,
preserves per-cue provider facts across mixed DeepInfra/Cloudflare results, and
writes one conditional final document the API independently verifies.

Two clean rebuilds of the dispatcher from source with a fixed epoch produced
identical SHA-256 `92203b8b0b5fcf6f12fa46a71afbae2320cc68e38ddb7c7e386c71c98b98bb7f`.

## Webhook canary — six of eight, honestly

The signed public receiver proof passed exactly-once delivery for `room.created`,
`room.updated`, `room.archived`, `room.restored`, and `session.started`, plus
signed-503 handling, durable retry across API restart, and duplicate manual
redelivery.

It **did not** reach all eight, and the blockers were disclosed rather than
worked around:

- Public participant admission returned `media_plane_unavailable` (no configured
  local media-plane adapter).
- The public API admits every participant as role `participant` with eligible
  roles `[participant]`, while v3 requires exactly one Host.
- API-created Session `folded_state` omitted `host_exit_policy` and
  `role_capabilities`, so Sync rejected a correctly Host-seeded join as
  `invalid_state`.
- The local API harness configures no `CHALK_SYNC_TOKEN_PRIVATE_KEY`, so
  admission omits its optional `sync_token` and the v3 SDK can't connect.

After each was narrowly repaired in a disposable database with exact-one-row
assertions, the final run still timed out on `host v3 Sync recovery was not
observable within 30 seconds` with Sync healthy and logging no rejection —
recorded as unobservable at the present logging boundary rather than attributed
to the repaired state. **No production contract was widened to hide these.**

Real defects fixed along the way: an untyped PostgreSQL `CASE` in dispatcher
completion; `cardinality(NULL)` making omitted state and Event filters exclude
every row; an individual webhook Delivery branch becoming the aggregate journey
terminal state while sibling Deliveries were still pending; dispatcher fairness
upgraded from an intra-batch cap to durable cross-cycle tenant rotation (per-
Endpoint cap four, per-tenant cap twenty, persisted last-claim time); and
outbound address validation extended to reject IPv4/IPv6 special-purpose,
transition, documentation, multicast, and reserved prefixes including
`64:ff9b::/96`, Teredo, 6to4, and anything outside `2000::/3`.

A dedicated **300/min principal-scoped read policy** was added for the four
inspection routes so they don't consume the 60/min write bucket.

**Postgrex codec trap:** Postgrex generates its default type module at _dependency
compile time_, so an incremental build artifact retained `Jason` despite later
application configuration. Replaced with `ChalkSync.PostgresTypes`, explicitly
generated with stdlib `JSON` and selected by every Sync connection.

## Pre-staging readiness and the provider bridge

Three parallel read-only audits (API/artifacts, Sync, runtime/infra/observability)
found: transcription implemented and committed; recording with an integrated
control plane but no real SFU capture, composite rendering, mounted worker-control
HTTP operations, or production pool-health writer; Sync needing migration-range
and consumer-readiness fixes; and runtime, staging IaC, managed observability,
release control, and cost automation **largely unimplemented**.

**Architecture decision:** Sync remains the durable intent, authorization,
fencing, retry, and finalization owner; the **Go API becomes the sole
provider-execution gateway** over a private versioned mTLS interface, owning
provider credentials, calls, reconciliation, recording admission, durable
execution receipts, and the media-observation journal.

The bridge was built and proved cross-runtime against a fake provider: Sync
created and claimed a durable mute intent, used a bounded client over **TLS 1.3
mutual authentication with an ephemeral SPIFFE identity**, reached the real Go
handler/service/Postgres repository/verifier, invoked the fake provider exactly
once after the receipt was `dispatching`, finalized as applied with attempt count
one, and could not reclaim it.

Wire contract fixed deliberately: Go computes the canonical fingerprint rather
than trusting the caller; a same-identity/different-fingerprint replay resolves
to terminal `fingerprint_conflict` **without provider dispatch**; raw provider
publication/session/participant identifiers never cross the boundary.

**Status recorded as not done**, with the reasons named: no private mTLS
listener wiring, and no real Cloudflare dispatch because RTK has no durable
Chalk-ID/provider-ID mapping, SFU removal/end are unsupported, and neither
adapter exposes publication grant/revoke, recording start/stop, or observations.

A **release-blocking schema drift** surfaced here: freshly applying all
checked-in migrations through `20260713120000` did not create
`room_sessions.host_exit_policy`, `sync_admission_requests`, `sync_recordings`,
`sync_publication_fences`, `sync_publication_grant_reservations`, or
`sync_external_operations`, although generated code required them.

## Architecture atlas and its secure Worker

Built `architecture.html` — a self-contained atlas with system, plane, journey,
runtime, and data perspectives covering seven journeys, a five-lane recording
flow, four-zone runtime topology, seven Postgres domains, and 50 named tables,
with ranked global search and light/dark themes.

Its defining property: **it distinguishes repository implementation from
deployment readiness.** Review pushed this further — every partial system, plane,
component, journey, and runtime item got an explicit "Not done yet" definition,
and a follow-up found detailed partial journeys still labelling incomplete steps
as built, so unproven recording and transcription steps were marked partial with
their own completion gaps and the completeness assertion extended to journey
steps.

A dedicated Cloudflare Worker now serves it behind access control: content-hashed
bundled assets, secret-derived signed sessions, login-only rate limiting, and
hash-pinned CSP. Verified anonymous HTML/asset denial, secure session issuance,
authenticated build identity, and **byte-for-byte SHA-256 integrity** for both
bundled assets; the real rate-limit binding returned `401` for attempts 1–10 and
`429` with a retry boundary on attempt 11.

Adversarial review found four deployment-safety gaps (unpersisted access-code
rotation, readiness not identifying the expected build, chunked login bodies
bypassing the size guard, Worker tests outside the canonical gate) and then three
more (a **User-Agent rotation bypass** in the limiter, pre-deploy credential
persistence losing the last working code on failure, and a backslash-based
return-path redirect). The limiter is now keyed solely by Cloudflare's trusted
client IP.

A Wrangler/workerd boundary was recorded: Wrangler 4.107.0 accepted a
`2026-07-17` compatibility date during dry-run, but its bundled runtime supports
dates only through `2026-07-08`.

Separately, architecture-page zoom was fixed — both pages applied a fixed 12%/11%
jump per wheel event, ignoring touchpad delta magnitude. Replaced with
delta-proportional exponential scaling at sensitivity `0.002`.

## Smart gate

Staged-file scope locally, merge-base-to-HEAD in PR CI, affected checks plus
dependents, automatic isolated services, one coverage pass, and nightly/release
full mode. Includes a disposable migrated PostgreSQL wrapper shared by the API and
Sync gates.

Findings while building it: a coverage proof was silently suppressed by an
argument separator; a default-config test inherited the gate's intentional
database URL; pnpm's forwarded `--` delimiter needed explicit handling; and a cold
combined run exposed **three WebSocket upgrade timeouts** at ExUnit's automatic
20-case concurrency — capped at ten concurrent cases (overridable via
`CHALK_SYNC_TEST_MAX_CASES`) to match available schedulers rather than adding
retries.

Also fixed here: a regenerated `CloudflareSFUTracksResponse` schema collided with
the hand-written public media type (renamed the OpenAPI component to
`CloudflareSFUTracksAPIResponse`, preserving the wire response), and the web build
completed output but **never exited** because module-load telemetry construction
left an Effect scheduler timer referenced.

The long-running Expo/Hermes `import.meta.env` blocker was finally resolved with a
dependency-scoped Babel transform replacing only Effect's `import.meta` on React
Native, preserving `process.env` fallback.
