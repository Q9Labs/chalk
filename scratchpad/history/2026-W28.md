# 2026-W28 (2026-07-06 – 2026-07-12)

Condensed from 80 session logs — the densest week in the archive. Originals
removed on `chore/docs-scratch-cleanup`; full text remains in git history.

Three large threads ran in parallel: the **contract-first codegen pipeline**
(Go route contracts → OpenAPI → TypeScript/Effect SDK), the **sync engine

## Execution Trace Harness

Born from a stated confidence gap: reading generated code doesn't make behavior
stick. Built `apps/api/cmd/trace` + `internal/traceharness` — a scripted local
runner that walks a request through the **real** `httpapi.NewRouter` and real
service packages, with traced local doubles only at external/repository
boundaries. Records request input, auth principal, service normalization,
repository input, simulated DB transaction/query/result mapping, and final
response.

Scenario families: `route:*`, `service:*`, `policy:*`, `adapter:*`, `edge:*`.
Edge cases are first-class, not hidden in tests. CLI gained
`-color auto|always|never`, a summary header, an indented field tree (JSON-shaped
blocks were unreadable), and kept `-format json` machine-readable.
`ScenarioNames()` + `TestRunAllRegisteredScenarios` ensure every registered
scenario is exercised. Durable guidance in
`apps/api/docs/execution-trace-harness.md`.

## Contract-first codegen: from route shapes to a real SDK

**The problem.** `chi.Walk` recovers method, path, handler symbol, and middleware
count — but not request/response schemas, middleware identity, auth scheme,
rate-limit policy names, or error contracts. AST parsing of `internal/httpapi`
recovered JSON-tagged DTOs but hit real ambiguity: successful responses are
helper calls (`newTenantResponse(tenant)`), variables, or map literals, and error
mappings are scattered across handlers, service-error helpers, middleware,
authorization, CORS, and rate limiting. Validation rules
(`MinPasswordLength`, `mail.ParseAddress`, `regions.Contains`, `validRole`,
`pagination.MaxPageSize`) live in services, not on the DTOs.

**The answer: typed endpoint contracts.** Converted writer-style handlers to
`httpapi.Endpoint[Request, Response]` factories. Route mounting iterates endpoint
values, and the same values expose contracts to the generator. Introduced named
rate-limit policy names in `internal/ratelimit` and named `APIError` descriptors
so the contract attaches to a real route rather than a detached scratch schema.

**Pipeline promoted into the repo** (`apps/api/cmd/codegen`,
`scripts/codegen/*`, root scripts `generate:openapi`, `generate:sdk`,
`check:sdk-generated`). `check-sdk-generated.sh` is **non-mutating**: it
generates into a temp dir and diffs against checked-in artifacts. Wired into
`scripts/gates/commit.sh` as a drift gate.

**Semantic richness beyond structural generation:** nested list fields reuse
top-level component schemas; named provider-config schemas; generated enums;
validation constraints (UUID, email, URI, timestamp, non-empty); scalar component
schemas carrying `x-chalk-brand` (`TenantId`, `UserId`, `RoomId`,
`RoomSessionId`, `RecordingId`, `TranscriptId`, `MembershipId`, `AuditLogId`,
plus `UUID`/`Email`/`URLString`/`DateTimeString`). Polymorphic `resource_id`
stays unbranded until the contract can name its union. Effect emitter orders
schemas by `$ref` dependency so output compiles without forward references, and
emits tagged error classes from `x-chalk-error-codes`.

Baseline grew 26 paths/36 ops/54 schemas → **31 paths/43 ops/62 schemas** after
migrating the seven manually mounted integration routes into endpoint contracts.

**Effect v4 status (as of this week):** `effect@4.0.0-beta.94` exists under the
`beta` tag, but `@effect/platform@latest` still peers on `effect ^3.21.4` with no
v4 beta tag. Direct tarball compile confirmed v4 HttpApi/Schema are **not**
source-compatible with the v3 generator.

**Contract frontend decision — deliberately left open.** Rather than pick
TypeSpec vs a Chalk-native declarative format on vibes, both frontends were made
to lower the same expanded HTTP+sync fixture to a byte-identical 53,518-byte
canonical IR across 20 runs. An early comparison scoring native JSON 95.00 vs
TypeSpec 78.63 was **rejected by critical review** — the fixture omitted promised
entities and sync branches, TypeSpec lowering discarded error fields and
parameter optionality, and several "measurements" were rubric constants. The
repaired report records measured costs _without a score_ and selects no frontend.
Custom emitters are preserved regardless; TypeSpec would be evaluated only as a
parser/type-checker feeding a Chalk-owned versioned IR, so it stays replaceable.
`docs/contract-codegen.md` is the long-term spec.

## Sync engine: the Redis-authority reversal

The first production-readiness draft made Redis authoritative (leases, fencing,
change delivery, `WAITAOF` durability barriers). Two independent architecture
audits agreed it **recreated database serialization** through those mechanisms.

**Reopened and rewritten around direct Postgrex transactions**: one locked
Session control row, durable events and receipts, lifecycle intents, disposable
node-local coordinators, Postgres notification hints with head reconciliation,
bounded delivery, protocol v2, a real TypeScript runtime, and real-Postgres
multi-node/failover proof. Live module docs now state **PostgreSQL is the sole
durable Sync authority; Redis is optional acceleration.**

**Implementation proofs (isolated Postgres 18.3):**

- Locked command transaction: receipt-first resolution, atomic
  event/fold/revision/receipt commit, transaction-local deadlines, synchronous
  commit, capacity counters, disposable head notification.
- Six real-Postgres transaction tests proved atomic commit, independent fold
  equivalence, durable receipts past 300 intervening IDs, connection-set restart
  recovery, **unknown-COMMIT resolution**, pre-COMMIT rollback and safe retry,
  and concurrent decisions from two independent node connection sets.
- Bounded per-socket outbound ETS queue keeps encoded payloads out of process
  mailboxes; clears its tables on close or overflow; sockets outside the
  overflowing queue are unaffected.
- **Real two-node proof:** two unclustered BEAM OS processes accepted concurrent
  commands for one Session through separate v2 listeners, converged via Postgres
  notifications, retained one revision order, survived one node death, accepted
  another command on the survivor, and restored the killed node at authoritative
  revision 5.
- 100,000-operation deterministic campaign across 16 sessions / 64 participants /
  128 sockets passed; the 351,337-line trace replayed and reconstructed all 16
  sessions. Clean artifact `seed-2026071205-1783816283847-1`, trace SHA-256
  `6e049ffd38bac5ff06ba66fa4470946bc5c7797332743c209e261b0f99e2530b`.
- Launch-cardinality fixture: 500 participants, 250,000 events, 500,000 receipts.

**Two important corrections found by proof, not by tests:**

1. The slow-reader bound was **unproven** — the OS absorbed 2,000 small frames
   without forcing a non-reading peer to disconnect. Fixed by retaining sent live
   frames as in-flight until the client acknowledges the exact revision and
   digest, so event/byte/age limits cover queued _and_ in-flight delivery and
   kernel/WebSocket buffering can't hide a dead reader. Real bound then proved:
   disconnect on the **257th** outstanding live event, while an acknowledging
   peer continues.
2. A 100,000-op campaign failure (`revision_order_or_convergence=:snapshot`) was
   a **defect in the verifier, not the engine**: revision-zero recovery correctly
   chose a snapshot past the 2,048-event replay limit while the verifier demanded
   replay mode. Artifact preserved and fully streamed before any code changed.

Frame-size boundary corrected: the generated protocol's **1,048,576-byte** cap
applies to full snapshot-welcome; the 65,536-byte cap is client-to-server only.

**Sync Breaker harness.** Layered design informed by FoundationDB simulation,
TigerBeetle VOPR, and Jepsen: independent model + seeded histories → direct OTP
fault injection → real WebSocket actors → Redis/multi-node chaos. Failures must
be machine-detectable through model-based invariants, not throughput or crash
counts. Review found artifact/verdict defects that would have produced _false
passes_: empty scenario selection passed without executing a check, and three
serializers stringified booleans/nils. Also: the "loopback-only" ephemeral Bandit
listener actually relied on the all-interface default — bound explicitly to
`127.0.0.1`.

**Sync readiness verdict (2026-07-11):** core prototype coherent and locally
tested; production service **not ready**. No Redis stateholder, release/container
setup, Elixir CI job, telemetry, readiness check, rate limiting, or soak
evidence; production boot fails with `CHALK_SYNC_TOKEN_VERIFIER must be set`.

**Declarative sync v3.** Hasan selected `/v3/sync`, target-only SDK methods
(`setMicrophoneEnabled`, `setCameraEnabled`, `setHandRaised(boolean)`), and
**immediate v2 disablement with no compatibility window** — Chalk has no
production v2 clients. Settled: role presets `host | cohost | participant` with
capabilities from Session policy and no per-participant overrides; admission
`open | approval | closed`; one concurrent screen share; self-only display-name
changes. **Consent-safe moderation** — moderators may force microphone/camera
_off_ and _request_ unmute, but never force capture on. `host_exit_policy` is
immutable after Session creation and is `require_transfer | promote_cohost`;
disconnect alone never transfers host authority. This replaced a stale North Star
rule that auto-promoted the longest-present participant. Host membership never
expires from presence loss; every Session has a tenant-selected, plan-capped
maximum duration.

Media boundary corrected after an adapter-coupled proposal: **MediaPlane** owns
provider-neutral media execution/observation, **SyncEngine** owns live capability
enforcement and signaling, **Postgres** retains only durable
policy/lifecycle/receipts/facts.

## Outbound webhooks

Lifecycle-core events, at-least-once delivery, public management API, minimal
payload snapshots, transactional outbox. Envelope field is `event` (not `type`),
versioned with integer `api_version: 1`.

Sync is in scope because it is the durable authority that applies lifecycle
intents and commits Participant active/left and Session ended — but its ownership
is narrowed to same-transaction Event production; endpoint management and
delivery stay in API and dispatcher.

A server-only `@q9labsai/chalk-client/webhooks` subpath provides raw-byte
Standard Webhooks verification, secret rotation, typed dispatch, and a
customer-supplied durable inbox lease contract — kept out of root/browser/RN
exports.

**Notable findings:** the overloaded Endpoint revision was split into a public
configuration revision and an immutable delivery **Target Revision**, resolving
the contradiction between incrementing `If-Match` on every PATCH and not creating
a new target for name-only changes. Go's default JSON marshaler and Elixir's
encoder **disagree on HTML escaping** — the canonical signed Participant fixture
was strengthened with Unicode, quotes, a backslash, and HTML-sensitive characters
and both HMAC vectors recomputed. Default batch-size fairness could starve later
tenants. The SSRF blacklist omitted IPv6 transition/reserved prefixes.

Repeatedly held at **not done** rather than accepting code-complete: missing
real-Postgres delivery-state tests, management audit records, erasure journey
closure, queue/cleanup telemetry, and hostile egress cases. A restore-safety gate
stayed open — `EraseUserWebhookEvents` destroys live signed bodies and fences
delivery, but there is **no durable external erasure tombstone or backup-restore
reconciliation authority**.

## Observability v1

Vendor-neutral OTLP/Collector core; Grafana Cloud as initial managed backend;
first-party React Native Sentry crash adapter. Browser OTel auto-instrumentation
is still experimental, so the SDK exposes a **Chalk-owned event/diagnostic
contract with injected exporters**, not OTel as public API.

Central guarantee: **every meaningful operation retains a complete journey
skeleton at 100%**, while expensive healthy detail stays sampling-eligible.
Journeys may root at client, API, sync, worker, provider, infrastructure, or
monitor; each records the first observed layer and whether upstream visibility is
complete, external, or unknown, then follows every fanout branch to a terminal
state. Implementation gates must prove sampling cannot erase a journey.

Media model corrected mid-plan to **direct Cloudflare Realtime SFU as primary**,
with RealtimeKit as an uncommon adapter. Cloudflare internals remain an
acknowledged blind spot with only two real ways to remove it.

Verified first complete local journey across client intake, API persistence, sync
work, Postgres, Tempo, Prometheus, Loki, and Grafana. Hardened from review:
malformed browser telemetry queues isolated so one corrupt entry can't block
recovery; telemetry intake credentials routed through canonical expiry/revocation;
requests bounded by **both** event count and encoded size (100-event cap aligned
across server, OpenAPI, and TypeScript).

A real Tempo defect surfaced: leading-zero trace-ID normalization — Tempo
returned the ID without its leading nibble while the smoke script required exactly
32 characters.

## Infrastructure readiness — ratified, reopened, re-ratified

Baseline selected: **AWS `ap-southeast-1`**, one small rebuildable API/sync/Redis
node behind **Cloudflare Tunnel**, **PlanetScale Postgres** in-region, separate
recorder worker, persistent staging + production, immutable **GHCR** images,
GitHub OIDC + SSM deploys, **OpenTofu** as canonical IaC CLI, 1Password as secret
source with SSM as runtime mirror, `api.chalkmeet.com` / `sync.chalkmeet.com`
with no compatibility aliases. Podman under systemd Quadlet as the EC2 OCI
runtime. Email as the lean launch notification destination.

The deleted Terraform stack was reviewed **only as failure-mode history**: it
coupled mutable `latest` images, application secrets, a single public EC2 origin,
and provider resources into one production state. The new design inherits none of
its modules.

**Decisions with explicitly accepted consequences:**

- Root-local Redis AOF for the Sync Stateholder → **explicit loss of active
  collaborative state after total app-node/root-volume loss**; a terminal
  room-generation outcome rather than silent empty-state recreation.
- PostgreSQL-only durable jobs (`FOR UPDATE SKIP LOCKED` leases, CAS attempts,
  retry/dead-letter, reconciliation) — no external job infrastructure.
- R2 as the only finalized-artifact store, **no restore** after accidental,
  malicious, or authorized object deletion. 30-day default / 365-day maximum
  tenant-configurable retention; no legal hold at launch; hard delete revokes
  access immediately and verifies active-store deletion within 24 hours.
- PlanetScale's included **two-day** backup/PITR window → corruption discovered
  after two days has no restore point.
- Recovery objectives: service and AOF recovery ≤2 min, verified rollback ≤10
  min, app-node replacement ≤15 min, PlanetScale RPO 5 min / RTO 2 h.
- Pre-authorized rollback is part of each production approval and may return
  **only** to the prior stable manifest named in that approval.

**One aggregated uptime service was rejected.** Independently scheduled web, API,
sync, media, artifacts, telemetry-pipeline, and status services per environment,
sharing a result contract but with separate identities, heartbeats, credentials,
fallback buffers, and alert labels. Public status lives at
`status.chalkmeet.com` on a dedicated Pages project + Worker + private R2 — the
accepted tradeoff is that it survives Chalk deploys, API failures, and app-node
loss but **not a Cloudflare-wide outage**; external Grafana probes and a
non-Cloudflare paging destination are the operator signal.

**Cost work was repeatedly corrected by measurement:**

- Grafana Free allows one stack per account; environment write isolation would
  make Pro mandatory — resolved by two company-controlled Free accounts (a
  _provisioning gate_, since public material doesn't confirm one company may own
  two). Fallback is production Free + staging local-only, **never** an automatic
  Pro upgrade.
- Workers Free permits 100 Workers but only **five Cron Triggers per account**;
  four component services across two environments need eight. Combining checks
  into one scheduled handler was excluded, so: Workers Paid ($5/mo, 250 triggers).
- Grafana synthetic billing counts probe locations, tests, and runtime minutes
  **rounded up** — the 80,640-execution scenario assumed one billed minute and
  excluded browser/media/artifact/retry/drill volume. Free-plan headroom stopped
  being treated as a production forecast.
- Staging moved from always-on to scale-to-zero outside bounded activation
  windows with an 8-hour max lease. A critique found an in-node expiry workflow
  **cannot guarantee its own shutdown** → replaced with an external five-minute
  EventBridge/Lambda reconciler with conditional activation records, bounded
  drain, forced scale-to-zero, root deletion, and heartbeat/drift alerts.

**Recorder capacity reopened the spec twice.** A three-concurrent-recording
launch ceiling was rejected; target became ~15–20 simultaneous recorded meetings.
Twenty always-warm DigitalOcean workers would cost $840/mo, so the final shape is
**scheduled prewarming with an unscheduled meeting-start hold**: native selective
WebRTC capture in SGP1 separated from scale-to-zero GPU composition in TOR1,
encrypted temporary rendering, deterministic 720p30 stage view within 30 minutes.
Browser composition, client-side capture, RealtimeKit managed export, and live
native composition were all rejected for launch on cost, reliability, or coupling
grounds. Capacity contract: ≤20 recorded rooms, ≤10 participants per recorded
room, 100 total launch participants, 120-minute recording cap, global 21-node
recorder-compute ceiling.

**Transcription:** DeepInfra `openai/whisper-large-v3-turbo` primary
($0.00020/audio-min) with Cloudflare Workers AI fallback ($0.00051). Providers
are **never raced** — a full fallback adds ~$37–45, not a second bill.
Speaker attribution uses **track-aware authenticated per-participant SFU tracks**,
not acoustic diarization; each non-overlapping interval is billed once and only
real crosstalk splits per participant. A shared physical microphone is honestly
one speaker device. Pyannote is a future mixed-audio adapter, not a launch cost.

Final ratified envelope: ~$140.48/mo normal baseline, warn >$155 production +
foundation, warn >$25 staging, pause automatic staging changes >$10 delta, block
combined plan >$200.

**Honest capacity position:** the topology is a _lean launch foundation with an
accepted single-app-node availability boundary_ — not HA, not horizontally
scalable. Local Go runs hit ~10,700–12,800 req/s with no errors but omit
production hardware, network, database, sync, Redis, and observability paths. 100
concurrent participants is the first staging qualification workload, **not a
promise**, requiring a six-hour soak; at most 70% of the first failing load is
admitted after that lower ceiling passes its own soak. Vertical scaling is the
only launch-era scale response until shared Stateholder and distributed sync
ownership exist.

## React effects policy

Audit found **57 direct `useEffect` calls** (56 in components, one in
`internal/useMediaQuery.ts`). Official React guidance treats Effects as an escape
hatch for external synchronization and does not recommend an application-wide ban
where components must synchronize media, timers, DOM, subscriptions, or
third-party widgets. Enforceable boundary adopted: **zero raw Effects in
components/utils**, with genuine lifecycle synchronization isolated in narrowly
named internal adapters or external stores.

The React Native SDK completed this refactor to **zero `useEffect` sites** —
manager hooks moved to `useManagerState`/`useSyncExternalStore`; preview,
transcripts, whiteboard, recording duration, clipboard, animation, pagination,
pre-join, meeting-room, Android connection, and multitasking lifecycles moved
into framework-free stores/controllers; CallKit split into
`NativeVideoConferenceCallKitController` with an injected port.

**`VideoConference` does not exist.** Commit `0d25f532` deliberately deleted it
and `MeetingRoom` on July 5 when the runtime/controller layer was removed — while
the public website still shows the nonexistent root import. Rebuilding it
requires a settled client/runtime boundary (admission, provider bootstrap,
session state, media/sync).

## Effect migration of the TypeScript client

Telemetry moved to Effect-native internals behind its Promise facade, preserving
all 52 scenarios. Two real regressions were caught by audit before they shipped:
the stream pipeline didn't force a full batch through before the linger window,
and an event emitted during async restore could persist before restored events
merged. Final internals: client and compatibility delivery facades own
ManagedRuntimes and dispose scopes idempotently; retries use a scoped
`Schedule.spaced(...).pipe(Schedule.take(1))`; event IDs/timestamps come from an
Effect Clock/Random-backed Layer. Tests use a scoped ManagedRuntime with TestClock
plus scripted exporter/storage Layers.

## AI BYOK

Vocabulary settled: **gateway** (OpenRouter, Cloudflare AI Gateway) ≠ **provider**
(Anthropic, OpenAI, Google, Meta) ≠ **model** ≠ **account** (credential bundle;
tenants may have several) ≠ **generation** (persisted invocation with usage/cost
ledger rows).

**Scope was then deliberately cut to simple BYOK only.** The richer AI account,
policy, model allowlist, async generation, and usage-ledger design is explicitly
_not_ to be silently reintroduced unless reopened. Spec at
`apps/api/docs/ai-byok-plan.md`.

Transcription route corrected away from caller-provided base64 audio: `POST
/recordings/{recording_id}/transcriptions` reads the completed recording's
tenant-owned storage key and streams the object body. Extensionless recordings
resolve via parsed media types (`video/webm; codecs=opus` → `webm`,
`video/mp4` → `mp4`), extension takes precedence over content type, and empty
audio streams are rejected before calling the provider while preserving the first
byte for non-empty streams. OpenRouter STT is synchronous and upstream providers
can time out around 60s, so async transcription must be a Chalk-owned job flow.
