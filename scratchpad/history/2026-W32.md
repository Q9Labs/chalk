## The ubiquitous language decision

**Vision (Hasan's framing).** Chalk is **not** a video-conferencing or meetings
product. It is a **real-time collaboration and communication layer** for many use
cases — video conferences, classrooms, embedded collaboration surfaces inside
other software. The core primitive is **joining a shared place** and
communicating visually, audibly, textually, plus screen share and future
whiteboard. **Agents are first-class**: proactive assistants and representatives
participate as peers, not bolted-on bots. Naming must reflect that breadth, not
the meetings past.

Positioning vs Miro: layer vs destination; communication-first vs canvas-first;
agents as participants vs AI-as-tool; Chalk's persistent artifacts are what
_happened_ (Episodes → recordings, transcripts), not just what was made. Real
head-to-head competitors are LiveKit/Daily/100ms; the differentiators are turnkey
experiences, first-class agents, and coherent language.

### Method

- Two distinct diseases: **language drift** (one concept, many names) needs
  central taste decisions; **bad names** (lying or mechanical names) is
  per-surface hygiene, delegable once the vocabulary is fixed.
- Chalk has **one core bounded context** spanning DB → API → sync wire → SDK →
  UI → docs → marketing → agents. Vendored terms (WebRTC "track", CallKit,
  Cloudflare SFU) stay foreign, with translation tables at adapter seams.
- **Naming grammar:** every name = _domain root_ × _layer shape_ —
  `EpisodeSnapshot`, `EpisodeEndedEvent`, `episode.not_found`, `/spaces/{id}`,
  plural-snake tables, UI shape suffixes Panel/Dialog/Screen/Picker/Indicator.
- **Incumbents must earn their seat.** Tests per candidate: fit-to-vision,
  collision (especially within Chalk's own stack), verb naturalness, artifact
  phrasing, register, industry legibility. **Majority usage in the codebase does
  not decide** — the census measures the past; naming serves the direction.
- **Docs are pointers, never sources of truth.** A doc is _normative_ only if
  something enforces it (CI, codegen); otherwise it is a dated descriptive
  snapshot.
- No users yet → **outright renames everywhere**, no compat aliases, no versioned
  seams.

### Depth, versions, prefixes

- **§8 Depth of rename: all the way down, no mercy.** Same canonical roots reach
  wire frames, DB tables and columns, env vars, span names, infra stack names.
  Only the vendored-term exception stands.
- **Legacy protocol versions: delete entirely.** The Elixir sync service still
  shipped the whole legacy V1 architecture alongside V3, disabled in production —
  pure clutter. **Renumber: current v3 becomes v1** ("we will go from V1 to V3,
  but it doesn't make sense to keep calling it V3"). `state_schema_version` and
  `chalk-sync-state-v3` reset to **1** with no exemption.
- **§9 `Chalk` prefix in symbols: nowhere.** The package provides the namespace;
  pragmatic exceptions only for Go/Elixir internals with real collisions.
  `<Chalk />` is a full name, not a prefix.
- **§10 Grammar:** closed command-verb set, past-tense `<Subject><Verb>Event`,
  `<Noun>Snapshot`, UI shape suffixes. Error codes are `noun.condition` with
  **underscores** in the condition: `episode.not_found`, `space.access_denied`.

### Space durability decisions

The schema audit found the durable shell existed but was empty: all policy lived
per-`room_sessions`, chat streams and whiteboard scenes were keyed per session and
died with it, memberships were tenant-level only.

- **D1 Config home:** Roles/Capabilities/admission are defined on the **Space**;
  each Episode snapshots them immutably at start; edits take effect next Episode.
- **D2 Membership:** **Member un-parked** — durable User/Agent assignment to a
  Space with a Role. Guests stay Episode-scoped.
- **D3 Content:** **whiteboard AND chat are Space-scoped** and survive between
  Episodes (Hasan went further than the recommendation). Clearing is an explicit
  choice, never automatic. Space chat stream and whiteboard scene are the
  canonical single copies; Episodes write _into_ them while live and reference
  ranges afterward — Space content is never derived by merging per-episode copies.
- **D4 Episode start:** **emergent semantics with explicit start as an option.**
  Join always works: if no Episode is live and the joiner holds the start
  capability, joining starts one. An explicit `start episode` API remains as a
  ceremony/warm-up hook, never a prerequisite. Invite links target the durable
  Space slug. Invariant: **no one who is allowed in is ever turned away because
  nobody ran a create call.** Derived law: **at most one live Episode per Space**
  — otherwise "join the Space" is ambiguous.
- **D5 Presence without Episode: no.** A dormant Space is readable data; you
  become visible only by joining.
- **End policy:** mechanism from the platform, strictness from the customer.
  Three ends — explicit `end_episode` (capability-gated), natural (last leave plus
  a configurable linger window so blips and rejoins continue the same Episode),
  and deadline (Space-config default, capability-gated live extensions, hard
  tenant ceiling).

**Trunk sentence v2:** _Space = identity + config + members + persistent content;
Episode = an immutable-policy run that emerges on join and leaves artifacts._

### Identity

**Chalk never owns end-user identity** — the embedding app is the identity
authority. What a Member gets over a guest: standing access (the link just
works), a durable Role across Episodes, roster presence while dormant, continuous
identity in history ("attended all 12 classes"), and addressability. A guest gets
exactly one thing: admittance to the current Episode with a role that expires with
it. Two integration depths: ephemeral guest grant, or registered identity keyed
by the customer's external id (Stripe-customer pattern — `external_id` is a
unique reference per tenant, **never** the primary key; Chalk mints its own ids).

Guest→Member promotion paths: backend API call; in-UI promotion by a holder of
`manage_members` (requires resolving the guest to a registered identity via a
handshake with the customer's identity system); self-serve request plus owner
approval. Auto-enroll deliberately not proposed.

### Boundary findings

The god-object survey found problems Hasan agreed were valid:

- **`ChalkSession` split — LOCKED ("Without a question, option A").** ~6 fused
  concerns (connection/access lifecycle, media session, sync replica,
  room-control facade, chat/reaction state machine, snapshot store +
  diagnostics) split into a narrow connection coordinator plus feature
  controllers composed into one UI-facing store. **Name the pieces, not the
  fusion.**
- **The five "session" concepts get true names**: Go `sessionlifecycle` (→
  Episode), broker `MeetingSession` (edge lease), RN `ClientSession` (pre-join
  credential client), Elixir `Live.Session` (media/presence process), Elixir
  `Sessions.Coordinator` (socket delivery). **One word was carrying five
  abstractions; this coupling is the core disease.**
- **Media-plane contract ownership was wrong** — media's own interface lived in
  `sync/v3-types.ts`. Media gets a neutral contract of its own.
- **UI primitive double-ownership**: the React SDK's local duplicate primitives
  go away in favour of `packages/ui`.
- **Forwarding disease is layered**: sync client (~22-method flat mirror) →
  `ChalkSession` one-line forwards → React and RN hooks each hand-mirroring the
  entire action surface. **One command currently means four synchronized edits.**

**Method consequence:** rename waves and boundary redraws are the _same_ waves —
never touch the system twice.

### Parked, deliberately

- **Pulse** (Space-level ambient-activity aggregate) — a consideration only.
- **"Pass the chalk"** — future floor-control feature name.
- **Breakout/station** — if it ever exists it is a product-layer arrangement of
  multiple _Spaces_, never multiple Episodes in one Space.
- **Agent integration standards** — beyond the native path, possibly MCP, A2A,
  ACP. A real gap was identified: **none of the candidate standards may support
  video and audio** — they are text/JSON-RPC-shaped. The recorded read: the
  native server-side SDK _is_ the standard for the four requirements (speak/hear
  over AV, share results into the Space, send chat, write on the whiteboard) —
  an agent is just a Participant with credentials publishing WebRTC tracks. MCP
  remains a complementary text-layer bridge for agents that can't hold a media
  connection. Chalk-hosted vs externally-hosted is a deployment option, not a
  protocol difference.

### Later addition (2026-08-11)

Two forward-looking platform nouns ratified: **Spinoff** (a new Space derived
from a live or ending Episode, seeded with invited Participants — extends the
broadcast register; rejected breakout/huddle/branch) and **Buzz** (a real-time
summons that rings a Member's devices and deep-links them into a Space; rejected
cue, ring/call, tap, hail, page, knock, chime, beckon). **Aside** is deliberately
reserved, unused, for a possible in-Episode private lane.

## The language ratchet

A private `tools/language-ratchet` workspace package enforcing case-insensitive
word-boundary counts for `meeting`, `conference`, `videoconference`, `room`,
`session`, `attendee`, the `waitingroom` forms, and later `lobby` — **tracked per
surface, allowed only to decrease** through an explicit baseline update. Wired
unconditionally into the root smart gate.

Baselines started large (`session` ~5.5k in `apps/api` alone). Noisy terms
(call/host/peer/bot/ai) were deliberately excluded from v1. The ratchet **fails
closed on improvements too**, so any reduction must be accompanied by a staged
baseline update — a friction point hit repeatedly during the waves.

## The waves

Execution order: **contract/schema first** (codegen propagates), then client SDK,
React/RN, apps, infra, observability, marketing, **DB last**.

**Wave 0 — version plumbing.** Legacy sync deletion plus the v3→v1 renumber.
Explicitly _not_ vocabulary work.

**Wave 1 — contract/schema.** Ratified from
`space-episode-schema-design-2026-08-03.md`, walked through live before launch.

**Wave 2 — client SDK.** The largest and most contested. Public Promise
`SpaceClient` plus an Effect entry, internal `Connection`, five controllers, one
stable-slice store, complete access-refresh (R1), `AccessGrant` opacity, neutral
media plane, all `@q9labsai/*` packages at 4.0.0.

The first handoff was **rejected by independent audit as a direct prompt
violation**: `Connection` was still a 1,526-line feature-fused class, the Effect
entry wrapped Promise-native lifecycle, **device selection was cosmetic**,
`declineRequest` wasn't Promise-based, and public `AccessGrant` parsers weakened
opacity. Staging was withheld.

The correction went through several honest stages, each recorded with its
remaining caveat rather than declared done:

1. `Connection` split into a 297-line lifecycle coordinator plus media, chat,
   participants, reactions, and whiteboard controllers.
2. Context services and scoped Layers added — _but_ the underlying
   implementations were still Promise-native beneath the Layer façade, so the
   Effect wrappers were adapters, not programs.
3. The legacy access manager and stateful Promise `Connection` replaced by a
   native access Layer and a Queue/Deferred/Scope lifecycle actor.
4. Controllers converted to native Effect services; the temporary Promise bridge
   removed.

Lifecycle correctness work along the way: repeated stale media-failure signals
now coalesce to one recovery (port callbacks carry their source and current
snapshot); a synchronous Sync recreation failure backs off without stopping the
old Sync twice; and **Sync recovery had been rebinding both ports on the same
active scope, accumulating duplicate finalizers and media subscriptions** —
cleanup is now tracked per port.

Terra's review found four more concrete blockers: RN media recovery lost
replacement intent at the closed public access context, **chat attachment 401s
bypassed access refresh**, RN adapter and component teardown leaked the canonical
runtime, and the Effect factory's child scope wasn't parent-owned. A closure audit
then found a fifth — a normal leave/rejoin leak.

A separate **Wave 2 closure branch** was opened after an audit proved the
numbered wave had left banned internal vocabulary with no later owner: a 24-file
`src/session` namespace, dead `ConferencePhase`/`prejoin` state, whiteboard
participant-session identifiers. Internals moved to `src/access` and
`src/connection`; `src/session` no longer exists. The V1 client projection stopped
synthesizing `hostExitPolicy`, `hostParticipantId`, and built-in host/cohost roles
absent from the canonical schema.

Ratchet reductions locked at the end: client `room` −214 / `session` −121; React
`conference` −17, `room` −20, `session` −190; RN `conference` −10, `room` −39,
`session` −151.

**Wave 3/4 — React/RN and app adoption.** The ratified surface: `<Chalk />`,
`<Entrance />`, a closed nine-hook set, theme-token enforcement, legacy-surface
deaths, no compatibility aliases. A cross-platform audit rejected the first
handoff with seven P1 and six P2 findings (blank display names, unstable owned
client lifetimes, inert native theme overrides, missing web end-Episode control,
package-imposed container sizing, and more).

Both apps use app-owned identity arrival before `<Chalk entrance={false}>`
because the Episode broker requires a display name before issuing the first
opaque `AccessGrant` — preserving the ratified `getAccess({ space, reason })`
signature without placeholders.

Fourteen unreachable internal React barrels and components were deleted, along
with the now-dead `react-markdown` dependency.

**Wave 5 — infrastructure.** `infrastructure/episode-broker` and

**Wave 6 — observability.** A full hosted **cutover inventory** was written

## Live Episode Debugger

Internal developer tooling covering all Episode behavior — chat, reactions,
screen sharing, moderation, media, Sync, lifecycle — with the historical trace
linking post-Episode cleanup and artifact work.

The design's centre: **one stable umbrella Episode Diagnostic reference** is the
primary agent input and stays current through the linked epilogue; a selected
issue adds a _focus_ reference without creating a separate data island. Plus a
redacted, versioned "Copy all" snapshot for agents without resolver access and a
JSON download for traces too large for the clipboard. **Both outputs retain
omission counts, telemetry gaps, and their capture cursor so they never imply
completeness they did not capture.**

Accepted scope: localhost plus hosted development and staging, seven-day
retention, 8-hour / 100-Participant / ~1M-Event capacity target. Tightened by
critique around an idempotent after-commit observer, a closed v1 action set,
immutable post-end branch rules, purpose-specific append credentials,
commit-ordered batch cursors, replayable projections, and a shared AgentBrief/v1.

Security work during Wave 8 integration: stored provider HMACs are redacted at
every operator event boundary; hosted operator JWTs require a canonical
`tenant_ids` claim bounded to 128 entries; deep projection validation rejects
unknown nested fields, raw Participant identity values, and token-like
extensions; participant labels are the anonymous `Participant N` shape; hosted
diagnostics require deployment-owned allowlisted hosts and **reject
private/link-local/loopback DNS results** with redirects disabled; the capacity
harness defaults to dry-run and needs separate `allow-remote` and
`allow-production` overrides for non-loopback mutation.

A route-registration bug found later: the existing focused test passed **while
mocking away the generated route tree**. A real-tree regression test failed
against the unchanged router, and route-parent lookup was fixed to use `_app`
route object identity.

## Appearance system

Dark-mode ideation produced eight directions; Hasan rejected one as a complete
direction and identified a **composable model**: palette defines colors, texture
and material treatment is an independent optional layer that mixes with any
palette. Refined further to separate ambient lighting from texture so grain,
slate, translucency, and bloom don't become inseparable from color tokens.

Every accepted dark palette was then translated into a deliberate light
counterpart preserving temperature, accent relationships, mood, and contrast
philosophy **without literal inversion**. Final system: **15 palettes** (Chalk
Light, seven light counterparts, seven dark) × **3 textures** (Clean, Paper
Grain, Slate), with public React theme metadata, live switching in Settings,
controlled appearance props, dark-logo support, theme-aware whiteboard behavior,
and palette propagation into portalled dialogs and toasts.

A prior audit had established the honest starting state: the design system and
web surfaces were **intentionally light-only**, while dark variables and
detection utilities lingered in shared UI, the Settings dialog exposed a
**non-functional** dark/system choice, and React Native still used a dark-only
legacy palette.

## One-command local development

`pnpm dev` brings up the whole stack with production parity: Postgres-backed
Sync, API-issued JWTs, a generated local mutual-TLS provider bridge, the real
local Worker and Durable Object broker, **real Cloudflare SFU media**, linked
observability, supervised cleanup, and a two-client media proof.

The live proof passed real Cloudflare audio/video with rising RTP counters in
both directions, a committed host stop-camera action, and one journey correlated
through the Grafana Postgres ledger, Tempo, and Loki. Hot reload restarts
API/Sync/broker/web without restarting the client SDK watcher. `--fresh` archived
the old stable room, revoked its key, retired the undeletable tenant, and created
one new fixture **without wiping either Postgres database**.

A provider contract correction: startup creates and verifies a no-track
connection, retains no connection ID, and relies on provider expiry — **Cloudflare
exposes track close but no connection close.**

The aggregate review found **nine real edge-case defects**: mobile could fall back
to the production broker; custom web ports were ignored; startup signals could
orphan services; external stop trusted a reused PID; reset read the wrong
checkout's manifest and never prompted; reload failures kept stale state; and the
file watcher lost edits inside its debounce window. A re-review found three more,
including that a later unrelated reload could clear a metadata-free required
failure while stopped dependants stayed down.

## Production release (2026-08-08)

`master` was 93 commits ahead, spanning 1,948 files.

**The hard blocker:** production PostgreSQL was populated at Goose
`20260713130000`, so the fresh 20260803 baseline was **a hard no-go**. An
additive Room/Session → Space/Episode **migration bridge** was built instead:
historical Goose chain restored, fail-closed production data preflights, durable
Sync/provider history preserved, downgrade explicitly irreversible.

Review found three real migration authority defects before push: the bridge
**copied an invalid legacy Sync digest**, **forced restricted admission to
open**, and **merged cohost powers into the ordinary Participant role**. The
bridge now requires durable Sessions to be ended, rebuilds an exact Episode
snapshot and digest, maps approval → knock and closed → members-only, and keeps
cohost and participant bundles distinct. A re-review found five more: the bridge
now rewrites only schema-owned Sync payloads, preserves opaque JSON, and
recomputes translated Event wire sizes and replay counters.

Also landed: an explicit **recording capability flag** (managed production
disables recording and transcription while retaining stable API paths returning
bounded `503 service_unavailable`), durable status ingestion with an anonymous
redacted public status projection, and a guarded npm operator flow whose default
dry-run builds, packs, and validates eight public packages **without publishing**.

Schema snapshot reached **zero semantic drift** from the full migration chain: 82
tables, 1,124 columns, 712 constraints, 262 indexes.

Sync release-topology proof found three defects — a fixture missing the
`raiseHand` capability, **Whiteboard welcome frames leaking platform
capabilities**, and **Whiteboard catch-up querying by Space ID where the durable
receipt key requires Episode ID**. The complete profile then passed: 400 server
tests, breaker and replay, multi-node convergence, cross-node Whiteboard fan-out,
unclean node loss, PostgreSQL failover, soak and load, Node restart, and real
Chromium.

Four CI repair pushes followed the release commit, each a real clean-checkout
problem: test-presence rejecting lowercase React test filenames; React mapping the
Client package to source but **not the Client's diagnostics-contract dependency**;
Vitest and Expo Metro resolution boundaries hidden by the full build order; and a
loaded Linux runner exceeding a five-second budget while cold-loading one test,
**contaminating the next sequential mock**.

## Post-release production repairs (2026-08-09)

A chain of production-shaped defects, each fixed with an additive, fail-closed,
irreversible-Down migration proved against isolated PostgreSQL:

- **API Episode snapshot contract:** the API projection carried `config_snapshot`
  and omitted Sync v1 `deadline_at_ms`, `deadline_generation`, and
  `role_capabilities`, so `Reducer.from_snapshot/2` rejected revision zero. Fixed
