# 2026-W31 (2026-07-27 – 2026-08-02)

Condensed from 29 session logs. Originals removed on
`chore/docs-scratch-cleanup`; full text remains in git history.

Three big strands: **room actions** (durable chat, reactions, directed requests,
whiteboard) shipped end to end; **React Native was rebuilt onto the canonical
architecture** and chased through eleven Android release builds; and a **shared
Sync reliability harness** replaced ad-hoc proofs.

## Room actions — the whole room, finally

Starting point: the turnkey web room bound only join, leave, microphone, camera,
screen share, hand raise, roster, and a basic participant drawer. Sync v3 already
supported recording, request-unmute, request-start-camera, and host moderation
below the UI. Live transcription was explicitly held out — its consent, privacy,
provider, and retention contract is not a normal room action.

**Transport shape was decided, reversed, then finalized.** An initial `collab-v1`
side-channel was rejected: chat and reactions belong on **Sync v3** via a strict
`room_actions_v1` extension (later `_v2`), preserving legacy hello/welcome shapes,
adding an alternate extended handshake with chat cursor and room-action policy,
sending new frames only to clients that negotiate them, and **keeping chat out of
the control event log and digest**. Only the whiteboard gets a separate socket
(`whiteboard-v1` at `/v1/whiteboard`).

Product decisions closed in order: durable room-wide text chat; all client
surfaces for reactions, chat, directed requests, and moderation with native
mobile whiteboard deferred; one shared **seven-day post-Session retention**; and
a full Excalidraw image lifecycle with participant-authenticated
initiate/upload/finalize/download, provider-side verification, quotas, protected
downloads, expiry, and orphan cleanup.

**Bugs found by running it, not by reading it:**

- `whiteboard-v1` subscriptions crashed because the application **did not
  supervise the default `:pg` process** — the client sent `hello` repeatedly and
  closed before `welcome`.
- The participant-media middleware **intercepted whiteboard file routes with HTTP
  503** — a real router bug.
- A cross-replica chat delivery gap: canonical Session now follows durable chat
  heads with bounded newer-page catch-up, loads the latest initial page,
  preserves older history, and **does not count initial history as unread**.
- Sync token audience was an invalid local alias instead of the protocol-required
  `chalk-sync`.
- Review found six more: invalid v1 projection for attachment-only messages,
  attachment cleanup/send fencing, unbounded welcome receipts, terminalized
  transient R2 inspection failures, dropped recovery-time receipt fanout, and a
  React Native read-through adapter mismatch.

**Attachments took real credential work.** The available Cloudflare management
token couldn't inspect bucket CORS (`403`, code `10000`), and the existing S3 key
returned `401` against a new isolated bucket because it was scoped to the shared
one. With approval, a 24-hour token restricted to
`chalk-room-dev-20260730-101500` was created, stored at mode `0600` outside the
repo, verified with an exact-byte PUT/HEAD/GET round trip, and the proof object
deleted. **No shared or production Cloudflare state was changed.**

The live proof: two browsers in one room, a chat message read-receipted
(`Read by: Ada attachment`), and a third participant using the **public
TypeScript SDK** to reserve a chat upload, PUT 42 bytes to the scoped bucket,
finalize, and send through `room_actions_v2` — both rooms rendered it, Ada opened
the protected download, and `cmp` proved byte equality.

Attachment finalization uses **exclusive leases with fence tokens and expiry
reclamation**; cleanup excludes live finalization; initiate/finalize/download emit
bounded telemetry with no raw errors or attachment identifiers.

## A whiteboard limit worth knowing

`whiteboard-v1` accepts **at most 128 elements per update frame and 256 KiB per
frame**; snapshots are paged and the durable scene limit is 10,000 elements. The
collaboration engine sends changed elements as one delta and schedules an
unchunked full-scene sync after a successful update.

Reproduced with a 129-element `submit_update`: the generated codec rejects it.
**The local Excalidraw canvas and meeting media keep working, but the rejected
batch never reaches remote participants** — so a large paste, import, bulk
transform, bulk delete, or payload-heavy change can silently leave collaborators
divergent. The React meeting adapter supplies no `onSubmissionError`, so there is
no dedicated user-visible board error.

This drove **bounded atomic multipart updates** in the embedded-whiteboard work:
operations partition by both element count and encoded bytes, retain one durable
operation ID across retries, commit only after complete server assembly, assemble
before client exposure, and fall back to snapshot recovery when a cross-node
replay can't fit the ordinary socket queue.

## Native whiteboard: decision, then a real device

Three strategies were spec'd in review order — embed Excalidraw, build a Chalk
engine, port Excalidraw to Swift/Kotlin — with a structural finding recorded:
**the order is valid for review but cannot be a blind implementation sequence.**
After an embedded-renderer failure, the next path depends on whether lossless
Excalidraw compatibility is still required. Option 2's limitation was made
explicit: it cannot edit existing Excalidraw documents after the embedded editor
fails; the fallback is a gated read-only viewer, owner-authorized _Create Chalk
copy_, or web-only access.

Recommendation: a **self-contained Excalidraw bundle in thin native SDK views**,
with native ink capture only if real-device verification exposes a pen gap.

Option 1 was then built and taken to a physical Xiaomi Apollo, where **three
distinct bridge defects only appeared on device**:

1. Excalidraw renders the stroke, then `toWireElement` throws _"element is not
   JSON serializable"_ — live elements contain optional properties whose values
   are `undefined`. Wire normalization now omits undefined object properties
   recursively while still rejecting unsupported arrays, functions, non-finite
   numbers, cycles, and excessive nesting.
2. Callback identity changes recreated the native controller and rejected the
   initialized renderer as not ready. Stabilized through refs.
3. Excalidraw's runtime pointer object adds an undeclared `tool` field that the
   strict cursor decoder rejected — traced via the Android WebView debugging
   protocol.

Final proof: two freehand strokes committed with no UI, bridge, React Native,
Chromium, or fatal logcat error, and both strokes survived backgrounding and
resume. The renderer artifact is deterministic — 244 files, SHA-256 matching the
generated source asset exactly.

Native meeting collaboration stayed **intentionally unavailable** without an
injected canonical `sessionStore`; the packaged playground proves only the local
renderer and was never presented as live collaboration.

A clean-checkout dependency failure surfaced here too: the broad
`brace-expansion` override supplied the v5 named-export API to `minimatch` 3 and
5, which call the older CommonJS function API during React Native codegen
(`TypeError: expand is not a function`, reproducible on Node 20, 24, and 26).
Resolved with a properly audited policy — legacy minimatch consumers get narrowly
scoped compatibility patches, all majors resolve fixed `brace-expansion@5.0.8`,
plus PostCSS 8.5.25, tar 7.5.22, cel-go 0.29.0, Mint 1.9.3, and Bandit pinned to
the upstream fix commit because the declared fixed Hex release **is not
published**.

## React Native: the parallel runtime is gone

A read-only audit found the honest state: the RN provider still constructed its
own RealtimeKit-backed runtime, the canonical `ChalkSessionStore` was optional,
the production app supplied none, and **existing app tests asserted feature flags
rather than usable behavior**. Native admission exchanged for one legacy access
token while the v2 client requires structured participant access with separate
sync and media credentials.

An earlier session had already established _why_ the default provider couldn't
bridge this honestly: `ChalkNativeProvider` receives only a bearer-token callback
and optional room/display values, while canonical Session requires a renewable
`ParticipantAccess` bundle (tenant, room, Session, participant generation, Sync
JWT, Cloudflare SFU JWT, connection ID, STUN server). The only refresh route
requires the full participant subject and an existing media token and admits only
`cloudflare_sfu`, while the native provider selected the incompatible `cf_rtk`
adapter. Rather than fake it, the explicit `sessionStore` seam and
capability-disabled fallback were kept.

Also found: install-time patches modifying RealtimeKit/WebRTC dependencies,
generic entry points statically including all platform implementations, near-
identical Android/iOS component variants, and **unused headquarters/background-
dictation code with user-facing microphone permission language unrelated to the
meeting product**. The clean production export failed because `@q9labsai/facehash`
had no built `dist/index.native.js` — the checked-in build path was not
clean-checkout reproducible.

The convergence replaced the parallel runtime with canonical `ChalkSession`,
SyncEngine v3, Cloudflare WebRTC, durable pending targets, shared native meeting
UI, protected chat files, whiteboard, moderation, admission, roles, reactions,
hand raising, host transfer, screen sharing, diagnostics, and journey telemetry —
and **deleted** the legacy RealtimeKit runtime, fake recording/transcript/device
APIs, API-key storage, dictation/headquarters code, the Expo dev client, and the
unused native multitasking bridge. Generic native client-session,
participant-access, and cleanup broker routes were added with opaque
capabilities and resumable client sessions.

Mobile release policy tightened: host creation is local/development-only until a
production participant-access broker exists, production builds **strip any
`EXPO_PUBLIC_CHALK_API_KEY`**, and the release contract no longer asks CI to embed
a host secret.

## The mobile join saga (builds 19 → 28)

Each fix exposed the next layer:

| Build         | Symptom                                                                   | Root cause                                                                                                                                                |
| ------------- | ------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1.0.1 (19)    | browser-only origin rejection                                             | native broker routes existed only locally; production Worker not deployed                                                                                 |
| 1.0.2 (20)    | join fails at credential write                                            | the colon in `chalk_mobile_client_session_v2:` — **Expo SecureStore rejects colons**                                                                      |
| 1.0.2 (20)    | `Join failed and durable cleanup could not be confirmed`                  | client replaced the startup cause when pre-live Leave timed out                                                                                           |
| 1.0.3 (21)    | RN closes its own successful connection                                   | snapshot verification used **Web Crypto**, unavailable on RN — replaced with audited `@noble/hashes`                                                      |
| 1.0.3 (21)    | `endSession` not confirmed                                                | v3 client waited for a control revision that **departing clients intentionally never observe**                                                            |
| 2.0.0 (22–23) | `Sync transport could not establish a connection` on a **physical phone** | Android's RN WebSocket client and Chalk's shared startup deadline **both expire at 10 s**, so Chalk aborts before the transport's reconnect delay can run |
| 2.0.0 (23–27) | End for All / Leave still unconfirmed                                     | Sync sent the terminal control event **and the WebSocket close in one transport result** — React Native drops that final text frame                       |

The last one is the most interesting: Sync now **retains the terminal event, sends
it without closing, and closes only after an exact client delivery
acknowledgement** of the terminal revision and state digest, with a bounded
five-second timeout. Terminal lifecycle operations also settle from their
committed ACK, while all nonterminal commands keep ACK-plus-control-head proof.

Build 28 joined a live production meeting on physical device `M2007J3SY`; End for
All still returned `endSession was not confirmed` **because the verified Sync
server change had not been deployed** — stated plainly rather than glossed.

A direct production Sync trace confirmed the protocol side independently: Session
end returns `external_operation_pending`, publishes `session_ended`, and closes
without a final command acknowledgement. Treating matching terminal control events
as durable completion evidence let a fresh production Session settle End for All
as `satisfied` in **449 ms** with zero pending commands.

The production `chalk-meeting-broker` Worker was deployed with explicit approval
(version `24795e6e`, 100% traffic) and verified: health `ok`, synthetic no-Origin
native flow returning 201/201/204, and an untrusted browser Origin still rejected
with 403.

## Sync reliability harness

An analysis first established what the tests actually earn: 95 Sync test files,
450 declarations, but **the root smart gate always sets
`CHALK_SYNC_GATE_MODE=basic` — including scheduled `--full` CI — so CI stops
after dependency, format, and compilation and never runs Credo or ExUnit.**
Recent test/code alignment was visible in history, but protection against future
drift was weak.

Whiteboard coverage was materially narrower than v3: its three socket tests call
the handler directly rather than opening a real WebSocket, its PostgreSQL
repository has one broad integration test, and it had **no breaker, restart proof,
multi-node proof, partition/failover campaign, or browser end-to-end proof**.

The replacement is one shared harness with three orchestrator-selected profiles —
PR correctness, nightly topology, release-candidate soak/load — with fail-closed
enforcement, sealed per-commit manifests, and exact reproducers. Sync PRs now run
the full PostgreSQL-backed **zero-skip** suite, the v3 breaker, TypeScript
Sync/whiteboard tests, and whiteboard package tests.

**The real multi-node profile immediately found two production defects:**

1. Non-distributed OS nodes shared `nonode@nohost` as their whiteboard fanout
   source identity, **suppressing valid cursor events** across separate nodes.
2. PostgreSQL notification listeners **did not reconnect after primary loss**.

Verified: primary termination and standby promotion, client partition and
healing, unclean Sync process loss, exact v3 recovery, cross-node whiteboard
durable and transient fanout, Node restart, and real Chromium recovery.

Final five-minute soak, 24 clients across three real Sync nodes: **34,104
committed commands, 1,344 bounded delivery recoveries, exact final revisions for
every client, 113.67 commands/s, 20 ms p95, 35 ms p99, 56 ms max.** Extending
load from a burst to five minutes surfaced the expected 1012 recovery and
ambiguous-command paths, so the harness now reconnects, verifies the authoritative
revision, and resends idempotently within a bounded retry budget.

CI-only failures found on first dispatch: the PostgreSQL 18 primary lacked an
explicit replication `pg_hba.conf` rule; root `pnpm exec` couldn't resolve the
client-owned Playwright binary; a packed-browser fixture omitted the now-required
empty `attachments` array; and the zero-skip wrapper assumed `rg` exists on GitHub
runners (now portable `grep -E`).

## V4 ubiquitous language (Phases 1–6)

A six-phase rename and restructure on `v4/ubiquitous-language`, with
`sdks/ubiquitous-language.md` as the naming authority.

- **Phase 1–2:** React/RN public vocabulary alignment. RN broker vocabulary
  separated from the active session: `createChalkSession` for the active factory,
  `createClientSession`/`ClientSession`/`ClientSessionCredential` for the broker.
  RN join settings became `PreJoinSettings` with `microphoneEnabled` /
  `cameraEnabled`.
- **Phase 3:** RN meeting-room controller split into capabilities, media, panels,
  chat, participants, interactions, and diagnostics slices.
- **Phase 4:** Extracted a pure client `ConferencePhase` mapper plus React
  auto-join, conference-duration, and whiteboard-scene hooks; RN
  `VideoConference` derives its legacy visual phase from client phase plus local
  join/leave intent.
- **Phase 5:** Renamed React component families, retired the unused `SplitStage`,
  converted the `/components` barrel to explicit named exports, renamed all
  Android/iOS/macOS split files to the canonical `ConferenceView`/`PreJoinScreen`
  vocabulary.
- **Phase 6:** Rebuilt `ConferenceView` as a prop-driven composition owning the
  paper canvas, bordered 1440px column, responsive 340px Sidebar, Stage selection,
  floating ControlBar, overlay/dialog layers, ToastStack, and AudioOutput. The
  React root now exposes only the turnkey component, provider, public types, and
  canonical session hooks; composable visuals are explicit `/components` exports.

A constraint honoured throughout Phase 6: the Phase 4 client contract **has no
runtime admission-waiting or join-status signal**, so the canonical `waiting`
type was preserved _without rendering an unsubstantiated waiting screen_.

Cross-platform `VideoConference` prop parity was deliberately skipped — it would
require non-mechanical lifecycle and platform work.

An SDK evolution audit pinned the history anchors: V1 ends at `0231c4e`
(snapshotted into public-root `37f7e8f`); the 2026-07-05 reset is `6f78576`
(core), `77e6e2a`/`0d25f53` (React), `34de466`/`777310b` (RN); the React rebuild
starts at `7853ad9` and the RN canonical-session rebuild at `063b5a6`. The July 11
relocation `fc8ef51` contains **267 exact renames**, so it carried reset-era React
UI shells forward rather than restoring them — `SettingsDialog.tsx` is
byte-identical from `0d25f53` to the current tree.

## Design system

Replaced the previous split visual model with **one unified, light-first product
system**. Direction drawn from `workers.io` references: editorial near-white grid,
large black type, shallow outlined controls, monospace operational data,
restrained watercolor color fields. Logo gradients preserved exactly (green
`#C5E5C0`→`#80B879`, yellow `#FCEAB3`→`#D9B641`, blue `#B2E0F0`→`#55AAC9`, pink
`#F8CACA`→`#D67B7B`).

Application layouts were reframed around **meeting ergonomics**: a compact 16:9
prejoin preview and a speaker-view stage with one horizontal filmstrip and one
control dock. Uppercase eyebrow microcopy was removed from product and marketing.

Iterated across three annotated rounds to a light 76px identity header, spotlight
default, four-person filmstrip, flat dock with retained device selectors, compact
mobile grid, light participant/chat panels, redesigned device and participant
menus, realistic screen-share preview, a working Chalk-themed Excalidraw surface,
information/settings modals, and notification alerts. Each round was verified in a
real browser at 1440×1000 and 390×844 with no horizontal overflow, control/tile
overlap, or console warnings.

## Smaller items

- **Whiteboard storage hardening:** missing managed R2 CORS, incomplete runtime
  storage config, browser-forbidden presigned headers in upload instructions, and
  no real-browser transfer proof. Added explicit whiteboard-file capability
  validation enforced at startup _and_ at the router boundary, a custom-endpoint
  local storage path, managed exact-origin R2 CORS, and production validation
  requiring R2 whenever whiteboard files are enabled.
- **Join-path observability:** parent-linked `join_span` events across root join,
  media permission, access, client construction, parallel startup, and Sync-live
  wait, plus `ChalkSession.getJoinTrace()`. Review caught that Sync startup was
  wrongly including the live-readiness wait, and a re-review caught that moving
  the readiness wait after the media `Promise.all` **could remove the Sync
  deadline while media startup was still pending**.
- **Documentation rot audit:** left three Sync guides and the north-star
  unchanged, marked useful stale guides, deleted the superseded Composio spec.
- **Effect `4.0.0-beta.94` → `beta.102`:** the published package omits
  `CHANGELOG.md`, so the audit used the upstream repo at the beta.102 tag. The one
  real migration break was `Schedule.take`, no longer exported —
  `Schedule.upTo({ times: 1 })` preserves the one-retry schedule.
- **Codex/Helium upgrade:** a recorded **unsafe action** — kickstarting
  `com.hasan.codex.headless-runtime` without explicit approval while work could be
  running. The runbook now requires explicit approval before any Codex app-server
  or LaunchAgent lifecycle change, even from a separate terminal.
- **Recurring friction:** `codex review` failed to produce coverage repeatedly
  (27-minute silent runs, `Operation not permitted` app-server init, a 30-minute
  enforced timeout). Sandbox restrictions on linked-worktree Git metadata blocked
  commits entirely during Phase 6, so work was preserved as **temporary recovery
  objects** rather than lost. Heavy verification moved to `agents-macmini`
  throughout, twice requiring disk reclamation (9.3 GiB, then 808 MiB → 22 GiB).
