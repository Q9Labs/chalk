Status — not done. The implementation, generated contracts, focused database proofs, SDK builds, and product tests pass. Two browsers prove durable “Read by Ada” receipts, reaction fan-out, Excalidraw launch, and consent-based host requests. Attachment bytes remain unproved: the isolated R2 bucket passes CORS preflight, then returns 401 Unauthorized on the signed PUT because the available S3 key is restricted to the shared bucket. Final upload, protected download, and attachment-message proof wait on an approved key scoped to the development bucket.

Final behavior

  • Up to five finalized attachments can accompany one durable message.
  • Each participant owns one monotonic read-through sequence per chat stream.
  • Read receipts survive reconnects and fan out across Sync replicas.
  • Files are uploaded directly to R2 with short-lived signed URLs; API servers do not proxy file bytes.
  • Chat data and files are retained for seven days after the Session ends.

Intentional boundaries

  • No recording controls.
  • Ask-to-unmute and ask-to-start-camera remain consent based.
  • Host mute, stop-camera, remove, and role controls are wired in the browser room.
  • Native rooms render attachment metadata and receipts; a native file picker/upload surface is deferred.
  • Native whiteboard remains deferred; browser whiteboard stays on whiteboard-v1.

Public API — type-driven first

The public types force callers to finalize files before sending them, keep read watermarks sequence based, and expose feature availability explicitly through nullable transports and the negotiated room-actions version.

Compatibility rule. room_actions_v2 supports attachments and durable receipts. If negotiation falls back to room_actions_v1, text chat and reactions continue, attachment controls disappear, and markChatRead remains local.
