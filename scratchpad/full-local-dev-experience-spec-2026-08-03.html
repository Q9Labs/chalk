D1 · Core is default; mobile is explicit

Accepted: no catch-all full profile

Core: pnpm dev starts Postgres, Redis, migrations, API, durable Sync, Worker broker, web, SDK watchers, observability, and real Cloudflare media.

Explicit mobile

pnpm dev -- --profile mobile waits for core, then adds Expo and localhost device bridges. No device is a warning; an Expo or bridge failure leaves core supervised as degraded.

Still excluded

Recorder, transcription, files, integrations, email, and OAuth need separate safe local contracts.

D2 · The existing SFU app and 1Password item match

Accepted: fetch at runtime; persist no resolved provider secret

Evidence: the dashboard's local-development app ID and the 1Password item's app_id matched by hash, and the concealed app_secret is present.

Discovery

Find exactly one local Chalk SFU credential item, always use the discovered vault for reads, and cache only private source identifiers.

Injection

Pass app_id and app_secret only to the API child environment. Reject production-marked items and ambiguous matches.

D3 · API and Sync reload automatically

Accepted: automatic, readiness-gated restart

Owned Go or Elixir source and config changes trigger a debounced rebuild and dependent restart. Ready returns only after real health checks pass.

Healthy edit

Stop affected dependants, rebuild, restart in dependency order, and restore ready.

Compile failure

Enter reload-failed with the exact error and log path. Never present the last good binary as the edited code.

D4 · Startup proves the provider; smoke proves the meeting

Accepted: light provider proof at startup; full smoke on demand

Field presence is not enough, but two browsers on every edit cycle would add time and provider use.

Startup

Create and verify one no-track SFU connection through the real API adapter. Cloudflare has no close-connection endpoint, so no identifier is retained and provider expiry cleans the empty connection. Bad or revoked 1Password data blocks ready.

Full smoke

pnpm dev:smoke runs two clients, real tracks, rising counters, one host media action, and a linked journey.

The full smoke is required for release handoff and whenever an agent needs media proof.

D5 · State persists in one fixed local stack

Accepted: persistent state and one machine-wide stack

Persistent state exposes migration and stale-data bugs. Fixed localhost ports keep browser origins and mobile bridges simple.

Normal stop

Volumes and local Durable Object state survive. Disposable meeting and smoke fixtures do not.

Ownership

An atomic per-user machine record names the active checkout and status. Another worktree fails early with the owner and URLs. dev:reset is the only full wipe.
