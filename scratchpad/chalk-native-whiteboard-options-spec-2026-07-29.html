Measure Draft pass threshold
Cold open p95 ≤ 3 seconds for the fixed medium fixture
Warm open p95 ≤ 1.5 seconds for a medium scene

Pan or zoom Under 5% missed display deadlines; no stall above 100 ms
Medium scene 1,000 elements plus 10 images without input regression
Stress recovery 5,000 elements reopen and converge without crash or data loss
Endurance 20 open/close cycles under 1% post-close memory slope; 30-minute final within 15% of baseline

Run at least 30 cold and warm opens per device against a native blank-canvas reference. Include media deltas, fixed image bytes, display-refresh deadlines, WebView or GPU memory, and presented-frame timing.

Option 1 keeps Excalidraw authoritative

Native host owns

Lifecycle, safe areas, keyboard, clipboard, file bytes, share sheet, accessibility shell, and telemetry.

Embedded editor owns

Canvas, tools, selection, text, history, reconciliation, and final Excalidraw serialization.

A separate embedded artifact pins Excalidraw exactly and bundles CSS, fonts, MathJax, icons, hashes, and license notices. Offline install proof records zero non-Chalk requests.

Before the 1,000-element gate, whiteboard-v1 needs an atomic multipart update: validate all parts, commit one revision, then fan out. Partial bulk edits never become visible.

Ship Option 1 only after cross-client proof

Why it leads

One editor gives the strongest compatibility, the smallest permanent burden, and the fastest path to both first-party mobile and thin native SDK views.

Where it can fail

Pen latency, palm rejection, touch layout, keyboard behavior, WebView recovery, accessibility, or memory can still miss the device bar.

Option 1 exit gate

  • One compatibility manifest gates web and mobile features
  • Corpus round-trips between web, iOS, and Android
  • Multipart full sync and bulk edits pass above 128 elements
  • Concurrent edit, clear, reconnect, files, and stale-scene tests converge
  • All device thresholds pass during a live call
  • Bridge fuzz, ordering, size, security, and secret-leak tests pass
  • Renderer failures leave the meeting working
If this gate passes, stop. If it fails, allow one targeted remediation per failure class; the same hard gate failing twice becomes the structural failure report for the next branch.

Option 2 buys product control by changing format

The new engine cannot edit them

Web keeps Excalidraw editing. Mobile gets a read-only embedded viewer only if that narrower path passes; otherwise it opens on web.

An owner may create a new Chalk copy from one frozen source revision. The original never changes.

Legacy Excalidraw documents

Use a focused Chalk editor

The Option 1 failure report chooses a core that removes the measured cause. A new typed transport carries Chalk operations.

New Chalk documents

The first release includes pen, core shapes, text, images, selection, transforms, grouping, ordering, history, pan and zoom, clipboard, export, collaboration, recovery, accessibility, and diagnostics.

Full Excalidraw export is incompatible with a smaller focused engine. If lossless export remains mandatory, skip this option. New offline edits are also out of the first release.

Option 2 must prove an engine and a migration

Why choose it

Chalk controls the document, editor scope, collaboration rules, observability, and future structured tools.

Permanent cost

Chalk owns every editor defect and format change, and it operates two renderers while legacy Excalidraw documents remain.

Option 2 exit gate

  • chalk/1 schemas and reducer agree across runtimes
  • Web and React Native pass the complete first feature set
  • Randomized collaboration and recovery converge
  • Legacy documents follow the accepted read-only, web, and Chalk-copy policy
  • Owner-authorized copy, limits, rollback, and support policy ship first

Option 3 preserves format at the highest cost

Web stays the reference implementation. The ports share generated models, bundled fonts, canonical text shaping, operation traces, geometry vectors, visual expectations, and an upstream-delta report—not native editor code.

This is a reimplementation, not a normal fork. The React browser editor does not compile into Swift or Kotlin.

One upstream upgrade is part of Option 3's proof

Why choose it

Highest ceiling for platform input, accessibility, lifecycle, text systems, and pure-native SDK ergonomics while keeping Excalidraw documents.

Permanent cost

Three editors, two native implementations, platform text and graphics drift, and manual intake of every supported upstream change.

Option 3 exit gate

  • Swift, Kotlin, and web pass one semantic corpus
  • Repeated cross-platform edits preserve fields, text, bindings, order, and deletes
  • Both native editors pass device and accessibility gates
  • Concurrent collaboration and recovery converge
  • Current and previous manifests gate web/mobile release skew
  • One real upstream baseline upgrade completes before release

D1 and D2 set the measured Option 1 bar

D1 · Device thresholds

Premise: “Feels native” cannot decide a release.

A · Absolute + native reference: one clear support bar; may exclude older devices.

B · Premium + floor: broader support; two experience and evidence levels.

C · Relative only: adapts per device; may permit poor absolute behavior.

Recommend/default: A, frozen after Phase 0 variance is known.

D2 · Native pen capture

Premise: pen can fail while the rest of the editor passes.

A · Allow one neutral-stroke overlay proof: better pen ceiling; adds camera and preview handoff tests.

B · Pure embedded only: simpler architecture; any pen miss fails the whole option.

Recommend/default: A. Excalidraw still creates the canonical element.

D3 and D6 define the honest Option 2 fallback

D3 · Format policy

Premise: full Excalidraw behavior turns a focused engine into a port.

A · Dual format: chalk/1 for new work; permanent legacy policy.

B · Full compatibility: one format; highest engine scope.

Recommend/default: A. If B stays mandatory, skip Option 2.

D6 · Existing mobile boards

Premise: the new engine cannot edit the Excalidraw board that triggered it.

A · Read-only + Chalk copy: best mobile continuity; keeps a legacy viewer.

B · Web-only: simplest; mobile users cannot open old boards.

C · Full native edit: activates Option 3 as well.

Recommend/default: A, with honest web-only fallback.

D4 follows the Option 1 failure cause

D4 · Option 2 shared core

Premise: the fallback must remove the measured cause of failure.

A · TypeScript

Web Canvas plus React Native Skia fits current apps and ships faster. Reject it after a JavaScript scheduling or React Native contention failure.

B · Rust or C++

Wider native reach and different runtime behavior. Adds bindings, memory ownership, build, debugging, and release cost.

Recommend/default: A only after a WebView, Excalidraw, or browser-UI failure. Otherwise the failure report chooses B or stops the branch.
