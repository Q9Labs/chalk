# Retained Test Mutation Audit

The 59-file suite should not remain unchanged. The final audit supports 32 `KEEP`, 3 `MERGE`, 22 `REWRITE`, and 2 `DELETE` file verdicts. Two merges remove standalone files, two deletes remove stale files, and the third merge removes duplicated campaign cases while retaining the aggregate campaign boundary. A second case-level pass found about 30 more redundant case or assertion groups inside files whose runtime boundary remains necessary.

This is a read-only audit of commit `a7693edb0c104a247e6f522adc555b92a772d880`. No test or production source was changed. Manual mutants ran serially in isolated temporary checkouts on `agents-macmini` and were restored after each run; Stryker and Gremlins managed their own isolated workers inside those checkouts.

## Evidence standard

Each file was traced to its canonical runner, current production caller, unique failure, overlapping retained proof, and relevant history. A file gets `KEEP` only for a narrowly named contract whose focused baseline passes, reaches a current unique runtime boundary, and kills a causal production mutant. Survivors in other source paths and flaky broader runners are disclosed and excluded from that retention claim. A compile failure, skipped test, missing fixture, generic mutation score, or mutation-tool crash does not count as a kill.

The primary audit outcome per file was 51 `KILLED`, 6 `SURVIVED`, and 2 `INVALID`. No survivor or invalid result used to justify a contract gets `KEEP`. Stryker completed one bounded TypeScript campaign with 91 mutants: 69 killed, 16 survived, 4 timed out, and 2 had no coverage. Its reported 80.22% score counts timeouts as detected, but this audit does not count those timeouts as causal kills. Its Babel generator could not print several current TypeScript ASTs, so those instrumentation failures were marked invalid and replaced with manual causal mutants. Gremlins completed a bounded Go package campaign with 10 killed, 0 lived, 300 not covered, and 73 timed out; the high timeout and uncovered counts are tool limits, so the verdicts use focused causal mutants.

The history pass did not use age as a retention signal. It found concrete stale state only where callers or runners had disappeared: the unused worker-identity wrapper, the deleted cross-runtime Sync fixture, four orphaned migration commands, the dead whiteboard client decoder, no-caller diagnostics helpers, and the clean-install campaign dependency gap. Current glossary and protocol names were checked before assigning the other files a live boundary.

## Reduction and repair order

1. Delete `workeridentity/tls_test.go` and its uncalled wrapper.
2. Delete the unrunnable cross-runtime API test whose Sync entrypoint no longer exists.
3. Merge `request-safety.test.ts` into the account handler proof and delete the helper-only file.
4. Merge `v1-collaboration.test.ts` into `v1-client.test.ts` and delete its duplicate harness.
5. Apply the case-level reductions above, including the 15 clear SDK/Sync deletions and about 15 API/controller assertion-group reductions.
6. Remove orphan/dead inner cases from diagnostics contracts and whiteboard codec, duplicated leaf checks from the Sync campaign, and pure or duplicated deploy-contract cases.
7. Rewrite the six survivor files, the invalid campaign baseline, and the five boundary owners downgraded by the case audit before treating their full intended contracts as protected.
8. Route the four migration proofs and the image patch proof through canonical gates; an executable file with no continuous caller is stale operational evidence.

The audited branch reached 55 files after two file merges and two stale-file deletions, with about 30 additional case or assertion groups removed inside the remaining files. Current `master` then added PostgreSQL and trace-scenario regressions for active-participant lifecycle protection after the audit commit. The ready branch retains those two distinct database and observability boundaries, so its final floor is 57 files. It can fall further only by deleting a current unique runtime boundary or by replacing several unrelated boundaries with a monolithic suite, neither of which is a good reduction.

## Executed result

The implementation changes 50 paths relative to the 59-file audit baseline: 968 insertions and 1,892 deletions. Before rebasing it returned 55 retained test files. The current-master reconciliation keeps the new PostgreSQL lifecycle regression, rewrites its weak trace-scenario test to assert the wait/archive result and action order, and folds three new retention regressions into the existing Sync boundary owner. The rewritten scenario kills a causal mutant that starts with no active Participant; the original event-presence assertions let that defect survive. The exact classifier therefore returns 57 files. The reduction deletes `request-safety.test.ts`, `v1-collaboration.test.ts`, `cross_runtime_integration_test.go`, `workeridentity/tls_test.go`, and the uncalled worker-identity production wrapper. Migration validation now calls all four retained migration proofs, the image patch guard is selected by Smart Gate when its patch or proof changes, and the remaining weak files contain the required adversarial or boundary assertions.
