## Corrections and proof

### Remote-track identity

`sdks/typescript/client/src/media/client.ts` now maps each response track by
`(sessionId, trackName)` and rejects incomplete, duplicate, unexpected, or
wrong-kind responses. The focused client typecheck passed and all 26 focused
Cloudflare SFU tests passed.

Strict rerun `shakedown-2026-08-23T19-27-31-212Z-2el4fz` still failed
microphone, camera, and screen-share assertions. This is useful negative proof:
the correction closes response misbinding, but provider `Track not found`
errors occur before a usable response reaches this code.

### Ambiguous publication revoke

`apps/sync/lib/chalk_sync/live/episode.ex` now maps an ambiguous revoke result
to retryable dependency unavailability. This preserves the operation ID and
lets the existing V1 retry path finish the registry write before the browser
retires its sender. Do not add a second browser-side close; that was removed on
purpose and would create two owners for provider teardown.

The focused Episode regression passed all six tests. Strict runtime rerun
`shakedown-2026-08-23T19-48-18-622Z-zp2487` still produced 871 HTTP 503
responses: Avery 232, Blake 178, Casey 230, and Devon 231. Camera playback and
screen share still failed. Microphone passed in this run, but do not attribute
that to this correction without repetition. The raw run is copied locally.

### Bounded remote-pull retry

The client records failures against the full validated publication cursor and
backs off at 2, 4, 8, and 16 times the healthy poll interval. Success, restart,
or a changed cursor resets the progression. A zero test interval still uses a
one-millisecond base, and stale connection generations cannot carry failure
state into a replacement connection.

The client typecheck passed and all 29 focused Cloudflare SFU tests passed.
Strict run `shakedown-2026-08-23T20-06-02-948Z-n12b9p` reduced 503 responses
from 871 to 90, an 89.7% reduction. Long-lived failures settled near one
request every 16.6 seconds. Microphone, camera, and screen share still failed,
so this is verified pressure control rather than a stale-registry repair. The
raw run is copied locally.

### Native browser file

Both chat panels now use one helper that identifies the browser/raw-file branch
by `arrayBuffer` before considering the SDK byte-input shape. This avoids
mistaking the inherited modern `Blob.bytes()` method for an `ArrayBuffer` field.
The SDK chat controller and effects apply the same rule when extracting bytes,
so a native `File` cannot be mistaken for the SDK's already-materialized byte
input at either boundary. The focused ChatPanel test passes, including a
browser `File` subclass that exposes `bytes()`. Six focused client tests and
the client typecheck also pass.

Strict run `shakedown-2026-08-23T20-13-06-313Z-nl9zrx`, which contained only
the React half, proved that staging succeeds but sending does not: the
attachment stayed visible for the full 15-second completion assertion. The SDK
half was then deployed for strict run
`shakedown-2026-08-23T20-21-39-081Z-yny8xk`. The attachment still remained
visible, but the API recorded `chat_attachment` initiation as succeeded. No
finalize followed, and browser diagnostics contained no non-media HTTP error.
This proves both native-File boundaries execute and moves the unresolved path
to the presigned storage PUT or its browser-facing CORS contract. The isolated
RustFS container was live on 19000 and the launcher had configured the 13070
origin, but that is not enough to claim the storage failure's cause. Capture the
composer error or the PUT request itself before changing product code.

The durable scenario now races attachment clearing against the visible chat
composer alert. The next strict run should fail immediately with the actual
upload error instead of losing it behind a 15-second locator timeout. Syntax,
all 20 pure harness tests, and `git diff --check` pass; runtime proof still
requires restarting the isolated stack.

### Board control state

Both Space skins now forward `whiteboard.isOpen` to their desktop and compact
ControlBars, whose surfaces already map the value to pressed state and active
styling. The combined focused ChatPanel and SpaceView run passed 23 tests, and
the React package typecheck passed. This correction remains local only and has
no strict browser proof.

### Re-entry ownership

Chalk's Space surface already owns the ordinary leave command. `SpacePage` now
omits its public `onLeft` event callback so it cannot attach terminal cleanup or
repeat `leave()` after the SDK reaches left. The same client and prepared access
remain available for `Try again`. Episode end, unmount, and pagehide keep the
full terminal cleanup path. Twelve SpacePage tests, 30 React binding tests, and
both package typechecks pass.

Strict run `shakedown-2026-08-23T20-29-34-442Z-m0teud` falsified this ownership
change as a sufficient repair. Remote leave passed, but `Try again` did not
restore the video grid within 90 seconds. Keep the unit proof as evidence that
the supplied client can rejoin in isolation, but inspect the real app's client,
arrival-access, and route state across leave before accepting or extending this
change. Do not describe re-entry as fixed.

The strongest static lead is now the access contract, not React disposal.
`ConnectionLifecycle.stopPorts()` clears cached access, so retry does request
access again. But `createPreparedPublicSpace.connectionAccess()` refreshes the
same public arrival, while API `RefreshPublicAccess` calls `FindPublic` for the
same Participant generation and `ResumeJoin` for the same provider subject. It
does not create a new arrival or Participant generation after durable Leave.
The next browser probe should capture the public refresh response and the
client join trace. If it confirms this boundary, choose one owner for true
re-entry: mint a fresh public arrival/generation in the app access adapter, or
define an API reactivation contract. More `onLeft` cleanup changes will not
repair that contract.

## Guardrails learned from the evidence

- The large leave heap delta is late Excalidraw development loading, not a
  detached-DOM leak. Do not optimize against that false diagnosis.
- Chat-active pages own almost all live DOM growth, but forced-GC panel close
  released their DOM and Fibers. Measure bounded rendered history before
  claiming a leak.
- The remote M4 is shared and its audio daemon can consume a full core. Use
  browser-process CPU for shape and CPU profiles for attribution; do not treat
  shared host load as a clean regression score.
- A configured 60-second shakedown can take six minutes because strict failure
  assertions wait for their full timeout. A long wall time is not a hung harness.
- Vite requires Git metadata. The remote source has a synthetic empty commit
  only for `git rev-parse`; it is not the product revision.
- Never weaken an assertion to make a run pass. Unsupported, unreachable, and
  failed are distinct outcomes in the harness and report.
