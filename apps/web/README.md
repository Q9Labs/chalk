# Chalk web

This Vite, React 19, and TanStack Router app serves three roles:

- the public marketing shell at `/`;
- a production-capable public-SDK consumer Space at `/space`;
- a compact public-surface preview at `/sdk-preview`.

It is not a complete hosted real-time product. `/new`, `/whiteboard`, and `/status` are blank routes. `/privacy` and `/terms` are public legal pages. Track the remaining gaps in the root [`checklist.md`](../../checklist.md).

Routes live in `src/routes/` and are generated by TanStack Router. Shared product behavior belongs in the SDK packages; this app remains a thin first-party integration and verification surface.

## SDK Space

The `/space` route collects a display name before rendering `<Chalk />`. It creates a same-origin participant credential with `POST /local-chalk/participant-credentials`, keeps the returned `spaceInviteToken` in the URL fragment, and passes the broker's raw `AccessGrant` from `getAccess` without inspecting it. The credential is removed with `POST /local-chalk/participant-credentials/cleanup` after the Participant leaves.

The broker owns credential state and all server credentials. Its browser contract uses these routes:

```text
POST /local-chalk/participant-credentials
POST /local-chalk/access-grants
POST /local-chalk/participant-credentials/cleanup
```

`pnpm --dir apps/web dev` binds Vite to `127.0.0.1:3070` and proxies the broker path to `http://127.0.0.1:8787` by default. Set `CHALK_DEV_BROKER_ORIGIN` or `CHALK_DEV_BROKER_PORT` to use another local broker. The proxy forwards no authorization header.

Browser journey telemetry is opt-in through `VITE_CHALK_TELEMETRY_ENABLED=true`.
The page journey starts before participant credential creation, and the broker's
validated `apiBaseURL` selects the later intake origin. The API intake contract
requires an authenticated user credential or a verified provider bearer; the
browser broker currently exposes neither because its `AccessGrant` is opaque and
its credential is scoped to broker routes. Until Wave 6 supplies an authenticated
intake relay or an explicit bearer provider, the durable queue keeps events
retriable and makes no unauthenticated success claim.

The page journey is shared by broker HTTP calls and app-owned client
diagnostics, but the current public `SpaceClient` options do not accept an
existing `TelemetryJourney` or expose a W3C context hook for the Sync, media,
and provider transports. Those boundaries therefore cannot honestly claim
journey-header propagation from this app. Wave 6 must add that public context
seam, then wire the same context through every SDK transport; this app must not
parse the opaque `AccessGrant` to manufacture bearer headers.
