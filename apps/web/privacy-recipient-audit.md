## Negative findings and classification boundaries

- **Only Google and Apple sign-in** are configured. Mobile has no account/sign-in flow. A returned Google profile-picture URL is stored in the web identity; current dashboard avatar rendering does not add an automatic external picture request.
- **No transactional email sender** (SES, SMTP, SendGrid, Resend, Mailgun, etc.) was found in the app/server runtime. `mailto:` support/privacy links open the user's mail application; this audit cannot identify the separate human inbox provider from application code.
- **No client analytics/ad/error SDK** (PostHog, Segment, Sentry, Google Analytics, etc.) was found. Axiom is server-side operational telemetry, not a claim that Chalk sends nothing diagnostic.
- **No separate TURN provider** is configured in the current media bootstrap. Cloudflare STUN and SFU/negotiated media paths are covered above.
- **CSP is not a web allowlist here**: no web `connect-src`/`script-src` policy was found in the checked source or published response headers. The embedded native whiteboard instead has `default-src 'none'`, `connect-src 'none'`, `frame-src 'none'`, `script-src 'self'`, and local font/script/style assets. `renderer.tsx` sets `EXCALIDRAW_ASSET_PATH="./"`; `build-embedded.mjs` copies Excalidraw fonts and MathJax into the native artifact.
- Literal candidates such as W3C/schema namespaces, documentation/help URLs, React/Expo error-message links, example endpoints and package repository URLs are **not automatic data recipients**. `classic-assets.eascdn.net` occurs in the native bundle's Expo development asset machinery, not the production local-asset path.
- Excalidraw's upstream app/Firebase/AI/collaboration configuration strings occur in dependency bundles. Chalk supplies its own collaboration engine; these strings alone are not evidence that Chalk uses those upstream backends. Library/help links that users open are external navigation, not Chalk's server processors.
- User-selected external content can redirect or load its own subresources. Those depend on the selected content and are governed by its host; they cannot be exhaustively enumerated as a fixed Chalk origin list.
- This is a code/artifact audit, **not verification of deployed secret values, vendor contracts or every production account setting**. No new DPF certification or executed SCC contract is invented for jsDelivr/esm.sh. Their international asset-request processing is described without claiming a verified contractual mechanism. Google/Apple primary privacy/transfer documents support their separate descriptions.
- Problem-report submission is **not** introduced or disclosed by #335; #348 owns that new flow and its exact Discord payload disclosure.
