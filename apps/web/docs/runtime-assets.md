Search scope: `apps/web`, `sdks/typescript/{client,react}`, `packages/{ui,assets,whiteboard}` and the pinned runtime dependencies. Local CSS imports resolve through Vite. No external CSS `@import` or network dynamic import remains in application sources. The web-only `scripts/self-hosted-excalidraw.ts` Vite transform removes Excalidraw's external font retry in both development and production, and fails the build if that pinned code changes. The same transform runs during development dependency prebundling and production bundling. A browser regression forces a local Virgil font to return 404 during SVG export and rejects any external fallback request. Published SDK builds retain their upstream CDN defaults.

`packages/assets/src/index.ts` declares `assets.chalkmeet.com` sound URLs. Those belong to Chalk, are not third parties, and the current React call sound player synthesizes its cues. API/sync endpoints are Chalk services; SFU/TURN addresses and user-supplied chat attachments are service or user content, not font/script/CDN assets. Outgoing GitHub, identity-provider and legal links do not load on page render. The embedded/native renderer copies the complete font directory beside its bundle and has an offline CSP. Its first import sets an absolute document-relative font base before Excalidraw initializes. The package marks that bootstrap as a side effect, and the embedded build removes Excalidraw’s external font fallback. A file-URL browser test loads the built entry, rejects external requests and CSP violations, and requires Excalifont to load from the adjacent font directory.

The build copies static whiteboard assets from pinned installed packages without contacting a CDN. These files stay outside the JavaScript bundle and load only when used. Versioned vendor paths have a one-year immutable cache; editable font stylesheets and their hashed font files revalidate after one day. Each site font's OFL licence ships beside its font files, and the MathJax Apache licence ships with the runtime.

The web app configures local asset paths through `@q9labsai/chalk-whiteboard/assets` in a bootstrap module imported before the SDK. Configuration sets Excalidraw's font base synchronously, before static SDK imports can initialize its font faces. External SDK hosts retain their existing CDN defaults. Self-hosting hosts must call `configureWhiteboardAssets` in a bootstrap module imported before the SDK, with their Excalidraw CSS and MathJax base paths. The existing `excalidrawCssPath` prop overrides the stylesheet; passing it alone cannot initialize fonts before eager SDK imports. The embedded renderer retains its own local font configuration and resolves relative paths against its `file://` document URL. Both Vite configurations copy assets at startup, so a clean checkout works with `pnpm dev` without a prior build. Each vendor URL names the package version and a digest of the copied bytes, from `src/lib/whiteboard-asset-versions.ts`. The copy step checks both against the installed packages and fails when they differ, printing the new digest. A version upgrade or a same-version pnpm patch therefore needs a new immutable URL before it builds, and an existing published tree is reused only under the digest of the bytes installed now. The digest is per package: changing any copied file changes every URL in that package, so its files download again when next requested, and other packages keep their URLs.

Deployments store `chalk-asset-manifest.json` beside the static assets. It lists file paths and pinned digest roots for the current release and the last three deployed release SHAs. Trees shared by releases appear once. `sync:public` generates only the current trees and manifest from the installed packages; no vendor snapshots belong in Git.

Both `scripts/releases/web.py deploy` (the prebuilt archive upload used by Release/Promote) and `pnpm run release:web` run `retain-public-assets.ts` before any Pages upload. It reads the target's live manifest without cache, fetches older trees with at most 16 requests at once, and recomputes each tree's digest before publication. The new static directory contains only the four selected releases' trees, even after a warm build. Repeating the same release SHA does not consume a retention slot. A fifth distinct release removes trees used only by the oldest release.

An unreadable or missing live manifest stops the deploy. To bootstrap the first deployment, or explicitly discard retention during an outage, pass `--without-asset-retention` to either deploy command. The Release workflow exposes the same choice as `without_asset_retention` (default false). This choice can break lazy asset loads in older open clients. Future releases resume retention from the new live manifest. Rollback restores the manifest and assets of the saved Pages deployment together.

At today's pinned sizes, four entirely different generations contain at most 129,529,616 vendor bytes in 1,428 files, plus the rest of the web build and its small manifest. Unchanged trees add no copies. The deploy step also checks the full output against [Pages' conservative 20,000-file and 25 MiB-per-file limits](https://developers.cloudflare.com/pages/platform/limits/) before upload; larger future vendor trees must still fit those limits.
