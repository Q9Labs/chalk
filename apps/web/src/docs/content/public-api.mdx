## The public API is a versioned HTTP contract preview

The checked-in contract is `contract/generated/openapi.json`, version `0.0.0-preview`. This page is an allowlisted public summary of customer operations, not every path in the contract. Use the file as the source of truth for path names, request shapes, response codes, and error codes before shipping an integration.

```http
GET /v1/tenants/{tenant_id}/spaces
GET /v1/tenants/{tenant_id}/spaces/{space_id}/episodes
POST /v1/tenants/{tenant_id}/spaces/{space_id}/episodes/{episode_id}/end
GET /v1/tenants/{tenant_id}/webhook-endpoints/{endpoint_id}/deliveries
```

Customer operations cover Tenant, Space, and Episode records; Participant admission and access; media; recordings and transcripts; webhook endpoints and delivery inspection. Most routes use a Tenant id in the path. List routes expose `page_size` and `cursor`; the webhook delivery list also filters by `state` and `event_type`. Mutating routes that create or change durable state require an `Idempotency-Key` where the contract declares it.

For an embed, set `cors_allowed_origins` with `updateTenant`, then use `createSpace` and `createEpisode` to prepare a live Space. Admit each Participant with `admitEpisodeParticipant` and issue an AccessGrant with `issueAccessGrant`. Keep the Tenant API key on your backend; the frontend gets its AccessGrant through your `getAccess` endpoint. See [Authentication](/docs/authentication) for the credential boundary.

For current Participants across multiple Spaces, use `listSpaceLiveEpisodes` (`GET /v1/tenants/{tenant_id}/live-episodes?space_ids=...`) with 1–30 distinct comma-separated Space IDs and `episodes:read`. Each Space returns `live_episode: null` or an Episode ID, Participant count, and current Participant IDs and display names. Unknown or other-Tenant Space IDs return `404` for the entire batch.

For Home activity across up to 300 Spaces, use `listSpaceActivity` (`GET /v1/tenants/{tenant_id}/space-activity?space_ids=...`) with distinct comma-separated Space IDs and `episodes:read`. Each Space includes whether it is `archived`, its live Episode with the full `participant_count` and the first five Participants of the live roster, its latest Episode (including ended Episodes), and up to five joined Participants from that latest Episode, newest first join first. Unknown or other-Tenant Space IDs return `404` for the entire batch.

Use `getEpisodeAttendance` (`GET /v1/tenants/{tenant_id}/spaces/{space_id}/episodes/{episode_id}/attendance`) with `episodes:read` for live or ended Episode attendance. Each admitted Participant seat appears once, ordered by `first_joined_at`, with its display name, identity kind (`user`, `agent`, or `guest`), nullable external ID, first join, and latest leave. Rejoins keep the first join; this is not a list of presence intervals. `last_left_at` and `left_reason` are null while the seat is present. An ended Episode closes seats that never explicitly left at its end time with `left_reason: "episode_ended"`; explicit departures use `"left"`. Attendance remains available after the Episode event journal is cleaned up.

### Read Episode talk time

Use `getEpisodeTalkTime` (`GET /v1/tenants/{tenant_id}/spaces/{space_id}/episodes/{episode_id}/talk-time`) with `episodes:read` to see who spoke in an ended Episode and for how long. Chalk keeps no voice-activity record, so the measurement comes from the Episode's complete transcripts: every transcript cue is a span in which its speaker was talking. `source` is always `"transcript"`.

`status` says whether a measurement exists, and `talk_time` is set only when it is `"available"`:

- `available`: at least one Recording has a complete transcript.
- `no_transcript`: the Episode has ended and no Recording has a transcript or is getting one. Transcription was not requested, was disabled, or failed.
- `transcript_pending`: a transcript is still being made.
- `live`: the Episode has not ended, so there is nothing to measure yet.

When available, `talk_time` carries `episode_duration_ms`, `total_talk_ms` (the sum of every speaker's talk time, so time two people talk at once counts for both), `overlap_ms` (two or more people talking at once), `silence_ms` (nobody talking), and `recordings`, one entry per Recording with its `recording_id`, its `offset_ms` on the Episode timeline, and whether it was `transcribed`. When only some Recordings have a transcript, only those are measured. Each Recording's cues are placed on the Episode timeline by `offset_ms`: when the Recording's capture became ready, relative to the Episode start; a Recording that starts before the Episode is placed at its start.

`speakers` lists every Participant who attended plus any transcript speaker who matched no attendee, largest `talk_ms` first. A speaker who matched an attendee has that Participant's ID in `participant_id` and `speaker_key` (any other speaker's key starts with `ref:`); any other speaker has a null `participant_id` and keeps the display name from the transcript. `talk_ms` is the union of the speaker's cue spans, so overlapping cues never count twice, and `share` is `talk_ms` over `total_talk_ms`. `intervals` are the speaker's speech runs as `start_ms` and `end_ms` since the Episode started: cues are joined across pauses of up to one second, and `turns` is the number of runs. The response carries at most 5000 runs in total; past that, `intervals_truncated` is true and every `intervals` list is empty. `bucket_talk_ms` is each speaker's talk time in consecutive buckets of `bucket_ms` from the Episode start, and it always covers the whole Episode. Chalk picks the smallest bucket that gives at most 120 buckets.

### Download transcript text

Use `GET /v1/tenants/{tenant_id}/transcripts/{transcript_id}/text` with `transcriptions:read` to download a completed transcript as `text/plain; charset=utf-8`. The attachment filename contains the sanitized Space title and UTC recording date; non-ASCII titles also have an RFC 5987 `filename*`. The dashboard's **Transcript (text)** download uses this route through its authenticated backend. It does not offer a JSON download.

The first line contains the Space title, UTC recording start date, and recording duration (seconds below one minute, otherwise rounded to the nearest minute). A `Languages:` line names the detected languages from the document and finalized transcript metadata when known; requested transcription languages are not treated as detected languages. Speech lines use `[HH:MM:SS] Speaker: text`, with timestamps relative to the recording start. Cues are ordered by start time, preserving artifact order for ties. Consecutive cues from the same Participant identity and generation merge when the gap is at most five seconds, even if their media track changes. The first cue's display-name snapshot labels the merged line; unnamed identities get stable `Speaker 1`, `Speaker 2`, and so on in first-appearance order. Text, including Urdu and Arabic, remains UTF-8 without a BOM. An empty transcript says `No speech was transcribed.`

The existing `/document` and `/download-url` routes remain JSON APIs with unchanged behavior. The text export exposes the same validated reader fields as `/document`, not provider metadata or raw storage objects. Incomplete transcripts return `409`. Download the attachment with a normal HTTP client to retain its streaming body and filename; this non-JSON route is not included in the generated JSON client or the TypeScript server SDK.

### Use generated clients carefully

The TypeScript client has generated HTTP and schema modules for server-side use. Keep Tenant credentials and webhook management on the server. For a live Space, use `SpaceClient` and its AccessGrant boundary instead of issuing Participant media or Sync requests directly.

Your backend can call `admitEpisodeParticipant` with `admission: "direct"` to admit a Participant and receive access without applying the Space’s `open`, `knock`, or `members_only` admission gate. Omit `admission` (or send `"policy"`) to retain policy-based admission; direct admission still requires `episodes:write` and all normal Tenant, Episode, role, and capacity checks.
