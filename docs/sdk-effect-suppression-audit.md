# SDK effect-suppression audit

Baseline: PR #595, `a7f46229ce8bedf8d53575c9949236de3f82289d` (28 October 2026).
The review covered all 143 existing suppressions, not just new calls. Effects are
appropriate for synchronization and lifetime ownership; the rule is a review
checkpoint, not a ban on React effects.

## Removed or replaced effects

All state adjustments below update only their own component, are guarded by an
input transition, and converge before children commit. They do not run host
callbacks, allocate resources, or write shared providers during render. No effect
was moved to `useLayoutEffect` or hidden inside a wrapper hook.

## Retained categories and critical exceptions

| Category                                         | Count | Why an effect remains                                                                                                                                         |
| ------------------------------------------------ | ----: | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Resource ownership / imperative integration      |    28 | Media wrappers, audio contexts, downloads, URLs, clients, board controllers, native services and read receipts need a committed lifetime or external command. |
| External subscription                            |    24 | Client events, browser/native listeners, device discovery and transport summaries must attach and detach with their owner.                                    |
| Timers                                           |    18 | Clocks, delayed notices, reaction lifetimes and event-created feedback require cancellation.                                                                  |
| DOM / native accessibility                       |    19 | Focus, measurement, text area sizing, portals and hydration-time capability detection need mounted platform objects.                                          |
| Animation                                        |    18 | Browser frames, Web Animations and native shared values need committed geometry or explicit exit lifetime.                                                    |
| Committed transition bookkeeping / notifications |    13 | Host/provider callbacks, dismissed warning semantics, notification deduplication and layout history must not be driven by speculative renders.                |
| Development controls                             |     4 | Scenario and measurement registries are external controls; reapplying them every render would undo user interactions.                                         |

- **AudioOutput is protected:** all six calls remain byte-for-byte unchanged.
  Its two reconciliation effects deliberately have no per-render teardown;
  unmount-only disposal is separate so continuing audio is not interrupted.
  The inventory gives each protected call a reason without editing that file.
- **Android service:** keep refresh-on-media-change separate from
  stop-on-call-end. Combining cleanup scopes could stop the service on a toggle.
- **Boards and media:** do not replace session/recovery ownership with render
  derivation. Shared tracks are detached, never stopped by playback views.
- **Host/provider writes:** stage pin reconciliation and native board/follow
  resets must remain after commit; writing another component's state during
  render would introduce a regression. Local render resets are not a template
  for those cases.
- **Not just derived errors:** whiteboard failure-to-command-error reconciliation
  has event precedence. A derived error could hide a later command failure or
  resurrect a dismissed notice; preserve its dependency-triggered behavior.
- **Hydration:** keep display-capture detection after mount. Unlike the migrated
  media-query store, it has no change subscription and does not need one.
- **Focus lifetime defect fixed:** ReactionPicker now cancels its delayed focus
  when closed/replaced. A quick reopen cannot let the previous opening steal
  focus before the new entry delay finishes. Search reset and Escape handling
  are unchanged.

## Verification and remaining risk

Verified on Instabox Linux at code revision `63dd29c50`:

- React SDK: 61 test files and 460 tests pass.
- Focused reconciliation/session/report tests: 11 pass. Replacing only the changed production source with baseline source makes six tests fail (avatar, participant arrival, query switching, hydration, picker focus and request replacement); the other five remain passing behavior-preservation checks.
- Both SDK lint commands pass, including their TypeScript checks, token checks, formatting and native worklet checks. Native implementation edits remain reason-only.
- Both actual ast-grep fixture tests pass, and structural scans of both SDK source trees pass.
- Changed-file formatting passes. Local doclint passes for all 101 maintained documents.
- All 124 inventory links match their current source locations; baseline count is 143. Protected AudioOutput is byte-for-byte unchanged.

Focused tests observe committed fallback/link/query/request/terminal output,
SSR hydration, StrictMode subscription cleanup, report reopening, host-owned
client replacement and rapid picker reopening. Existing React SDK suites cover
stage, board, drawer, notices and client lifecycle behavior. Run the actual
ast-grep executable against SDK fixtures as well as repository sources.

Native production edits are reasons only. No native service, animation,
resource cleanup or protocol implementation changed. Real device/simulator,
autoplay, camera, screen share, and full end-to-end journeys are not established
by DOM tests or a typecheck. Existing async request actions can still settle
after a request is replaced; this audit preserves that behavior rather than
silently introducing a new cancellation contract. The retained effects are
reviewed exceptions, not a claim that their entire subsystems are bug-free.
