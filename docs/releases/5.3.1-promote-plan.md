# 5.3.1 promote plan

Prepare and hold the staging release first. Production promotion requires an
explicit go in the release thread and the existing quiet-window check. Exclude
camera backgrounds and short-invite changes reserved for a later release.

The staging and production real-call proof stages run `pnpm prod:proof leave`
before smoke and transcript. A failed Leave comparison fails the existing
Promote proof stage and invokes its supported rollback. Do not bypass it.

The comparison uses the integrity-verified published 5.2.6 client (released from
2ec22c54) and the checked-out candidate, with the same harness, installed runtime
dependencies, browser, host, and backend in one session. Five iterations alternate
baseline ordinary Leave, candidate ordinary Leave, and candidate publications-403
Leave. All calls first prove bidirectional audio and video. Only one participant
departs during the measured interval.

An actual SDK background publications request is held before each departure.
Ordinary scenarios keep it held through departure; the fault scenario returns an
injected HTTP403 when the real Leave operation is sent. The protocol operation
and its durable acknowledgement are never delayed or mocked. The observer must
see HTTP403 while leaving, and the candidate PeerConnection must stay open until
the acknowledgement. A separate old-client fault diagnostic must reproduce the
premature peer close; its expected failure is reported separately, not treated as
a confirmed baseline latency.

Time from the public Leave invocation to the actual durable protocol ack or
self-participant-left event, using one browser monotonic clock. The five confirmed
ordinary baseline samples define the reference median. Include every candidate
sample, both ordinary and403, in the candidate median. Require:

- Candidate median at most twice the baseline median plus500ms.
- Every candidate sample at most5000ms.
- Every ack confirmed; no fallback to the40-second deadline.
- Five samples of each planned scenario, with all403 observations verified.

Preserve encrypted raw socket evidence and the comparison JSON. Report medians,
maxima, counts, injected fault conditions, and any missing proof. These are
synthetic measurements of the live backend, not customer telemetry.

Capture the current2ec22c54 rollback manifest, release ID, media hash and Pages
deployment again before go. Keep the additive participant-device-hints table;
never run its Down migration. Capture npm latest-tag undo to5.2.6 for all seven
synchronized packages; preserve immutable published versions.
