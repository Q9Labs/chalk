# Screen annotation v1

A viewer draws on the shared frame. The other viewers see the same mark in their call, and the sharer sees it on the screen they are using. The mark is never part of the published media. This plan covers the approved first release. It adds no running feature in phase 0.

## Layer and authority

Use a **new, negotiated Sync v1 extension**, not another whiteboard-v1 scene. Whiteboard-v1 is a durable Space document with Excalidraw elements, scene versions, file assets and reconnect replay. Annotation has a shorter lifetime, frame coordinates, a different writer guard, and a disposable high-rate stream. Binding a board scene to a publication would still require new presence, expiry, moderation and recording semantics and would introduce the risk of clearing the Space board when clearing ink.

Reuse the whiteboard draw policy and grants, the same effective-access query and the same authority lock order. On shared policy and grant commits, notify both the annotation controller and existing whiteboard clients. Reuse the whiteboard file and scene write path when importing an annotated frame. Do not send annotation deltas to whiteboard-v1 or share its reducer, cursors or scene ID.

Sync owns the layer, keyed internally by tenant, Space, Episode and layer ID, with the live screen video publication and sharer's active participant generation as its binding. The SDK reads the selected source from the local capture track after the media plane confirms publication. The SDK sends `bind` with the observed publication ID and its first intrinsic size. Sync creates a fresh layer ID only for the active screen lease holder and the matching observed publication, not on a UI start intent, a remote track subscription or a screen audio ID. Retrying bind on the same publication returns the current layer. A new capture selection must replace the video publication even if its dimensions and surface kind match. Lease loss, supersession, replacement, Leave and Episode end close the layer. Brief transport loss does not clear it. If the authority is unprovable, hide the overlay and refuse writes until it is confirmed. Never migrate ink to a replacement publication, even for the same participant. No separate join or provider access is needed for viewers.

### Transport and state transitions

[The wire schema](../../contract/schema/screen-annotation-v1.json) is the source for the TypeScript bindings and Elixir metadata. Request `screen_annotation=1` on the Sync upgrade. Only proceed after `screen_annotation: true` in welcome and completion of normal Sync recovery. Deploy readers before sending the extension. The active Sync socket strips valid Sync correlation fields before exact-field validation. A peer that doesn't negotiate receives no extension frames. This does not alter a control digest, command receipt or projection sequence.

- `annotation_state_request` returns a recipient-specific `annotation_state`. Sync also sends state when a layer opens. State either contains the layer, revision, fence, permissions, and non-expired marks, or is null. Revisions start at one. Apply `annotation_changed` at the exact next revision for that layer. On a gap, stop local input and request a replacement snapshot. Processing a snapshot never replays presence. Sync installs the new snapshot before sending later deltas on the same connection.
- `annotation_command` is a request with an operation ID. Only bind has null layer and fence. Otherwise the SDK freezes both at gesture or action start, not lift. `annotation_receipt` reports the committed or already-satisfied revision, or a bounded rejection. Receipt and visible state can arrive in either order. An unknown delivery may be retried on a live recovered socket with the **same** operation ID and payload. Do not enqueue commands offline or rebase stale gestures. Use UUIDv7 operation IDs and a five-minute acceptance window with 30 seconds of future skew. Retain accepted operation receipts until the retry window closes, keyed by layer, actor generation and operation ID; reject expired IDs even after receipt removal. Check identity before returning any receipt. Deduplicate bind by active publication.
- For accepted durable mutations, take the same Episode, participant and policy locks as whiteboard and lifecycle writers, then the annotation layer lock. Revalidate active generation, publication, access, pause and fence in the commit transaction. Relevant access and policy changes, pause, and any clear increment the layer's fence, cancel in-progress ink, clear cursors and push updated state. A narrower clear still invalidates in-flight gestures for everyone rather than risking restoration by a late final. Never wait on sockets or a renderer while holding locks. Delete bounded live state and receipts after close or expiry; persist only the recording evidence described below. Send `annotation_closed` on retirement and drop any later updates for the obsolete ID.
- Cursor, laser and in-progress ink are **presence**. Send at most 30 latest values per second per active actor. Use an unsequenced `annotation_presence` sideband on the existing Sync connection, separate from durable and sequenced presence queues. At most one pending sample per actor and layer per receiver. Coalesce or drop it first under pressure. Fan out only after checking active generation, layer, fence and applicable draw access. Use a live authorization projection fed by the same ordered commit notifications, not a database write or query per point. Flush or disable it on a witness gap. Install control transitions before forwarding samples for the new fence. Server supplies author and expiry. Null cursor and draft remove that actor's presence; disconnect, expiry (one second), fence change and close also remove it. Discard old-fence samples. No DB rows, durable queues, replay, recording or exports for presence. If a final mark arrives before the last preview, suppress that preview by mark ID.
- Use Postgres for live durable marks and moderation and bounded disposable presence for hot traffic. Enforce byte limits before decoding large allocations, array and text bounds after decoding, and an encoded snapshot ceiling before committing a mutation. The JSON Schema sets the structural bounds. The transport additionally enforces UTF-8 byte limits, UUID formats, and cross-field rules. Reserve queue headroom for recovery and the last 256 of 16,384 receipt slots for moderator commands. Rate-limit before reaching the reserve. Layer closure does not require a receipt slot. If a receiver cannot take durable work, resnapshot or disconnect it rather than building an unbounded backlog. Limit one active stroke and request per actor, bound erase history to 32 actions, bound accepted operations per retry window, and expire previews and requests independently of user input.

### Mark model and geometry

A mark comprises a client-generated ID, shape, lifetime and style. Sync supplies immutable author identity, name and assigned color, creation order and timestamps. Sync assigns a stable palette color for each Participant in the Episode and sends the recipient's default in access state. The participant color is the default stroke color and stays with their cursor and mark attribution when they choose a different ink color. No client can submit another author's identity. Use the Episode's participant name for cursors and name the author on mark selection or accessible inspection. Render server-supplied names and text as plain text.

| Kind                     | Payload                                                                                                                          |
| ------------------------ | -------------------------------------------------------------------------------------------------------------------------------- |
| Pen, highlighter         | Up to 384 quantized points. Use deterministic simplification and replace the whole preview rather than sending point deltas.     |
| Line, arrow, box, circle | Start and end. Box and circle use the ordered bounding rectangle; a circle tool draws an ellipse when the bounds are not square. |
| Text                     | Anchor, up to 512 UTF-8 bytes of literal text, and a note background flag.                                                       |
| Stamp                    | Anchor and one of five stable IDs: check, cross, star, question, heart. The renderer owns their artwork.                         |
| Laser                    | Cursor with a locally reconstructed 380 ms trail. Never a mark and no undo entry.                                                |

Encode frame position as two unsigned integers covering 0 through 65535, inclusive. For input, invert the actual decoded video content rectangle, not the tile bounds or device pixel ratio. Quantize each normalized coordinate once. Ignore a gesture starting in letterbox padding; clip a drag that exits the frame. For fit and fill, calculate the content rectangle from the presented track's intrinsic width and height, element bounds and fit mode, center it, then clip at the visible viewport. On render multiply each axis by its own content size. Width is a fraction of **frame width**, in the same units, not browser CSS pixels or the shorter side. Stroke, font and arrowhead sizing derive from that width. Recompute transforms on orientation, resize and fit changes. Adaptive encoding changes pixel resolution but not the normalized space; avoid accepting input during ambiguous crop, missing metadata or a track switch. For a real resize on the same capture surface, map the normalized frame onto the new extent; do not attempt to pin marks to page or document content. Scrolling does not alter the transform.

Drawing feels local: render the current draft immediately, coalesce its latest remote preview, then replace it with the accepted mark. On lift, Sync stamps its time and sets the fading mark's expiry to +2,000 ms. Hold opacity then fade over the last 600 ms. Use a monotonic estimate of Sync time from round trips and timestamped frames; re-anchor on recovery. Expired ink is hidden even if the expiry sweep is late. Kept ink has no expiry within the layer. The eraser removes a whole mark, not a raster region. Undo and redo apply to the actor's own kept commits and own erases, not pointers, expired marks or moderation. A new edit clears the redo stack. An erase or clear by a moderator prevents the affected marks from being restored. Redo restores original order and authorship, never the pre-clear scene. Preview updates, expiry and no-op retries do not advance the revision.

### Moderation

Compute `can_draw` with the existing Space policy and Episode grants: everyone respects the role default and explicit overrides, hosts uses `manageWhiteboard`, and picked allows managers and explicitly picked participants. Pause hides incoming marks and stops non-sharer input on all surfaces. The sharer can still draw if allowed by the policy. Resume restores the other participants' kept ink and any unexpired faded ink. Pause does not extend a lifetime. Fading marks and the request queue expire by timestamp; replicas do not depend on expiry deltas. The current sharer or a manager can pause, clear all, clear one person's marks or erase another person's mark. Anyone can clear their own marks, even after losing drawing permission. Managers can change the shared policy and grants while paused. The sharer does not gain `manageWhiteboard` by sharing. If they do not have it, they can pause or clear and see who can draw, but a manager makes the policy change. The same policy and grants drive both surfaces, not two settings that happen to start equal.

Request to draw is separate from the Episode's existing hand raise. In picked mode or with an explicit block in everyone mode, a blocked viewer can send one request, valid for 30 seconds. The requester sees their status and managers see the queue. Approve atomically by applying the existing allow grant, or decline without creating a grant. The grant applies to both surfaces for the existing grant lifetime. Hosts mode does not admit an exception: show that only hosts can draw until a manager changes the policy. Cancel outstanding requests when they become irrelevant, on actor generation change, policy change or layer close. Reject expired decisions, even when the UI still shows a request. Revoked access invalidates a pending gesture before it can commit.

## SDK and rendering

`screenAnnotationFor(spaceClient)` returns a stable `ScreenAnnotationClient`, independent of rendering. It exposes `getSnapshot()`, `subscribe(listener)`, `serverNowMs()`, `dispatch({layerId, fence}, command)`, and `setPresence({layerId, fence}, cursor, draft)`. The phase 0 stub returns unavailable and sends nothing. The implementation binds the local publication internally. Root SDK consumers can compile against the exported model now. Keep annotation subscriptions out of the full Space snapshot so cursors don't rerender the call. On recovery mark the controller connecting, clear presence and only restore a snapshot after negotiated live recovery. Dispose the controller with its SpaceClient.

| Surface      | Public component seam                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| ------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| React        | `ScreenShareView` and `ScreenShareViewSurface` accept optional `annotation: {client: ScreenAnnotationClient; publicationId: string; actions?: ScreenAnnotationActions}`. Mount the canvas over the playing media only when the publication matches. No prop means existing playback. The viewer's bottom pill owns tool state and stays outside the clipped canvas. Publish the overlay and tools as `ScreenAnnotationLayer` and `ScreenAnnotationToolbar` for custom stages. |
| React Native | `Stage` accepts the same optional annotation object, with the active screen publication ID supplied by the native stage. `ScreenAnnotationLayer` and `ScreenAnnotationToolbar` use the same snapshot and action types with a contained native video viewport and bottom tray. Sample native pointer events for finger and Pencil, without installing gesture handlers over call controls.                                                                                     |
| Both         | `ScreenAnnotationActions` has optional `saveToWhiteboard(frame: ScreenAnnotationFrame): Promise<void>` and `downloadPng(frame: ScreenAnnotationFrame): Promise<void>` callbacks. A frame contains the publication ID, intrinsic size, matched current video frame handle (DOM or native adapter, not network data), and the immutable accepted mark snapshot and estimated server time. Hide actions with no adapter or no permission.                                        |

`packages/screen-annotation` owns common geometry, hit testing, stroke simplification and a Canvas 2D renderer. Freeze an adapter seam: `contentRect(frame, viewport, fit)`, `framePoint(rect, point)` (inverse, nullable outside the rect), and `paintAnnotation(ctx, {rect, clip, sharerId, paused, marks, presence, nowMs})`. Use a structural subset of Canvas 2D rather than React or browser globals in the renderer. The web stage, Document PiP and Tauri overlay call it directly. React Native and the Android system overlay host the same renderer in a bundled WebView, as the native SDK already does for the whiteboard's web assets. Native UI and window managers own input and geometry; never give an annotation WebView a general native command bridge, external navigation or network fetches. The recorder uses its Skia canvas adapter. Pin a redistributable font, deterministic paths for stamps, blend rules, rounding and device-scale fixtures so platform emoji and font choice don't change placement. Use one ordered accepted scene and separate preview paint pass. Pixel parity means identical geometry, layout and style with a small anti-alias tolerance, not bit-identical WebKit and Skia rasterization.

Save and export take a single frozen-at-action snapshot of frame and visible **committed** marks. Save uploads the pristine frame through the existing whiteboard file API, then writes an image with editable Excalidraw elements at unit scale in one bounded scene operation. Convert freehand, geometric shapes, text and stamps to editable board elements, not a second flattened image. Insert at a new board location, use stable element IDs for retries and use existing orphan file cleanup if upload succeeds but the scene operation fails. Do not grant access to the board or its assets through screen share moderation. PNG composites that same frame and mark snapshot at native frame aspect; excludes call UI, contributor cursors and previews. No data is saved or downloaded on a participant's behalf without an explicit action.

## Desktop sharer

Use **Tauri v2** for one signed macOS and Windows app: Rust for local authority, pairing, hotkey, tray and native windows; a bundled, unprivileged TypeScript WebView for the shared renderer and control. Electron would provide the same renderer but not remove the need for native window, DPI and capture exclusion adapters, and would ship another browser engine. Use macOS AppKit windows and Win32 HWNDs beneath Tauri. One transparent always-on-top window per visible monitor segment is click-through and never takes focus. Separate hit-testable windows hold the draggable Pill or Island and settings. Save only the selected control style and normalized position along one of four edges per local sharer profile. The hotkey toggles canvas input only while drawing, with Escape, blur and disconnect restoring click-through.

### Identify first, then position

[`getDisplayMedia`](https://www.w3.org/TR/screen-capture/) reports a surface category and capture characteristics; it does not expose a portable OS window or monitor handle. Track labels, sizes and aspect ratios are hints, not identity. Use the following binding procedure, once per capture. Do not ask for Screen Recording permission just to position an overlay.

1. Chalk captures with in-picker surface switching discouraged, and keeps an unannotated local preview of the actual selected track. A native binding is supported only where switching the source can be prevented or reliably detected. Connect to the installed Helper from the picker or the first-draw prompt. Pass only a fresh capture nonce, source category and current frame dimensions with the authorized layer binding. The Helper lists local monitor IDs or window handles, never sends the list or titles to the service.
2. For a monitor, the sharer chooses the corresponding display in the Helper. Before enabling ink, confirm the mapping against the local preview with a short coded three-point calibration in a deliberately capturable, temporary calibration window; match positions and nonce **in the local track**. Do this in a pre-share step or pause outgoing video during calibration. Do not persist or send probe pixels. Verify overlay exclusion separately with a probe in the actual protected overlay. Reject ambiguous, occluded or aggregated selections. For a window, select the exact local handle with a click and confirm the preview against the visible captured content rectangle, including whether chrome and shadows are present. A separate calibration window may not appear in a window capture; validate corresponding landmarks in the preview and the clicked window instead, including origin and extent. Prove exclusion on the local clone using only frames captured after the browser receives acknowledgement that the native landmarks were painted. Without a reliable capture timestamp, keep using the annotated preview or PiP. Do not accept a blind match by title or dimensions. For an arbitrary browser tab, bind the containing browser window and calibrate its actual tab viewport, not its outer bounds. A cooperating captured Chalk tab can identify itself with [Capture Handle](https://developer.chrome.com/docs/web-platform/capture-handle) and report its viewport; no assumption that unrelated tabs cooperate. For a non-cooperating tab, require the user to select and confirm the matching tab viewport and hide ink when the selected tab's visibility or content bounds cannot be revalidated. Fall back to Document PiP if the sharer cannot prove the binding.
3. Store the binding only for the live publication: source nonce, retained native handle and process lifetime, local capture content rect, and current platform transform. On macOS read Quartz display and window geometry, convert global points to AppKit coordinates, then use screen backing scale for the overlay buffer. Opt into Accessibility only when the sharer enables window following. Use AX move, resize and focus events plus a bounded resample for lost events. On Windows use a per-monitor DPI-aware process, DWM extended frame bounds and client rect where the capture omits chrome, per-monitor DPI, and WinEvent location and visibility notifications. Handle negative display origins. Compute the transform in a single virtual desktop coordinate space, intersect with each display, and convert to that display's local points exactly once. Bindings hide immediately when a window minimizes, closes, loses verified visibility, or its source, DPI or capture bounds can't be explained. Same-handle motion translates marks without a Sync command. Geometry changes recompute the transform or require recalibration; do not jump to a like-sized display.

### Keep ink out of capture

Monitor overlays must pass a capture exclusion probe with the actual browser, OS and source. On supported Windows builds test [`WDA_EXCLUDEFROMCAPTURE`](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowdisplayaffinity) on all Helper windows. For window and tab capture test that the browser samples the target, not the composited desktop. On macOS legacy window sharing flags are not a cross-browser guarantee. Test display capture first on shipping macOS browsers. If any supported macOS monitor path captures the overlay, use a Helper-owned [ScreenCaptureKit filtered display capture](https://developer.apple.com/documentation/screencapturekit/capturing-screen-content-in-macos) that excludes the entire Helper app. The picker then uses the system consent flow for that capture, not on install. The native source must feed the **existing** SDK screen publication lifecycle, not join as another participant or publish a second share. Prototype WebRTC capture-track handoff to the tab before committing to that integration; keep desktop capture privileges out of the browser bridge. Until verified, direct an unproven binding to PiP. Do not ship an overlay that shows up in the remote stream or claim browser capture can always be made to exclude it. This is the first desktop feasibility check.

### Local connection, then device code

- Default to a per-device Helper listener on a fixed numeric loopback address only, never a LAN listener. Use a click-initiated browser fetch channel: `POST /v1/challenge`, `POST /v1/attach`, followed by authenticated `POST /v1/exchange` for control and streaming `GET /v1/events` via fetch. Require the exact configured Chalk HTTPS Origin and exact numeric loopback Host on every request and preflight, including streams. Reject missing and opaque origins, no wildcard or credentialed CORS, cookies, redirects, untrusted navigation, reflective origins, arbitrary localhost proxying or arbitrary URLs. The app explicitly shows a first-connection fingerprint for the sharer to match and approve. The pairing boundary prevents silent pairing by another local process and blocks untrusted web origins and DNS rebinding. It does not cover an impostor running as the same OS user that the sharer explicitly approves: the browser cannot verify a loopback responder's code signature, and code running as that user can already access the browser's Chalk session.
- The first loopback pairing requires the code displayed after native approval. The browser remembers the Helper's OS-stored public identity only after it verifies that approval and code, scoped to the signed-in account and web origin. On later shares the Helper must prove possession of the remembered key, the API must find an unrevoked registration, and native Allow still applies to the exact tab and share. A changed or cleared identity or a revoked registration requires the code; code pairing does not undo a revocation. Remembering a first-use identity does not extend the same-user impostor boundary. Device-code pairing stays preview-only; credential rotation is deferred.
- A challenge contains a fresh nonce, Helper public key and supported protocol versions. The tab requests a one-use, audience-bound attach ticket from the API using the active share's participant access grant. The API verifies the tenant, Episode, active generation and publication. The ticket binds the nonce, exact browser origin, Helper key, role (sharer only), layer and protocol version, and expires within 60 seconds. The Helper verifies signature and claims locally, consumes the nonce once and gives the approved tab a per-attachment random session secret carried in a header, never the URL. Issue and attach only for an admitted sharer, not anyone who knows an Episode ID. Tear down on end, source change, generation change, version mismatch, revoke or missed heartbeat. Stop paint and input if the attachment lease expires. No API, media or board tokens leave the trusted Chalk tab. The web bridge forwards only state, deltas and presence scoped to the current layer; it accepts only annotation commands with bind and policy management removed, and sends them through the existing authoritative SDK. Frame geometry, bounds and capture nonce are local; no screenshots or machine window handles pass through signaling.
- [Chrome's Local Network Access guidance](https://developer.chrome.com/docs/modern-web-guidance/guides/security/local-network-access) includes loopback and other private address spaces. Chrome 142 began prompting for local network access on requests such as fetch. Current Chrome guidance distinguishes the public-to-loopback permission from public-to-LAN. Expect first-use prompts and enterprise blocks. Try once on user action and detect actual connection failure or timeout, not a browser sniff or an assumed permission API. Use a loopback IP literal and an explicit loopback target address space when supported. Test allow, deny and unavailable Helper on real HTTPS origins. Offer device code immediately on denial without asking users to disable browser protections. For browser-only sharing, open [Document Picture-in-Picture](https://developer.chrome.com/docs/web-platform/document-picture-in-picture) from a button click: move or recreate the pristine share preview plus the same canvas in the PiP document. Do not substitute video-only PiP, which cannot show the canvas. Where Document PiP is unavailable, use the annotated preview in the call tab. Restore the original title and favicon on idle, stop, Leave or navigation; rate-limit the cue to active drawing rather than flashing per mark.
- Use the [OAuth device authorization flow](https://www.rfc-editor.org/rfc/rfc8628) pattern on the managed API for fallback. Helper requests a one-time device code and polls at server cadence. The browser approval screen names the device; approval requires a real signed-in session or a current verified guest sharer session, not a typed account name alone. Short code expiry, polling backoff, exchange binding to the Helper key, rate limits and generic errors protect the flow. Complete sign-in once and keep rotating credentials in Keychain or Windows Credential Manager, with explicit disconnect and revoke. A persistent device credential proves the device, not authorization to follow any meeting. On each share the tab approves a fresh attachment to its exact publication. API issues an expiring, proof-of-possession attachment capability for that audience; Sync authorizes annotation-only state, deltas, presence and scoped commands via a separate attachment endpoint. It never becomes a second participant, takes the seat, resets generation, sees chat, receives media, or reads stored artifacts. End the attachment on the same fences as the local path. No public relay of pixels. In remote mode calibration still stays on-device and requires matching the real browser preview and native selection before drawing.

### Helper interface and release

Version the Helper bridge independently at 1. Its handshake is `{version, helperPublicKey, challenge, expiresAtMs}` then `{version, challenge, pairTicket}`. Server-to-Helper payloads are negotiated annotation state/change/presence/closed frames plus `{type: "capture", captureNonce, surface, width, height}` and a lease deadline. The loopback bridge also carries scoped commands and a bounded readiness status: `unbound | calibrating | ready | unsupported_surface | update_required | disconnected`. Preserve original layer, fence and server time. Drop any message outside the live attachment; validate bounded strings and numbers at the bridge, deny arbitrary Tauri invoke and scope OS bridges to the bundled origin. The managed API reserves `POST /v1/screen-annotation/helper/pair-ticket`, `/device/start`, `/device/approve`, `/device/exchange`, `/device/revoke`, and `/attachment` under the same Helper prefix. The attachment token is limited to `screen_annotation_helper_v1`, is key-bound, and carries tenant, Episode, participant, generation, publication and layer claims. Use a 60-second attachment lease, refresh while the owning tab and publication are current, and close on refresh failure. The Sync endpoint is `/v1/screen-annotation/helper`. Present the attachment token with the server-nonce proof, never in a URL. Sync sends initial state after proof, then pushes updates. After proof, the endpoint accepts only `commit`, `erase`, `undo`, `redo`, `clear`, and `pause`. It does not accept state requests or presence uploads. The API owns device registration, ticket issuance and attachment refresh. Sync owns authorization and fanout; remote messages have the same restrictions and use the same mark command handler as local ones.

Package signed installers for macOS (Apple Silicon and Intel if supported by the stack) and Windows (x64 first), with macOS Developer ID, hardened runtime and notarization and Windows Authenticode before distribution. Use [Tauri's signed updater](https://v2.tauri.app/plugin/updater/) with a pinned verification key, HTTPS manifests, signed platform artifacts and release rollback instructions. Keep staging and production update channels and keys separate. When handshake versions do not overlap, report Update required and stop native ink delivery; offer PiP while updating. The just-in-time prompt and share picker link to the current signed installer, not a raw executable from an in-call message. Release credentials stay out of the repo. Phase 0 builds and deploys no Helper.

## Mobile sharer and viewers

The native SDK already calls `react-native-webrtc` display capture. The iOS app uses its broadcast extension in `apps/mobile/ios/ChalkScreenShare`. Keep that path unchanged. iPhone, iPad and Android viewers use the same model and local paint loop, with a bottom tray, two-finger pan and Pencil support on iPad. iOS sharer PiP comes later; don't add a private OS overlay.

Android already declares the MediaProjection foreground service permission. Add the overlay only after the sharer explicitly chooses it and grants [draw over other apps](https://developer.android.com/reference/android/provider/Settings#ACTION_MANAGE_OVERLAY_PERMISSION). A foreground share service owns a `TYPE_APPLICATION_OVERLAY` with a passive non-touchable ink surface and a separately touchable compact control. React Native retains the active SpaceClient and owns commands; the service gets only a scoped stream of renderer state and sends bounded input back while its own share is valid. Remove windows promptly on permission revoke, service shutdown, share stop, background termination or geometry ambiguity. Use the [MediaProjection](https://developer.android.com/media/grow/media-projection) captured-content size and visibility callbacks, display insets and physical rotation, not the launching Activity's bounds. App-window sharing doesn't expose a portable target window rectangle. Allow overlay only when captured content can be positively mapped and is visible; otherwise show the marked preview in Chalk.

Treat Android capture exclusion as a device proof, not a flag assertion. Test the actual outgoing projection with the overlay visible: no ink and no black region. Try protected windows and app-only projection on supported builds, and record which capture modes meet the invariant. Do not ship a full-display overlay path that burns in ink or blacks out the underlying content. If supported hardware cannot meet both requirements, escalate the specific platform limitation to the lead with evidence before treating any scope as dropped.

## Recordings

Compositing reads a versioned annotation sidecar, never the live socket or media pixels to infer ink. For each recording that includes the screen publication, initialize from the authoritative mark snapshot at the capture boundary, then persist accepted operations and close in authoritative order. Scope by tenant, Episode, recording, publication and layer, not display name or current sharer. Capture schema for the sidecar: `{version: 1, layer: Layer, initial: {atMs, revision, paused, marks}, changes: [{atMs, revision, change}], closedAtMs}`. Here `atMs` is capture timeline milliseconds. Use the wire `Change` variants with control reduced to pause state, not recipient-specific access. Convert committed and expiry timestamps to the same capture timeline before persistence. Order same-time changes by revision; deduplicate by layer and revision. Never record pointers, provisional brush strokes, draw requests or policy settings. Store only bounded chunks plus checkpoints; use recording retention, encryption and artifact authorization, not a file in the public call snapshot. Close may be at the recording cut even if the live layer continues. Use a transactional outbox or the existing recording snapshot barrier so exporting at stop cannot race a late committed change.

At render time locate the actual decoded active screen publication and its content rect in the recording layout. Apply sidecar changes through the frame timestamp, evaluate fades on that clock, clip to the decoded share and draw above it before call chrome. Keep `apps/recording-renderer/src/compose/whiteboard.ts` as the separate whiteboard path; reuse its headless Canvas approach, not its renderer or scene cursor. Backward compatibility: absent sidecar yields today's export, and older recordings stay renderable. A sidecar that exists but is invalid cannot silently masquerade as clean video. Surface an explicit recording render failure under the existing export recovery path. Release a renderer that reads both formats before enabling sidecar production, and keep it available for retries of frozen Recordings on rollback. The same sidecar can support a timeline or marks toggle later, without changing video.

## Observability and proof

Extend the existing trace and journey context in [observability.md](../observability.md). Sync writes `screen_annotation.opened` and `screen_annotation.closed` in the layer transaction, linked to the authoritative screen publication event if it has a journey. Otherwise link to the parent Episode and retain the share binding in the ledger payload. Include Episode-end closure, trace and span IDs and bounded outcome or cause. Retry and rejection paths must not leave success evidence. No ledger event per mark, cursor, policy toggle or reconnect. The capture sidecar is recording data, not telemetry. Follow the existing webhook catalog conventions if these ledger events are exposed; do not add external deliveries just for instrumentation. Add proof that opens and closes a real layer, joins the events to the parent journey, and checks duplicate and denied writes and trace redaction.

Use bounded metrics for command result, receive-to-paint, presence coalescing, resnapshot, bridge attach method and failure category, inactive overlay cause, and recording sidecar lag. Do not log coordinates, text, display names, device keys or codes, publication or participant IDs as metric labels, window titles, raw frames, or credentials. Treat trace context as correlation, not authentication. Test normal and rejected attach to show the outcome is observable and payloads and secrets are not.

### Acceptance measurements

- **Alignment:** share a generated asymmetric fiducial grid with edge and center targets. Inject a gesture at a known frame point and measure the centroid of the drawn mark against the target in the remote capture, sharer overlay screenshot and recorded export. Compute Euclidean pixel error divided by the displayed width of the mapped frame (not screen width). Compare p95 to **0.5%** per surface and scenario. ## Decisions to carry into implementation

- Validate desktop and Android exclusion before polishing the overlay. The recommended Mac fallback is Helper-owned display capture with a filtered stream and explicit OS consent only on that path. For an arbitrary tab or Android app window without a provable transform, retain the in-call or PiP preview rather than guessing. If there is no supported clean native projection path, report the affected OS and capture mode as a release decision.
- Keep shared draw policy management at its existing capability boundary. The sharer can always stop marks or clear them but does not gain persistent control of the Space by sharing. Keep hosts mode strict.
- Preserve publication-bound, frame-fixed kept ink. Model a future content anchor as a new negotiated coordinate mode, not a hidden offset in today's marks. The current sidecar already supports future recording controls. The SDK can add an iOS PiP adapter, an end-of-share sheet and Episode summary artifacts without changing mark identity or granting additional authority now.
