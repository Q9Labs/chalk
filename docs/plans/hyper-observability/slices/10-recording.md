# Slice 10: Recording and rendering

This slice proves that a Recording a Participant asked for was captured, rendered, stored readable and played, and when it wasn't, names the hop and the module that broke it. SWE-2 builds it. It owns the symptom prefixes `recording.`, `render.` and `playback.`. It writes against C1 (IDs, envelope, registry), C2 (ProofBundle, verdict fields, three-state values), C3 (`evidence_gap`, watermarks) and C4 (compact CLI grammar). Slice 11 consumes this slice's readback result, slice 12 owns webhook delivery of recording events, and recorder OTLP wiring is foundation-side parallel work. Code facts are at b3dc1d3afa.

The slice starts when Sync finalizes the `start_recording` reservation (`apps/sync/lib/chalk_sync/stateholder/postgres/external_operation_finalizer/recording_outcome.ex:18`) and stops at playback in the dashboard player. A Tenant's own player behind the public download URL is outside our view: the API mint is the last hop we see there.

Neighbours: transcripts are slice 11 (their precondition is this slice's `recording.artifact_readback` reading `ok`). The `recording.started`, `recording.completed` and `recording.failed` webhooks (`apps/api/internal/webhooks/event_names.go:23`) are slice 12. The fleet worker env that lacks OTLP (`apps/api/internal/recordernodebootstrap/identity.go:77`) is foundation work: this slice reads its absence as `recorder` not read, never as a healthy recorder. Other dashboard pages are slice 1; Worker edge logs are slice 14.

Words: the export job is the `recording_jobs` row with `kind='render'` (`apps/api/db/schema.sql:2675`), which the artifact-state query calls `export_job`. The capture session is the SFU session with `session_kind=capture` (`features/media/sfu/internal/media/events.go:57`). Every `recording_jobs` row is a `job` item (`job_` handle), declared by its row, with `job_kind` set to the row's `kind`: the capture job is `capture` and the export job is `render`. Each check here judges one job (`item: job`, `per: item`): `recording.never_captured`, `recording.missing_span`, `recording.capture_failed` and `recording.empty` judge the capture job, `render.failed`, `recording.artifact_unreadable`, `playback.*` and `recording.not_ready` judge the export job, and `recording.stuck` judges whichever job is stuck.

## 4. Rule conditions

Missing data never yields healthy. Each rule's `decide` returns `pass`, `unknown` with a reason, or one finding per job (`broken`, `degraded` or `expected`); `healthy` comes only from the kernel, when every planned check passed on complete coverage. Every check requires `db`, and the export job's checks require `r2` once the Recording is committed. A source the gap column below names is a `required` witness of that check: when it wasn't read, the kernel prints `gap: <code> all: <source> not read` and the header reads `coverage=partial(<areas>)`, while a finding the other witnesses prove still stands. Every other `recorder` and `sfu` witness is `required: false`: it corroborates and picks the module, and its absence is no gap. An empty query result counts as absence only when that source's read succeeded. A rule's `unknown` reason prints as `gap: <code> all: <reason>`. Expected reasons are declared in `observability/registry/areas/recording.json` `reasons` with the area's prefixes and print as `reason=<code>` on a finding with no module. A job's window runs from its row's `created_at` to its terminal state; a job that has not ended is open, so its header reads `partial(open)` until it does. A capture job with `attempt_count=0` belongs only to `recording.never_captured`.

## 7. Out of scope and traps

- Don't touch the transcription job or transcript files (slice 11), the webhook outbox or delivery (slice 12), `apps/api/internal/recordernodebootstrap/identity.go` or any recorder unit or env file in Git (foundation), `infrastructure/`, the `tools/formal/recording-pipeline/` model, production config, or other slices' prefixes. Don't change the URL lifetime or add URL refresh: that is a follow-up product change, and it would erase F9. Showing the note from `onError` is a user-visible change, so run the Orb per AGENTS.md.
- `status=completed`, `export_status=ready` or a 200 from `download-url` isn't proof that the video plays. Only readback `ok` proves the stored object, and only `playback.progressed` proves a viewer saw it. A mounted `<video>` or a resolved `play()` Promise isn't playback.
- Never log or print the signed URL, signed headers, any R2 object key, the R2 credentials or the presigned readback URL. Readback reads `CHALK_R2_READ_ENDPOINT`, `CHALK_R2_READ_BUCKET`, `CHALK_R2_READ_ACCESS_KEY_ID` and `CHALK_R2_READ_SECRET_ACCESS_KEY` (a read-only token on the recordings bucket, from 1Password), presigns a 300 s GET with `aws4fetch`, and runs `ffprobe` and `ffmpeg` on that URL with a 60 s timeout each. It never downloads the whole object.
- The HEAD checksum is metadata, so it proves the object wasn't replaced, not that its bytes decode. Only the ffprobe and decode steps prove the bytes.
- `recording.capture_attempt_failed`, the attempt-failure row, the db `error_code` and Sync's failed status all copy one decision. `capture_packet_count` is the recorder's number. The client's `url_expires_at` is the API's. Never count any of these as a second witness.
- No recorder rows isn't a healthy recorder. Make `recorder` a `required` witness only of the checks whose gap column names it, and have their `applies` and `decide` treat it as needed only for a Recording with at least one claim, so the kernel prints `recorder not read` exactly there. `r2` is already a `observability/registry/core.json` source; make it a `required` witness of the export job's checks once the Recording is committed. Coverage comes from the kernel alone, so don't add a gap or source list to the older report's `scripts/diagnose-call/gaps.mjs` or `scripts/diagnose-call/join.mjs`.
- No `sfu.publication.started` rows mean "nobody published" only when the node reported both session rows for every Participant; otherwise `decide` returns `unknown`. `sfu.media.egress` has no packet count (`features/media/sfu/internal/media/events.go:119`); use `sfu.media.transport`.
- Don't wrap repository helpers, SQL calls or timers in `op`. Section 5 is the whole list. Don't put `transition` into a Postgres trigger; emit it from the Go methods named above, after commit.
- The F4 hook is one call inserted at `apps/api/internal/recorderworker/capture_readers.go:98`, after the nil-packet check and before `receivedAt := time.Now()`: `if dropCaptureRTP() { continue }`. `apps/api/internal/recorderworker/capture_fault_release.go (new)` defines it as `return false`; `apps/api/internal/recorderworker/capture_fault_faultinject.go (new)` returns true when `CHALK_RECORDER_FAULT=drop_rtp`, read once. Check the release build with `cd apps/api && go list -f '{{.GoFiles}}' ./internal/recorderworker`, which must not list `apps/api/internal/recorderworker/capture_fault_faultinject.go (new)`.
