# Slice 04: Video

This slice proves that a Participant's camera reaches every viewer as a moving, sharp picture, and names the first hop where it stopped when it doesn't. SWE-2 builds it. It owns the `video.` prefix and covers camera video only, from capture to the rendered tile. It depends on C1 (registry, envelope, `transition`/`op`/`fact`/`surface`/`decision`), C2 (`ProofBundle`, three-state readings, the three verdict fields), C3 (`evidence_gap`, source watermarks) and C4 (the line grammar in [docs/diagnose.md](../../../diagnose.md), `--json`). It reads, and never redefines, slice 2's media connection state and `join.leave` fact, slice 7's reconnect and background transitions, slice 8's `end.episode` fact and slice 9's crash records. Code facts are at b3dc1d3afa.

Journeys, on web and mobile: a Participant with a seat turns the camera on and it starts; the camera keeps running until they turn it off; every viewer whose tile is on screen sees that camera moving; a viewer with a large tile on a clean link gets the high layer.

Boundaries. A camera failure in the prejoin preview is slice 1. Every symptom judges one Episode and runs once per seat of its declaration, so a finding's party is always the seat its check ran for. The three publisher symptoms run for each seat as the camera's owner. The three viewer symptoms run for each seat as a viewer and cover every camera it receives; each failing publisher is named in a `fact:` line (`fact: publisher pt_4c1e camera ingress flowing [ev_2e0f]`), so a freeze the publisher's uplink caused prints one finding per affected viewer, each at the publisher's hop. How many viewers a publisher-side failure reached prints in `diagnose evidence`, never as a key on the finding line. The registry already declares `video.frozen` (episode, per seat) with no witnesses and no fault scenario; the slice fills both and adds the other five.

## 4. Rule conditions

Missing data never yields healthy. Each rule's `decide` returns `pass`, a finding (`broken`, `degraded` or `expected`), or `unknown` with a reason that names the missing evidence; the verdict alone builds `healthy`, and only when every planned check passed on complete coverage. An unknown check prints `gap: <code> <party>: <reason>` and puts `video` in the Episode's coverage (`partial(video)`). An EXPECTED result is an `expected` finding whose `reason=` is the code in brackets, each declared in the area file's `reasons` with outcome `expected` (`cancelled` is the registry's own); every other finding leaves `reason` empty. Each source a rule reads is a `required` witness, and a check counts as checked only when every required reading is complete, whatever `decide` returned: a finding whose required source is incomplete still prints, next to a `gap:` line for its check. Thresholds are named constants in each rule file, with today's values from the files cited below, because the rules hash covers only the rule file and its registry entry, so a threshold read from another file could change a verdict without making it stale. Shared terms:

- _Seat_: a seat in the Episode declaration, which `applies` reads, so a seat that recorded nothing is still judged. _Connected_: slice 2's media connection state is connected for that Participant throughout the stretch.
- _Bound_: the `video.camera` transition's latest state is `live` with `bound=true`.
- _Flowing_: an SFU ingress or subscription row whose packet count grew by >= 50 since the previous row of the same track, with the rows <= 35 s apart (`scripts/diagnose-call/quality.mjs:7`). _Not flowing_: a row with growth < 50, or `packets=0` on the first row, followed by no flowing row for 20 s. No row after it reads `absent` only up to the `sfu` source watermark; past the watermark the reading is `unknown`.
- _Window_: one 10 s `call_stats` sample (`sdks/typescript/client/src/media/call-stats.ts:9`). A window carrying `gap` (`docs/observability.md:81`) measured nothing.
- _On screen_: the probe reports `on_screen=true`, `page_visible=true`, `covered=false` and `rect_h >= 36`.
- _Older SDK_: a Participant who sends `call_stats` but no `video.camera` transition or `video.render_probe` rows. Rules needing those rows return `unknown` (`client <version> has no camera transition`, `no render probe`); no transition never means no failure.
- Exclusions: no rule fires while either side is not connected, during a slice 9 crash record for the affected tab, while the publisher's camera subscription reads `pause_reason=source_unauthorized` or has `sfu.source.lease_lost source=camera` (`features/media/sfu/internal/media/authority.go:98`, `:235`) with no later `sfu.source.lease_opened` (slice 7), or for `source=screen`.
- One code per publisher, viewer and stretch, the first in this order: `camera_wont_start`, `camera_stopped`, `not_published`, `not_shown`, `frozen`, `low_quality`. A later rule passes a stretch an earlier code already explains.
- Unknown reasons: `sfu rows absent` (on a Chalk SFU Episode, or past the `sfu` watermark), `cf has no per-track packet witness` (Cloudflare, `scripts/diagnose-call/gaps.mjs:27`), `client rows absent` (the seat's client rows absent, or windows carrying `gap`), `client <version> has no <row>` (an older SDK), and `no render probe` (probe absent, a tile beyond the first 16, or `unavailable(native_render)`).

## 7. Out of scope and traps

Don't touch: other prefixes and their files (`join.`, `media.`, `audio.`, `share.`, `access.`, `reconnect.`, `background.`, `end.`, `page.`, `app.`, `perf.`, `recording.`); `apps/api/internal/adapters/cloudflare/sfu/*` (read only; the in-flight branch `origin/obs/cf-per-track-error-code` changes `apps/api/internal/adapters/cloudflare/sfu/failure_observability.go:43`, and this slice must not depend on it); `scripts/diagnose-call/verdict.mjs`; the foundation contracts; production config, alert thresholds and `infrastructure/observability/production-alerts/call-verdict.json` values.

Migration. `starved_viewer` and `congested_viewer` (both from `lowBitrate`, `scripts/diagnose-call/rules.mjs:177`) become `video.low_quality`. `viewer_hid_video` (`hiddenVideo`, `scripts/diagnose-call/rules.mjs:213`) becomes the `video.viewer_hidden` branch of `video.not_shown`. `starvedViewerCall`, `starvedWithoutNodeCall`, `hiddenByViewerCall` and `congestedViewerCall` (`scripts/diagnose-call/scenarios.mjs:112`, `:125`, `:181`, `:202`) become the rows of those codes' fixtures under `observability/fixtures/`. Once the new rules pass the coverage gate, the same change removes the three kinds from `KINDS` (`scripts/diagnose-call/rules.mjs:253`), their functions, the four scenarios and the tests that import them, so the older checker and the kernel never both judge camera video. `uplink_degraded`, `node_dropping` and `downlink_degraded` stay where they are, as hop evidence.

Traps a literal builder will hit:

- `useVideoTrack` status `playing`, `loadeddata` or a resolved `video.play()` (`sdks/typescript/react/src/components/participant-tile/useVideoTrack.ts:51`) is not a picture. Only the probe's presented frames, geometry, `covered` and luma prove one.
- `sfu.subscription.paused reason=viewer`, `recv_hidden_videos` and the IntersectionObserver report are one decision. Never count one as corroborating another.
- A 200 from `cloudflare_sfu.add_tracks`, a `subscribe` `media_result succeeded` (`sdks/typescript/client/src/media/client.ts:1883`) or `sfu.publication.started` means a request or negotiation succeeded, not that packets flowed.
- No ingress row after a no-growth row reads `absent` only up to the `sfu` watermark. Transport rows don't extend it. Past it the reading is `unknown`, never healthy.
- A `call_stats` window with `gap` is not zero packets. A late or hidden probe tick is not a black tile. A Participant with no camera transitions is an older SDK, not a camera that never failed.
- A reconnect that starts after the picture stopped, or with cause `receive_stalled`, is the stall's consequence and never makes a finding EXPECTED.
- `rect_h` is in device pixels, like the viewer layer policy; comparing CSS pixels to 480 misreads every high-DPI tile.
- Never print healthy because no rule fired, as the older checker's `scripts/diagnose-call/verdict.mjs:19` does. Video results go through the rules and the kernel only.
- Don't wrap every media function in `op`, proxy `RTCPeerConnection` globally in the SDK, or add timers beyond the probe. Use only the boundaries in section 5.
