# Slice 05: Screen share

This slice proves four things about a screen share: it goes live when a Participant picks a screen, every other Participant sees a moving picture of it, it stops when the sharer stops it, and every refusal had a real cause. SWE-2 builds it, and it owns the `share.` prefix. It depends on C1 (registry, kernel calls, handles), C2 (ProofBundle, three-state readings, verdict fields), C3 (`evidence_gap`, source watermarks) and C4 (the line grammar in [docs/diagnose.md](../../../diagnose.md)). It reuses slice 4's render measurement (`video.render_probe`, 04-video.md section 5) on the share element and adds no render fields of its own, and it relies on slice 2 for the media connection. Code facts are at b3dc1d3afa. An Episode has one share at a time: Sync's lease refuses a second sharer with `screen_share_in_use` (`apps/sync/lib/chalk_sync/stateholder/postgres/screen_share_lease.ex:53`), and the SFU separately refuses a second screen track with `screen_share_active` (`features/media/sfu/internal/media/node_create.go:165-166`).

## 2. Symptom catalogue

| Code                   | Meaning                                                                                                                | Item                | Party             | Severity |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------- | ------------------- | ----------------- | -------- |
| `share.start_failed`   | The sharer picked a screen, but the share never went live for the Episode.                                             | `episode`, per seat | the sharer's seat | medium   |
| `share.capture_failed` | The screen picker failed for a reason other than the Participant's own cancel or an OS refusal.                        | `episode`, per seat | the sharer's seat | medium   |
| `share.blocked`        | A Participant was refused with `screen_share_in_use` while nobody was really sharing.                                  | `episode`, per seat | the refused seat  | medium   |
| `share.not_seen`       | The share is live at the SFU, but a present viewer has no visible picture of it.                                       | `episode`, per seat | the viewer's seat | medium   |
| `share.frozen`         | The viewer's share is on screen and packets arrive, but no new frame is presented.                                     | `episode`, per seat | the viewer's seat | medium   |
| `share.wont_stop`      | The sharer asked to stop, and 5 s later Sync hasn't stopped it, the SFU still receives it, or a viewer still shows it. | `episode`, per seat | the sharer's seat | high     |

Every symptom judges one Episode and runs once per seat of its declaration, so a finding's party is always the seat its check ran for: the sharer for `start_failed`, `capture_failed` and `wont_stop` (`applies` keeps seats with `can_publish`), the refused Participant for `blocked`, and the viewer for `not_seen` and `frozen`. The other Participant a finding concerns, the sharer O or the lease owner, is named in a `fact:` line, and how many viewers a failure reached prints in `diagnose evidence`. The registry already declares `share.wont_stop` (episode, per seat) with no witnesses and no fault scenario; the slice fills both and adds the other five.

`share.wont_stop` is high by decision: the Participant can't stop others seeing their screen, which is a privacy exposure. A share that ends without the sharer asking gets no code: every browser end arrives as `ended`, and the SDK treats it as the Participant's own stop (`sdks/typescript/client/src/space-client/media-controller.ts:1618`), so the two can't be told apart. A problem report about it becomes `BLIND_SPOT`.

## 4. Rule conditions

Missing data never yields healthy. Each rule's `decide` returns `pass`, a finding (`broken`, `degraded` or `expected`), or `unknown` with a reason that names the missing evidence; the verdict alone builds `healthy`, and only when every planned check passed on complete coverage. An unknown check prints `gap: <code> <party>: <reason>` and puts `share` in the Episode's coverage (`partial(share)`). An EXPECTED result is an `expected` finding whose `reason=` is the code named for it, each declared in the area file's `reasons` with outcome `expected`; every other finding leaves `reason` empty. Each source a rule reads is a `required` witness, and a check counts as checked only when every required reading is complete, whatever `decide` returned: a finding whose required source is incomplete still prints, next to a `gap:` line for its check. Sync's and the SFU's own codes are recorded on their decisions as area-file reasons under `share.` (`share.screen_share_in_use`, `share.capability_denied`, `share.dependency_unavailable`, `share.screen_share_active`, `share.screen_ceiling`, `share.lease_not_owned`), and the rules below match those. Thresholds are named constants in the rule files that use them, because the rules hash covers only the rule file and its registry entry, so a threshold read from another file could change a verdict without making it stale: `share_ingress_ms=25000`, `share_view_ms=10000`, `share_stop_ms=5000`, `share_lease_stale_ms=35000` (20 s renewal, `apps/sync/lib/chalk_sync/stateholder/postgres/screen_share_lease.ex:7`, plus the 15 s look, `apps/sync/lib/chalk_sync/episodes/coordinator/server.ex:17`), `share_owner_live_ms=20000`, `share_picker_min_ms=300`, `share_role_race_ms=10000`, `share_frozen_ms=5000`, `share_frozen_packets=30`, and `starved_floor_kbps=100`, today's value in `infrastructure/observability/production-alerts/call-verdict.json:3`.

Shared terms. **grew(O, [a, b])**: an ingress line for O with `source=screen` timed in [a, b] has `packets` above O's previous line for that `mid`. **flat(O, [a, b])**: no such line and the sfu watermark is complete to b or later; without the watermark the reading is unknown (`sfu rows absent`). **Present viewer V**: W12 has V joined before a and not left before b, V is not O, and V's client watermark is complete to b; a present V with no client rows makes the check unknown (`client rows absent`). **O asked to stop at t**: a W15 `share.client` transition `on→stopping` for O with trigger `user_control` or `platform_ended` at t. A W2 `share_stop` alone is not asking, because a long drop also sends it (`sdks/typescript/client/src/space-client/media-controller.ts:1522`, `:1535-1538`). **visible(V)**: a W11 probe for O's screen publication with `on_screen=true`, `page_visible=true`, `covered=false`, `video_width>0` and `presented_frames` grown since V's previous probe.

## 7. Out of scope and traps

**Don't touch.** Other slices' prefixes, `sdks/typescript/react/src/components/participant-tile/useVideoTrack.ts`, `sdks/typescript/client/src/media/call-stats.ts`, `sdks/typescript/client/src/media/client.ts`, slice 4's probe files, the camera and microphone paths in `sdks/typescript/client/src/space-client/media-controller.ts`, `ScreenSharePresentation`, `StageContentTileSurface`, `sdks/typescript/react/src/components/space-view/RecordingSpaceView.tsx`, the C1 to C4 contracts and production config. Leave every line named in `tools/formal/screen-share-lease/anchors` byte-identical, including each `_ = release_screen_lease(state, lease)`; that is why the release result is reported inside `release_screen_lease/2`. Run `tools/formal/screen-share-lease/run.sh` after the Sync change.

**Traps.**

- `media_result share_start outcome=succeeded` means only that the Sync command's Promise resolved (`sdks/typescript/client/src/sync/v1-live-target-telemetry.ts:21-23`). Sync's `live_target.stage` timing always says `outcome: :success` (`apps/sync/lib/chalk_sync/telemetry.ex:27`). Only W6 ingress and the viewers' W11 prove a share is live.
- W2 with the passed-through `reason_code` is a copy of W3, W5 is a copy of W4, Sync's projection is a copy of W6, and `sfu.admission.refused screen_ceiling` is the same decision as `share.publish`. None is a second witness.
- `screen_share_in_use` becomes `command_rejected` on the client (`sdks/typescript/client/src/sync/v1-live-target-telemetry.ts:37-38`). Never build a rule on `command_rejected`.
- `useVideoTrack` reports `playing` after one `loadeddata` (`sdks/typescript/react/src/components/participant-tile/useVideoTrack.ts:31-38`): one decoded frame, not visibility. `framesDecoded` keeps rising behind a paused or hidden element. Visibility comes only from W11.
- `device_failed` records every `NotAllowedError`, a cancel included, as `permission_state=denied` (`sdks/typescript/client/src/media/capture-error.ts:40-43`). Use W1's duration and policy fields.
- An empty SFU query on Cloudflare, no lease row, no viewer rows, or an ingress silence without a complete watermark are gaps. None means "nobody shared" or "everyone saw it".
- Never log `MediaStreamTrack.label`, capture labels or window titles; only the `displaySurface` enum. No SDP, no frame content, no pixels.
- Adopt `op` only at `sdks/typescript/client/src/space-client/media-controller.ts:708`. Don't wrap the Effect pipelines or timers, and don't add an op in the native adapter. A rule never emits backstops and never returns `healthy`.
