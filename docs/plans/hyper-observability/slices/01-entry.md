# Slice 01: Entry: dashboard, invite, admission, prejoin, embed and boot

This slice proves that every way into a call either reaches an admitted Participant or leaves a named, attributed reason: a Space page that never boots, an app that boots but never shows its first screen or crashes before the call UI mounts, an embed whose host page blocks Chalk, an invite refused against its own rows, a knock nobody saw, an approval the Guest never collected, devices refused at prejoin, and a dashboard request that failed. SWE-2 builds it, and it owns the prefixes `boot.` `embed.` `invite.` `admission.` `prejoin.` `dashboard.`. It writes against C1 (IDs and envelope: `cs_` minted at boot before auth, `dev_` with `device_ephemeral`, `formatHandle`, trail headers), C2 (`ProofBundle`, the three verdict fields, three-state readings), C3 (delivery, `evidence_gap`, watermarks, the credential-free first-party ingest path) and C4 (the line grammar in [docs/diagnose.md](../../../diagnose.md)). It consumes slice 14's edge feed and hands off to slice 2 at the media connection. Code facts are at b3dc1d3afa.

## 2. Symptom catalogue

| code | meaning | item | who is affected | severity |
|---|---|---|---|---|
| `boot.never_ran` | Space pages were served to browsers, but no script ran in any of them | `platform` | every visitor of the route in the window | high |
| `boot.app_failed` | the beacon ran but the app never showed its first screen, a code chunk failed after the one allowed reload, or a page threw during render before the call UI mounted (the entrance or prejoin page, caught by the root route) | `attempt` | the visitor (`cs_`, also once admitted) | high |
| `embed.blocked` | the embed got access grants, but nothing sent under them reached Chalk | `tenant` | Participant in a tenant app or a Dashboard Account's own call (`pt_`) | high |
| `invite.refused` | the API refused an invite for a reason its own rows contradict | `attempt` | Guest (`cs_`, `spc_`) | high |
| `admission.unresolved` | a join attempt never got an admission decision, so the visitor waited on a screen that never resolved | `attempt` | the visitor (`cs_`) | high |
| `admission.unanswered` | a knock expired while a host was positioned but never saw it, or a host's answer never committed | `episode`, per seat | Guest (`pt_` from `sync_admission_requests.participant_id`) | high |
| `admission.not_collected` | the host approved, but the Guest's waiting page never collected the approval | `episode`, per seat | Guest (`pt_`) | high |
| `prejoin.devices_blocked` | the browser refused devices without the visitor refusing a prompt | `attempt` | Guest or Participant (`cs_`) | medium |
| `prejoin.preview_failed` | a device failed to open for a reason other than refusal or absence | `attempt` | Guest or Participant (`cs_`) | medium |
| `dashboard.request_failed` | a `/dashboard-api/*` request failed with 5xx, or valid sign-ins were rejected as unreadable | `platform` | Dashboard Account (`usr_`, or `cs_` when unreadable) | medium |

The item is what the symptom's registry entry declares. An `attempt` is keyed by its client session (`cs_`), the one id a visitor has before a seat, and covers the attempt whether or not it became an Episode seat. A `platform` item is one environment over one UTC day, which fits a route or a sign-in failure that no single Tenant owns, and `embed.blocked` judges one Tenant's day because its threshold counts grants across the Tenant. Only the two Guest seat symptoms run per seat, so every other finding's party is `all`, and the seat, grant or route it concerns prints in a `fact:` line or a related record such as `seat pt_4c1e grant=unused`. The registry already declares `admission.unresolved` with its fact `admission.decision`; the rest are this slice's to add.

## 4. Rule conditions

Missing data never yields healthy. Each rule's `decide` returns `pass`, a finding (`broken`, `degraded` or `expected`), or `unknown` with a reason that names the missing evidence; the verdict alone builds `healthy`, and only when every planned check passed on complete coverage. An unknown check prints `gap: <code> <party>: <reason>` and puts its prefix in the item's coverage (`partial(admission)`). A rule reads only the sources named for it here. An EXPECTED result is an `expected` finding whose `reason=` is the code in brackets, each declared in the area file's `reasons` with outcome `expected`; every other finding leaves `reason` empty. Each source a rule reads is a `required` witness, and a check counts as checked only when every required reading is complete, whatever `decide` returned: a finding whose required source is incomplete still prints, next to a `gap:` line for its check. Local and Orb stacks have no Cloudflare, so the edge source is not read there and every check that reads it prints `gap: <code> <party>: edge not read`.

- **`boot.never_ran`** (`platform`; reads edge, client). BROKEN: a 15-minute window holds at least 20 edge `200 text/html` documents for `/:a-:b-:c` or `/space/*` (the `_headers` patterns in `apps/web/public/_headers`) to user agents not matching `WhatsApp|facebookexternalhit|Slackbot|TelegramBot|Twitterbot|LinkedInBot|Discordbot|Googlebot|bingbot|Applebot|HeadlessChrome`, with 0 `boot.started` for those paths, at least one `boot.started` for those paths in the previous 24 h, and a `boot.started` of the same build from any path after the window end. EXPECTED: none. UNKNOWN: no edge feed (`edge unavailable`), or no `boot.started` of that build after the window (`client not live after the window`). A ratio above zero is never a finding.
- **`boot.app_failed`** (`attempt`; reads client). The clock starts at `boot.started` when `visibility=visible`, else at `boot.visible`; a page never visible passes cases (a) to (d). BROKEN, any of the following, where (b), (c) and (e) count only what happened before `boot.load_call_ui` ended `ok` on that `cs_` (later ones are slice 8's `render_cause=chunk_reload` reload and slice 9's codes): (a) no `boot.app` shown within 20 s, and a `boot.pagehide` with `app_shown=false` came 20 s or more after the clock start; (b) `boot.chunk_failed` with `reloaded=false`; (c) `boot.chunk_failed` with `reloaded=true` and no new `cs_` on the same persistent `dev_` within 10 s; (d) `boot.load_call_ui` with no terminal within 20 s, or ending `error` with a code other than `boot.chunk_load` (chunk failures are judged by b and c); (e) `hop=client_render`: a `boot.render_failed` or a shown `boot.error_page` on any route, also on a page never visible, with `module` from `route_id` (`web.entrance` under `/_space`, `web.dashboard` under `/dashboard`, else `web.boot`, which also covers a surface whose fact never arrived). When (e) holds, (a) adds no second finding for that page. EXPECTED (`boot.chunk_reloaded`): `reloaded=true` and a new `cs_` on the same `dev_` within 10 s; that new page is judged as its own attempt. EXPECTED is never (e). UNKNOWN: case (a) without any `boot.pagehide`, case (c) on a device with `device_ephemeral=true`, or a client `evidence_gap` in the window (`client incomplete`). Case (e) with a `boot.error_page` but no `boot.render_failed` within 5 s is still broken, with `module=web.boot`: a root catch is never dropped because its partner fact is missing.
- **`embed.blocked`** (`tenant`; reads api, sync). A grant is unused when its Participant has no `sync.websocket.authenticated` whose `participant_id_hash` equals the hash computed exactly as `apps/sync/lib/chalk_sync/transport/socket_context.ex:29-30` computes it from the canonical Participant ID (never from the `pt_` handle), and no api `http.request` on a route naming that Participant other than the grant itself, within 60 s of issue. EXPECTED (`embed.grant_withdrawn`): every unused grant's Participant was removed, or its Episode ended, by a tenant-credential request within 60 s of issue. UNKNOWN: missing 2xx api logs (`api 2xx not shipped`), or a sync watermark short of issue plus 60 s (`sync incomplete`). One unused grant alone is no finding.

BROKEN: `invite.disabled` while the row at the decision has `enabled=true`, or `disabled_at` null or later than the decision; `invite.generation_mismatch` always, because rotation replaces the handle (`apps/api/db/queries/public_invites.sql:77-83`), so a matching handle with another generation has no legitimate cause; `invite.invalid_row` and `invite.space_mismatch` always; `invite.space_archived` while `archived_at` is null and `spaces.updated_at` precedes the decision; `invite.members_only` while the decision carried a `usr_` with a `memberships` row for that Tenant created before the decision; `invite.arrival_mismatch` unless the arrival's `invite_generation` is lower than the invite's `generation` and `rotated_at` is after the arrival's `created_at`. ## 7. Out of scope and traps

- **Neighbour slices.** `join.no_media`, listen-only and the SFU `admission_refused` kind already in `scripts/diagnose-call/rules.mjs:256` are slice 2's; don't reuse that name. `rejoin.refused` is slice 8's; access renewal and reconnect are slice 7's. A tenant backend whose `getAccess` throws, and API-key errors, are slice 12's: `embed.blocked` needs a grant that was issued. Crashes after the call UI mounted are slice 9's `page.` codes. A render crash on the entrance or prejoin page before the call UI mounts is this slice's `boot.app_failed` case (e); a native crash before JS runs is slice 9's `app.crashed_at_launch`. A camera failing inside the call is slice 4's. The edge feed is slice 14's, and it ships 5-minute rollups only (`edge.http_rollup`), which `boot.never_ran` reads. The per-request edge rows that `admission.unanswered` (call-status reads) and `dashboard.request_failed` (Pages function logs) read have no owner yet, so those rules print `partial(edge)` in production too until the lead assigns them.
- **Foundation contracts and production.** Don't edit C1 to C4 code, the registry shape, or the Pages project `chalk` (`scripts/deploy/deploy-web-release.mjs:23`). The `_headers` change in fault 2 lives on a throwaway branch only.
- **The invite code is a credential.** Never log it or put it in a fact, and never send a refusal reason to the client. The CSP fact keeps origins and directives, never full URLs.
- **A status is not a reason.** `ErrInviteUnavailable` is one error for eight causes; a 404 or 410 in the client says nothing about which. Logging the API's status in the client and calling it a second witness is wrong; so is counting `http.request` and `public_invite.request` as two, or `public_invite.admission` and its db row.
- **A render or a Promise is not proof.** `CallLimbo` rendering doesn't prove the visitor saw it, so surfaces go through `<ObservedSurface>`. A resolved `getAccess` doesn't prove the embed connected, and `admission.decide` ending `ok` doesn't prove a decision: `decided_at` does.
- **Don't treat `participants.status='active'` as proof of a connection.** Sync activates a Participant in SQL (`apps/sync/lib/chalk_sync/stateholder/postgres/sql/lifecycle.ex:174-177`); a host also needs its sync authentication.
- **Empty is not healthy.** A query that returns no `boot.started`, no knock surface or no edge rows proves an absence only when that source's watermark covers the window; otherwise it's the gap or unknown case section 4 names. A rotated link refused as `invite.not_found` is a gap, not `expected`.
- **No blanket wrapping.** Add the kernel calls in section 5 and nowhere else: no `op` around every fetch, no global `getUserMedia` or `fetch` proxy, no timer wrapping. Keep existing hashes (`participant_id_hash`) and add no redaction; C1 owns privacy.
