# Slice 09: Crashes and performance, web and native

This slice proves when a Participant's call page or app crashed, died, hung or ran short of resources after the call UI mounted, on web and on React Native, or whose native app crashed at launch before its JS ran, and says so even when the dying client could not report itself. SWE-2 builds it. It owns the prefixes `page.`, `app.` and `perf.`. It depends on C1 (envelope, `cs_`/`dev_`/`pt_` handles, registry), C2 (`ProofBundle`, three-state values, verdict fields), C3 (P0 reservation, `evidence_gap`, telemetry credential) and C4 (CLI grammar). It consumes no other slice's symptoms. Slice 7 consumes `timer_throttled`, and slice 13 consumes the run marker, the P0 checkpoint and the long-task fields of `perf_heartbeat`. Code facts are at b3dc1d3afa: today the only crash witness is the client event `render_crashed` (`sdks/typescript/client/src/telemetry/app.ts:18`), nothing in `scripts/diagnose-call` reads it, and mobile reports no crash at all.

## 3. Witnesses per symptom

These cannot observe themselves: a crashed, killed or discarded tab, a killed or crashed native process, and a JS thread stuck in a loop. An iOS jetsam kill leaves no per-run exit reason at all. Their absence is proved by the run marker read on the next run, by Sync seeing the seat's socket close, and by a live seat in `db` (`participants.left_at`, `apps/api/db/schema.sql:550`) whose `cs_` stops with no `call_ended`.

**Run marker.** One 1000 ms timer drives everything: the web Dedicated Worker in `sdks/typescript/client/src/telemetry/heartbeat-worker.ts (new)`, or the JS interval in `sdks/typescript/react-native/src/app-health/probes.ts (new)`. Every 5th tick the main thread writes the marker synchronously, and it also rewrites it on every `visibilitychange` (web) and every `AppState` change including `inactive` (native). Web: `localStorage["chalk.run.<cs>"]` holds `cs`, `ten`, `phase`, `visibility`, `last_elapsed_ms` (the outbox clock, `sdks/typescript/client/src/telemetry/outbox.ts:123`), `heap_used_mib`, `heap_limit_mib`, `release_sha` and `clean_exit`. `outbox.onClosing` (`sdks/typescript/client/src/telemetry/outbox.ts:96`) sets `clean_exit=pagehide`, and `call_ended` sets `clean_exit=call_ended`. Native: `ChalkAppHealthModule` keeps the same fields in a file in app-private storage through synchronous native methods, plus `pid`, `launch_id`, `launched_at_ms` (device clock), `js_ready`, `app_state` and `will_terminate`. `markLaunch` writes `phase=launch` and `js_ready=false` with no `cs` or `ten`, because JS mints the `cs_` (`sdks/typescript/react-native/src/space-client/native-session.ts:18`); the install inside `installNativeSession`, which `apps/mobile/App.tsx:22` runs at module load, sets `js_ready=true` and `cs`. The P0 checkpoint (the outbox's unsent P0 events, at most 50 events or 32 KiB) goes to IndexedDB (web) or the same native file every 5 s, only for slice 13.

**Reading it.** On the next run, `sdks/typescript/client/src/telemetry/previous-run.ts (new)` skips markers younger than 15 s, posts a BroadcastChannel `chalk-run-alive` ping and waits 2000 ms, and drops any marker whose `cs` answers (a live sibling tab). It records one `previous_run` per dead marker with `previous_client_session_id`, `phase`, `visibility` or `app_state`, `clean_exit`, `last_elapsed_ms`, the heap numbers, `js_ready` and `was_discarded` (the new document's `document.wasDiscarded`). The API stamps Tenant, Episode and Participant from the new session's credential, never from the body (`docs/observability.md:64`), so the rule takes the dead run's Participant and Episode only from that `cs_`'s own earlier rows. A marker is sent only under a credential of the same Tenant as its `ten`; others wait. A launch marker has no `ten`, so it goes under the next telemetry credential of any Tenant, and its row carries no Tenant, Space or Episode data. Unsent markers are kept 7 days. Today the only exit signal is `call_ended end_reason=page_closed` (`sdks/typescript/client/src/connection/lifecycle.ts:177`).

## 4. Rule conditions

Missing data never yields healthy. A rule returns `broken`, `degraded`, `expected` or a gap; `healthy` comes only from the sealed `ProofBundle`. Every rule returns `partial(client)` with `gap: client cs_<x> evidence_gap after seq <n>` when C3 reports a seq gap or unknown tail for a live `cs_` it reads, and `partial(sync)` when Sync rows were not read for the window (except `app.crashed_at_launch`, which reads no Sync).

- **`page.crashed`.** Broken when a live web `cs_` has `render_crashed render_cause=render_error`. `cause` is `chunk_load` when `error_class=chunk_load`, else `render_error`. If no `call_crashed` `shown` follows within 2000 ms, add the fact `surface unconfirmed`; the finding stays broken. Expected: never.
- **`page.tab_died`.** Candidate: a `previous_run` from a web `cs_` with `phase` `live` or `reconnecting` and no `clean_exit`, whose `previous_client_session_id` has earlier rows in the same Tenant. The marker's server time is `min(received_at - elapsed_ms)` over that dead `cs_`'s rows (`apps/api/internal/sdktelemetry/request.go:69`, `:94`) plus `last_elapsed_ms`. Broken when Sync has a `sync.websocket.closed` with the dead run's `participant_id_hash` and Episode, `reason` other than `timeout` and `server_shutdown`, from marker time minus 5 s to plus 20 s. `cause`: `discarded` if `was_discarded=true`, `oom_suspected` if `heap_used_mib >= 0.9 * heap_limit_mib`, else `unknown`. No finding when the dead `cs_` has any row with `elapsed_ms > last_elapsed_ms + 10000` (it kept running). No finding when the close is `reason=timeout` more than 60 s after marker time: the device slept or lost power, slice 7 claims it, and the checker's `UNEXPLAINED` backstop fires if it doesn't. Expected: never. Gap: a live seat whose `cs_` ends with no `call_ended` and no `previous_run` gives `partial(client)` with `cs_<x> tail unknown after seq <n>`; it is never broken on that absence alone.
- **`page.uncaught_error`.** Degraded when a live web `cs_` has `render_crashed` with `render_cause` `unhandled_error` or `unhandled_rejection` and `error_name` other than `none`. One finding per `error_fingerprint` per `cs_`, with its count. A row with no `error_name` (an SDK older than this slice) gives no finding and one gap line `cs_<x> error_name unavailable(old_sdk)`. Expected: never.
- **`app.crashed`.** Broken on any of: an `app_js_fatal` from a live native `cs_`; a native `render_crashed render_cause=render_error`; a native `previous_run` with `phase` `live` or `reconnecting`, `app_state=active`, `js_ready=true` and no `clean_exit`. `cause` from `app_exit_info` with the marker's `pid`: `REASON_CRASH` gives `java_crash`, `REASON_CRASH_NATIVE` gives `native_crash`, `REASON_ANR` gives `anr`, `REASON_LOW_MEMORY` gives `low_memory`; then an `MXCrashDiagnostic` dated within 60 s after marker time gives `native_crash`; then `js_fatal` or `render_error` from the rows; else `unknown`. Put the pair in `disagreement` when the marker has `clean_exit` set but `app_exit_info` for that `pid` says `REASON_CRASH`, `REASON_CRASH_NATIVE` or `REASON_ANR`. Expected: never. Gap: `partial(client)` when `op previous_run.read` ended `error(storage_unreadable)`.
- **`app.crashed_at_launch`.** Scope is `attempt` for the `cs_` that sent the row, and the party is its `dev_` (same install, same app-private file), because the dead launch never had a `cs_`. Candidate: a native `previous_run` with `phase=launch`, `js_ready=false` and no `clean_exit`. Broken when `app_exit_info` for the marker's `pid` has `REASON_CRASH` (`cause=java_crash`), `REASON_CRASH_NATIVE` (`native_crash`), `REASON_ANR` (`anr`) or `REASON_INITIALIZATION_FAILURE` (`init_failure`), or when an `MXCrashDiagnostic` is dated within 60 s after `launched_at_ms` (`native_crash`). The finding's time is `launched_at_ms` and `reported=` is the row's `received_at`, so a reader sees the delay. Expected `user_closed_app` for `REASON_USER_REQUESTED` or `REASON_USER_STOPPED`, and `os_ended_launch` for any other Android reason (a process started in the background that never ran JS). Gap: no exit reason (iOS with no `MXCrashDiagnostic`, Android below API 30, or an empty exit list for that `pid`) gives `partial(client.exit_reason)` with `gap: client.exit_reason unavailable(no_exit_reason)`, never broken on the marker alone and never healthy. A checker run before the row arrives sees nothing for that device: that is the unobservable gap in section 3, not health.
- **`app.killed_in_background`.** Broken when a native `previous_run` has `phase=live`, `app_state` `background` or `inactive`, and no `clean_exit`. Expected (`user_closed_app`) only when `app_exit_info` for the marker's `pid` has `reason` `REASON_USER_REQUESTED` or `REASON_USER_STOPPED`. iOS is never expected: `willTerminateNotification` also fires when the system ends a running background app, so `will_terminate=true` only sets `cause=will_terminate`. Other `cause` values: `low_memory` (`REASON_LOW_MEMORY`), `signaled` (`REASON_SIGNALED`), `excessive_resource` (`REASON_EXCESSIVE_RESOURCE_USAGE`), `freezer` (`REASON_FREEZER`), `other` (`REASON_OTHER`, which a swipe from recents may give), else `unknown`. iOS and Android below API 30 record `app_exit_info` as `unavailable(no_exit_reason)` and the finding keeps `cause=unknown`; an empty exit list for that `pid` is `unavailable(no_record)`.
- **`perf.ui_unresponsive`.** Per live `perf_heartbeat` window with `visibility=visible` for the whole window (web) or `app_state=active` (RN). `stall_ms` is the largest of `long_task_max_ms_30s`, `main_ping_max_ms_30s` and `js_lag_max_ms_30s`. Degraded when `stall_ms >= 1000` or `long_task_total_ms_30s >= 6000`; broken when `stall_ms >= 5000`. Adjacent firing windows merge into one finding. Hidden or background windows are `not_applicable`. Expected (`process_suspended`, web only) only when `long_task_max_ms_30s` is observed and below 1000 and `worker_late_max_ms_30s >= main_ping_max_ms_30s - 1000`: the worker was frozen as long as the main thread, so the whole process was paused, which a main-thread bug can't cause. Gap `partial(client)`: a live visible span of more than 60 s with no `perf_heartbeat` while the `cs_` seq advances, or a window where `long_task_max_ms_30s` and `main_ping_max_ms_30s` are both `unavailable`.
- **`perf.memory_pressure`.** Web: the baseline is the lowest `heap_used_mib` among heartbeats from 2:00 to 5:00 after join. A live span shorter than 5:00 makes the growth test `not_applicable`; a longer span with fewer than 4 heartbeats in that range gives `partial(client)`. Degraded when `heap_used_mib >= baseline + 300` in 4 consecutive heartbeats, or `heap_used_mib >= 0.9 * heap_limit_mib` in any heartbeat. `heap_used_mib=unavailable(unsupported)` (Safari, Firefox) gives the gap `pt_<x> heap unavailable(unsupported)`, never `not_applicable`, `0` or healthy. Native: degraded on 1 or more `memory_warning` while live and `app_state=active`. Expected: never.
- **`perf.device_overloaded`.** Degraded when, while live, `thermal_state` is `serious` or `critical` (iOS), `severe` or worse (Android), or `cpu_pressure` is `serious` or `critical` (web), for 60 s or more without a break. No join-time `thermal_changed` row gives `partial(client)`; `unavailable(unsupported)` gives the gap `pt_<x> thermal unavailable(unsupported)`. Expected: never.

`timer_throttled` (for slice 7): the worker emits it when the gap between two of its 30 s heartbeat closes exceeds 45 000 ms, with `expected_ms`, `actual_ms`, `hidden_ms` and `visibility`. No slice 9 rule reads it.

## 7. Out of scope and traps

**Do not touch:** other slices' prefixes; the reload-rejoin handler (`apps/web/src/components/space/SpaceCall.tsx:96` to `:114`, slice 8); `apps/web/src/components/space/SpacePage.tsx:262` and the root route error page in `apps/web/src/routes/__root.tsx` (slice 1); outbox delivery, batching and backoff (C3); the envelope and IDs (C1); `participant_id_hash` and other existing hashes; `perf/budgets.json`; production config; the React and React Native SDK `<Chalk>` components (no boundary there in this slice).

**Traps a literal builder will fall into:**
- Today every non-chunk uncaught error becomes `render_crashed` (`apps/web/src/lib/chunkReload.ts:56`, `:60`). Only `render_cause=render_error` is a crash; `chunk_reload` belongs to slice 8.
- A rendered fallback is not proof the Participant saw it. Emit `shown` from `<ObservedSurface>` after commit and only while visible.
- `void outbox.flush()` resolving proves nothing. The proof is the stored API row. The crash event may never land, which is why the run marker exists.
- `render_crashed`, `call_crashed`, `perf_heartbeat` and `platform_changed` all come from one client: never count two of them as two witnesses. The Sync close after `page.crashed` is the client's own `release()`. `participant_media_sessions` and `sfu.session.closed` are one witness.
- Never put `pt`, `ep` or `ten` in the `previous_run` body, and never resend the dead run's checkpointed events under the new credential: the API would stamp them with the new session's Participant and Episode.
- Never read a live sibling tab's marker as dead: skip markers younger than 15 s and any `cs` that answers the ping.
- Don't use `sendBeacon`: it can't carry the `Authorization` header, and a token in a URL or body is a credential leak. Today's `fetch` with `keepalive` (`sdks/typescript/client/src/telemetry/outbox.ts:236`) stays. Never store a credential in the marker, IndexedDB or the native file.
- No `perf_heartbeat` rows means a gap, not "no stalls". `performance.memory` missing means `unavailable(unsupported)`, never `0`.
- Don't wrap `setTimeout`, `fetch` or React components globally, and don't add `op` around the marker write. Add only the boundaries in section 5.
- Never raise `perf.ui_unresponsive` from a hidden or background window; that lateness is slice 7's.
- Never export an error message, stack text, URL or component props. Export only `error_name`, `error_class` and `error_fingerprint`.
- New event fields must reach the API allow-list before an SDK sends them, because an unknown field rejects the event (`docs/observability.md:64`).
