# Telemetry delivery model

A TLA+ model of how a client telemetry record reaches the API exactly once: the SDK outbox with one source per join, its queue, P0 reserve, drop lists and journal across a reload, the network that loses and duplicates, another Participant that forges a batch or end for a source it learned, and the ingest route that checks the source's owner, commits the source ledger, then writes the sink and answers with the seqs it settled. TLC checks that only a source's own Participant writes it, that an answer never names a seq the ledger has not committed as stored or rejected, that the sink holds only committed rows, that the ledger claims only what the sink holds or a crash visibly lost, that every durably enqueued record is with the client, stored, named by a stored drop record, or inside a gap the server names, that a gap never invents an exact range, that a close never hides committed history, and that routine records never push out a P0 record. Under the fairness assumptions in the model, every durable record ends up stored, named by a drop record, or lost in a way the server names, and every source before the live one has its end on the server. The model assumes a lossless sink once a row is written and a valid credential for every source; the header says what else it leaves out. The contract it checks is [docs/telemetry-delivery.md](../../../docs/telemetry-delivery.md).

Run `./run.sh` (about four minutes, Java 11 or later). It checks the code anchors, the real model for safety and for liveness, each without and with a join as another Participant, and every broken variant in `breaks` under the bounds its row names. The bounds are small on purpose: `TelemetryDelivery.cfg` has two client sessions, one record each besides drop records, a queue of one and one fault of any kind; `TelemetryDeliveryJoin.cfg` adds one join and drops the fault, and is most of the run time at about 33 million states; `TelemetryDeliveryLive.cfg` and `TelemetryDeliveryLiveJoin.cfg` are the liveness runs. A join together with a fault across a reload passed 25 million distinct states in three minutes with its queue still growing, so it and two records per join are by-hand runs.

Trace validation replays what the real outbox did. Run the delivery tests (`sdks/typescript/client/src/telemetry/outbox.delivery.test.ts` and `sdks/typescript/client/src/telemetry/outbox.delivery.rejoin.test.ts`) with a trace directory, then replay it:

```sh
TELEMETRY_TRACE_DIR=/tmp/telemetry-traces pnpm --dir sdks/typescript/client exec vitest run src/telemetry/outbox.delivery
tools/formal/telemetry-delivery/run.sh --trace /tmp/telemetry-traces
```

`trace.mjs` turns each NDJSON trace into `TraceData.tla`, and `TelemetryDeliveryTrace.tla` asks TLC whether some run of the model takes every line. When none does, `run.sh` names the first line the model can't take. A trace the model rejects proves the code and the model disagree; traces that pass don't prove the code refines the model, because they cover only the runs the tests made.

`anchors` lists the code fragments each action mirrors; `run.sh` fails when one is gone. `breaks` lists the broken variants and the rule each must break.
