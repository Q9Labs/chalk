# app.crashed_at_launch fixtures

The positive and healthy fixtures are not written by hand. They are the rows the real emitters produce for the symptom's fault scenario and its healthy control, carried from hop to hop through the hand-off files in `chain/`. Each hop is a test that drives real code, and each one compares what it produced with the committed file, so a hop that renames a field, drops one or changes a value fails its own test.

1. Hop (a), `sdks/typescript/react-native/src/app-health/app-crashed-at-launch.fault.test.ts`, is the fault scenario: a launch marker that never reached js_ready plus the OS's REASON_CRASH exit info for that pid. It drives the real kernel and outbox and writes the ledger frames the outbox posts to `chain/client-frames.<run>.json`.
2. Hop (b), `TestTelemetryChainCrash` in `apps/api/internal/httpapi/crash_chain_test.go`, posts those frames to the real telemetry route and the real Postgres ledger, seeds the server-side close rows Sync and the SFU write for a dead run's witnesses, runs the real relay to an Axiom HTTP fake, and saves the API rows, the server rows and the ledger report under `chain/`. For `page.tab_died` it also seeds `participant_media_sessions` and runs `scripts/crash-check/evidence.mjs`, the reader that turns the durable Postgres row into the `db.participant_media_sessions` fact row.
3. Hop (d), `scripts/crash-check/chain.test.mjs`, makes the proof fixtures from the saved rows and judges them through the real diagnose kernel: the positive run must give this symptom's finding, the healthy run must check its seat and give none.

`chain/hops.json` declares each hop's test, its command and the files it writes. Each fixture lists its hand-off files under `chain`, and `node scripts/gates/obs-coverage.mjs` fails when a fixture's rows are not exactly those files' rows, when the first hop is not the fault scenario, or when a file in `chain/` or a fixture is written by no hop.

The ids, clocks and receipt times are pinned, so the hops write the same files on every run; only the registry hash (`schema_ver`) is left out of hop (a)'s comparison, because any registry edit changes it. `node scripts/gates/obs-chain-replay.mjs app.crashed_at_launch` runs the hops in order in write mode and fails when any of them writes a file that differs from the committed one, skips, or fails. To rewrite the files after a deliberate change, run each hop's command from `chain/hops.json` with `CHALK_CHAIN_WRITE=1` in order.
